#H2489, #R9DSP: The removal of `SleepFunction<Long, Void> threadSleep` and replacing it with `Runnable onNextThread` seems to change the intended functionality. The original `threadSleep` was used to introduce a delay between capturing thread states before and after, which is crucial for measuring time differences. Replacing this with a generic `Runnable` that doesn't necessarily perform any sleep operation could lead to incorrect measurements if not handled properly by the caller.

#H2489: The addition of `onNextThread.run();` inside the loop over threads can have unintended side effects, especially if `onNextThread` performs operations that are not idempotent or thread-safe. This could lead to race conditions or inconsistent states if multiple threads are being processed concurrently.

#S04SB: The new method `detect(Writer writer, Runnable onNextThread)` introduces a change in the public API of `HotThreads`. While this addition seems useful for more flexible logging, it should be ensured that existing users of the `detect(Writer writer)` method do not rely on the absence of additional callbacks. Consider documenting this change clearly and providing migration guidance if necessary.

#V04WQ: The new static method `logLocalCurrentThreads` is introduced to capture and log current threads without sampling. This method should be tested thoroughly to ensure it handles large numbers of threads efficiently and logs them correctly in chunks. Additionally, the use of a `StringWriter` for potentially large outputs might lead to memory issues; consider using a more efficient logging mechanism if performance becomes an issue.
