#DT641, #Y2B46, #T2V7F, #4H8Q2, #6A0AW: The setting `ENABLE_STACK_OVERFLOW_AVOIDANCE` is marked as deprecated and may be removed at any time. However, the code still relies on it for functionality, which could lead to issues if the setting is removed without updating the code accordingly. Additionally, the tests should explicitly check for deprecation warnings when this setting is used.

#F6MNQ, #5HMC7: The introduction of `enableStackOverflowAvoidance` in `TransportService` and its usage in `onConnectionClosed` method seems inconsistent with the removal of the direct executor check. The logic now checks if the handler's executor is `DIRECT_EXECUTOR_SERVICE` and switches to a generic executor, which might not align with the intent of avoiding stack overflows as described by the deprecated setting.

#5DRR0: The `getDevNullConnection` method in `TransportServiceLifecycleTests.TestNode` creates a connection that does nothing. This is fine for testing purposes, but it should be clearly documented what this method is intended to simulate and why it's necessary.

#Z8GKP, #6VW67: The constructor of `TestNode` has been refactored to accept settings, which is good for flexibility. However, the default constructor still calls the new one with empty settings, which might not be ideal if there are specific settings needed for certain tests.

#T2V7F, #4H8Q2, #6A0AW: The test methods `onConnectionClosedUsesHandlerExecutor`, `testOnConnectionClosedUsesHandlerExecutor`, and `testOnConnetionCloseStackOverflowAvoidance` seem to cover different scenarios related to the executor used when a connection is closed. However, the naming of `testOnConnetionCloseStackOverflowAvoidance` has a typo ("Connetion" instead of "Connection").
