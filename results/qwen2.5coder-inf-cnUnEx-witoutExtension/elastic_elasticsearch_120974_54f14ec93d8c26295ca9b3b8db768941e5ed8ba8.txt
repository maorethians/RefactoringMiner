#BCR52, #EAW4C: The logic for marking fields as containing copied data has been moved from `IgnoredSourceFieldMapper#postParse` to `DocumentParserContext#createCopyToContext`. This change is intended to ensure that ignored source values are added to the list of ignored field values before parsing begins. However, there are a few considerations and potential issues:
1. **Redundancy in Checks**: The check for `mappingLookup.isSourceSynthetic()` and `indexSettings().getSkipIgnoredSourceWrite() == false` is repeated in both methods. This redundancy can be avoided by ensuring that the logic is centralized in one place, reducing the risk of inconsistencies.
2. **Order of Operations**: Moving this logic to `createCopyToContext` assumes that all necessary mappings and settings are available at this point. If there are scenarios where these might not be fully initialized, it could lead to incorrect behavior.
3. **Thread Safety**: The code does not explicitly handle thread safety. If `ignoredFieldValues` is accessed or modified by multiple threads, appropriate synchronization mechanisms should be in place to prevent race conditions.
4. **Code Duplication**: Although the logic has been moved, there is still some duplication in the comments and the handling of parent mappers. This could be refactored into a helper method to improve maintainability.
