#82926, #D8GXG: The logic for filtering settings now includes checking against prefixes and explicitly denied settings. However, there is a potential issue with the `EXPLICITLY_DENIED_SETTINGS` check. In both `#82926` and `#D8GXG`, the condition to filter out explicitly denied settings is incorrect. The current implementation will only deny settings that exactly match those in `EXPLICITLY_DENIED_SETTINGS`. It should instead ensure that no setting starts with any of the prefixes listed in `EXPLICITLY_DENIED_SETTINGS`.
For example, if `EXPLICITLY_DENIED_SETTINGS` contains `"index.routing.allocation.include._tier_preference"`, it will not deny `"index.routing.allocation.include._tier_preference.some_suffix"`.
Suggested fix:
In both `#82926` and `#D8GXG`, change the condition to check if any setting starts with a denied prefix:
```java
|| EXPLICITLY_DENIED_SETTINGS.stream().anyMatch(setting::startsWith)
```
