#0RV2H, #ZQDER, #E4FDY, #3ETWE, #V41E4, #D6DGV, #DVHD3, #Z62M9, #WMQGV, #GFPMS, #FW7DY: The refactoring introduces a new class hierarchy with `SystemResourceMigrationInfo` and its subclasses. However, the method `fromTaskState` in `SystemIndexMigrationInfo` is removed without any replacement or alternative way to create an instance of `SystemIndexMigrationInfo` from a task state. This could lead to issues if there are parts of the code that rely on this method for creating migration info objects.

#0RV2H, #ZQDER, #E4FDY, #3ETWE: The refactoring introduces a new method `migrateResource` which handles both index and data stream migrations. However, the logic inside `migrateSingleIndex` is duplicated in `migrateResource`. It would be better to refactor this common logic into a separate method to avoid duplication.

#0RV2H, #ZQDER, #E4FDY, #3ETWE: The refactoring introduces a new method `checkDataStreamMigrationStatus` which checks the status of a data stream migration. However, there is no handling for cases where the migration task fails and needs to be retried or cancelled. The current implementation only retries if the task was already in progress when the node started the migration.

#0RV2H, #ZQDER, #E4FDY, #3ETWE: The refactoring introduces a new method `cancelExistingDataStreamMigrationAndRetry` which is not defined anywhere in the provided code. This could lead to compilation errors if this method is called.

#9T9E6, #11SHG, #545MT: The test cases introduced for handling migration failures are good, but they only cover scenarios where a single index or data stream fails. It would be beneficial to add test cases that cover scenarios where multiple indices or data streams fail during the migration process.

#NDE8X, #103YV, #XA6GY, #YM4RE, #CT3DK, #K0FXW, #A5RJ2, #JHE77, #VXAA9: The changes to `DeprecatedIndexPredicate` and its usage in various places are mostly correct. However, the addition of the `includeSystem` parameter is a good change but it should be ensured that all places where this predicate is used have considered whether system indices should be included or not.

#MNTJG: The change to allow restricted indices for internal users is necessary for the new functionality introduced in the migration process. However, it should be ensured that this does not introduce any security vulnerabilities and that only authorized actions are allowed on these indices.
