#F6GD5, #GYWFX: The change in `skipExpression` now includes `Case` expressions, which is a logical extension given the new test cases added for `IsNotNull` on `Case`. However, the test case `testIsNotNullOnCase` checks the children of the `Case` expression using `Expressions.names`, which expects `Expression` objects. The `contains` matcher in the test case uses string literals that do not represent valid `Expression` names. This will likely cause the test to fail because the actual children of a `Case` expression are expressions like `emp_no > 10000`, `"1"`, etc., and these cannot be directly compared with string literals.
