#ATH6F, #4MF5Z: The check for `maxFileSize != -1` is added to ensure that a file size of `-1` is treated as an invalid value. However, this change assumes that `-1` is a valid representation for an unlimited or undefined file size in the context of `ProcessLimits`. It would be clearer if this assumption was documented or if there was a constant defined for `-1` to represent an undefined file size. The test case now includes setting `maxFileSize` to `-1` and verifying that no exception is thrown. This is good as it ensures the check handles `-1` correctly. However, it would be beneficial to add a comment explaining why `-1` is being used in this context, especially if `-1` represents an undefined or unlimited file size.
