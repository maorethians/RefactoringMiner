#MTJ29: The change from using a custom `SourceLoader.SyntheticFieldLoader` to `SyntheticSourceSupport.Fallback` is intended to ensure that synthetic source does not include a value if there was no value in the document. However, this change might not fully replicate the behavior of the previous implementation, especially regarding the `fieldName()` method which returned `fullPath()`. The `Fallback` class may not handle this specific requirement correctly.

#3VA9W: The test case added (`testNoValueInDocumentSyntheticSource`) is a good start for ensuring that synthetic source behaves as expected when there is no value in the document. However, it would be beneficial to add more test cases covering different scenarios, such as when the field has a value and when the field is nested within other objects.
