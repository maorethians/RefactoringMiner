#2T3QZ, #FXAR8: The change from `IndicesOptions.strictExpandOpen()` to `IndicesOptions.strictExpandOpenAndForbidClosed()` in `FieldCapabilitiesRequest` and the subsequent tests assume that closed indices should be forbidden. However, the new test cases do not fully cover scenarios where indices are explicitly specified versus using wildcards. Additionally, the message assertion in `testOneClosedIndex` seems incorrect as it checks for a specific string "closed" which might not be the exact message thrown by `IndexClosedException`. The tests introduced (`testNoIndices`, `testNoIndicesIgnoreUnavailable`, `testOneClosedIndex`, `testOneClosedIndexIgnoreUnavailable`, `testTwoIndicesOneClosed`, `testTwoIndicesOneClosedIgnoreUnavailable`) are comprehensive for the new behavior but could benefit from more descriptive assertions. For instance, instead of checking the message "closed", it would be better to verify that an `IndexClosedException` is thrown when a closed index is accessed and ignored when `ignoreUnavailable` is set.
