#A715P, #6BC19, #N4H71: The fields `stoppedCompilationTime` and `logShutdownCompilations` are accessed and modified by multiple threads within `submitForCompilation` without synchronization or the use of `volatile`. This can lead to memory visibility issues and race conditions; for example, the shutdown warning may be logged multiple times if several threads enter the `SHUTDOWN_COMPILATION` block simultaneously.

#N4H71: When `compilationActivityMode` is `STOP_COMPILATION`, the code iterates through all queued targets to cancel them on every call to `submitForCompilation` until the retry delay expires. Since this method can be called frequently, repeatedly scanning and attempting to cancel the same set of targets in the queue is inefficient. The queue flush should ideally occur only once when the transition to `STOP_COMPILATION` is first detected (e.g., inside the `if (stoppedCompilationTime == 0)` block).
