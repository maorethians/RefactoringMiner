#Y0M91: The logic in `unsignedLongAsLongExact` is inverted and incorrect. An unsigned long stored as a signed `long` fits into a signed `long` if and only if it is non-negative (i.e., its most significant bit is 0). The current implementation throws an exception for all valid values ($\ge 0$) and attempts to return a transformed value for invalid ones ($< 0$). It should be:
```java
if (l >= 0) {
    return l;
}
throw new ArithmeticException(UNSIGNED_LONG_OVERFLOW);
```

#T7GHK: In `ascending` (Double), the average of two middle values is calculated as `(values.getDouble(middle - 1) + values.getDouble(middle)) / 2`. However, in `doubleMedianOf`, it is calculated as `(values[middle - 1] / 2 + values[middle] / 2)`. The latter is safer against overflow (though unlikely here) and should be used consistently across both methods.
