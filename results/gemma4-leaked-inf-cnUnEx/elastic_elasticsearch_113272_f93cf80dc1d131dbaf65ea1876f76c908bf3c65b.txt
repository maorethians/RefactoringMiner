#9CT4X: The use of the Java `assert` keyword (e.g., `assert testCase.getMatcher().matches(Double.NaN) == false`) is discouraged in test suites as these assertions are ignored by default unless the JVM is explicitly started with the `-ea` flag. These should be replaced with `assertThat` or other JUnit/Hamcrest assertions to ensure they are always executed in CI/CD environments.

#PBD1R: The logic in `addSuppliers` introduces a regression in test coverage for empty collections. While it explicitly handles cases for size 1 and sizes $\ge 2$, it completely omits the case where the collection size is 0, even if `minRows` is 0. If `minRows` was previously used to include empty lists in tests (as seen in the original `randomList(minRows, maxRows, ...)` calls), those scenarios are no longer tested.

#54Y24: The logic for calculating the expected average has changed for empty data sets. In the previous implementation, an empty stream processed by `summarizingInt/Long/Double().getAverage()` would result in `0.0`. In the new implementation, if `fieldData.size()` is 0, the `expected` value remains `null`. This changes the test expectation from `0.0` to `null`, which may lead to test failures or mask bugs depending on whether the ESQL `Avg` function is intended to return null or zero for empty inputs.
