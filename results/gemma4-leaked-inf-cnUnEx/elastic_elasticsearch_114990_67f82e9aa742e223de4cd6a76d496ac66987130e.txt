#FT0CW: The rewrite logic in `doCoordinatorRewrite` for `TermsQueryBuilder` is logically incorrect. A `terms` query acts as a logical OR; therefore, the query should be rewritten to `MatchAllQueryBuilder` if *any* of the provided terms match the tier, and only rewritten to `MatchNoneQueryBuilder` if *none* of them match. The current implementation returns `MatchNoneQueryBuilder` immediately upon encountering the first non-matching term, effectively treating the query as a logical AND.

#H9T2D, #YA34E, #AKW8H: In `QueryStringQueryBuilder` and `SimpleQueryStringBuilder`, the raw `queryString` (or `queryText`) is passed directly to `tierFieldTermQueryCoordinatorRewriteIfPresent`. Since this helper method eventually calls `internalTermQuery`, it treats the entire query string as a single literal term. This bypasses the parsing and analysis logic inherent to these builders, meaning complex queries (e.g., those containing operators like `AND` or `OR`) will fail to match unless the tier name exactly matches the raw query string.
