#5HMC7: The logic in `onConnectionClosed` completely ignores the `enableStackOverflowAvoidance` field (initialized in #Y2B46). The current implementation forces a fork to `threadPool.generic()` whenever the handler's executor is `DIRECT`, regardless of whether stack overflow avoidance is enabled or disabled via settings. This contradicts the purpose of introducing the `ENABLE_STACK_OVERFLOW_AVOIDANCE` setting and will cause tests like #4H8Q2 (which expects direct execution when the setting is false) to fail.

#5HMC7: The second check `if (executor == EsExecutors.DIRECT_EXECUTOR_SERVICE)` is logically redundant or unreachable. Since the preceding block explicitly replaces `EsExecutors.DIRECT_EXECUTOR_SERVICE` with `threadPool.generic()`, this condition can only be true if `threadPool.generic()` returns the direct executor, which is not the case for a standard thread pool.
