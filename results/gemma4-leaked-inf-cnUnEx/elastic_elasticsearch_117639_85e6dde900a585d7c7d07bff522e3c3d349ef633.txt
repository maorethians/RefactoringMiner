#CJW50: The updated logic for calculating join outputs correctly handles the removal of match fields from the non-dominant side (e.g., removing match fields from the right side during a `LEFT` join). This ensures that only one copy of the join key is preserved in the output, which is consistent with standard SQL `USING` semantics and prevents attribute name collisions.

#6310A, #CP3WV: The removal of `computeReferences()` from `BinaryPlan` is a necessary correction. As noted in the documentation update in `#CP3WV`, `computeReferences` must not rely on `output()`. The previous implementation in `#6310A` violated this constraint by calling `Expressions.references(output())`. Removing this override ensures that binary plans fall back to a safer reference computation mechanism (likely summing children's references) that does not depend on the resolved output state.

#CF847, #2JNNB, #NSX49: The refactoring of `LookupJoin` to remove the explicit `output` field and rely on the inherited `Join.output()` method is consistent across the chapter. The changes in `Analyzer.resolveLookupJoin` correctly align with this by no longer attempting to pre-calculate the output list, instead delegating that responsibility to the plan's own logic via the `JoinConfig`.

#K6N7D: The removal of unused variables `keepMatches` and `keepPatterns` in `EsqlSession.fieldNames` is a good cleanup that reduces noise in the codebase.
