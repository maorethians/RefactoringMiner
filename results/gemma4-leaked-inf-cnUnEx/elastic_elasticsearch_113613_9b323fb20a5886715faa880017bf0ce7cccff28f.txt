#D7008, #Q5MVT: The transition from a raw `int[]` to `TDigestIntArray` for the internal stack in `IntAVLTree` introduces calls to `stack.resize()` on every single `push` and `pop` operation. While `MemoryTrackingTDigestIntArray.resize` only performs reallocation when expanding, calling it on every `pop` simply to update the logical size is unnecessary overhead compared to the previous direct integer decrement. If these operations are frequent, this will introduce significant method call overhead and potential breaker logic processing for no gain in memory efficiency (as shrinking the underlying array typically doesn't happen automatically in these implementations).

#1J5E5: In the `MergingDigest` constructor, the resource cleanup pattern differs from the one used in `IntAVLTree` (#5BVR4) and `AVLGroupTree` (#KN5K1). While using a `catch` block to close partially allocated arrays is functional, it is less robust than the `try-finally` pattern with local tracking variables. If an unexpected `Error` (like `OutOfMemoryError`) occurs rather than an `Exception`, the resources will not be released. It is recommended to align this with the safer `finally` block pattern used elsewhere in the PR.
