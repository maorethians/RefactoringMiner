#5W338: The use of `entries[i].split(":")` to parse the schema header is less robust than the previous `indexOf(':')` implementation. If a column name contains a colon, `split` will break the name into multiple parts and only the first part (`header[0]`) will be treated as the name, whereas the original code correctly identified everything before the first colon as the name.

#BBARN: The cast to `ObjectNode` when modifying the mapping properties (`((ObjectNode) propertiesNode.get(key))`) assumes that the property is defined as a JSON object. If the mapping file contains a property that is not an object (e.g., a primitive or null), this will throw a `ClassCastException`.

#VD6V6: The logic for parsing the schema row has been changed to make types optional (`if (split < 0) { columns[i] = entries[i].trim(); }`). This is a significant behavior change from the previous version, which strictly required a type definition for every column and threw an `IllegalArgumentException` otherwise.
