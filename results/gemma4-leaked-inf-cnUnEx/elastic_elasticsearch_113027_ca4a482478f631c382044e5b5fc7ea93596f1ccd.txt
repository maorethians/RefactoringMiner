#BDPYD: The implementation of `parseDocForMissingValues` uses `XContentDataHelper.encodeToken(parser)` to capture the value of missing fields. However, `encodeToken` only captures a single token (e.g., just the `START_OBJECT` or `START_ARRAY` marker). This is a regression from the previous eager implementation which used `XContentBuilder.copyCurrentStructure(parser)`, allowing it to capture entire subtrees (objects and arrays) as bytes. As a result, any ignored fields that are complex types will now have their source incorrectly recorded as only the start token rather than the full content.
