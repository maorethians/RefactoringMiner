#KVKEQ: The logic for populating `namedExpressions` only includes expressions that are instances of `Alias`. If there are other types of `NamedExpression` (e.g., constants or direct attributes not wrapped in an `Alias`), they will be missing from the map. This causes a regression compared to the previous implementation (seen in `#4X2QM`), where any non-`Attribute` `NamedExpression` was used for replacement in the upper projection.

#KVKEQ: The `namedExpressions` map is populated in a single pass over the `lower` list. If an alias references another named expression defined later in the same list, it will not be fully resolved because the dependency is not yet present in the `aliases` map at the time of processing. To ensure correctness regardless of declaration order, the `aliases` map should be fully populated before calculating the resolved expressions for `namedExpressions`.
