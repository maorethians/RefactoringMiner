#KM0Z6: The nesting of `assertBusy` calls is redundant and disrupts the timing logic of the test utility. The inner call uses a default 10-second timeout, while the outer call specifies a 1-minute timeout. Because `assertBusy` implements an exponential backoff sleep between attempts, wrapping one inside another creates a "loop within a loop" that makes the actual polling interval unpredictable and significantly exceeds the intended 1-minute window if failures occur.
If the goal is to poll for up to one minute and log warnings when searches are still active, use a single `assertBusy` call with the 1-minute timeout.
