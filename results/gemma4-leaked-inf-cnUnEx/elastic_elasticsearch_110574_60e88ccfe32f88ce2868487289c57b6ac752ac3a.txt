#7HFQ2: The logic in `validateGrokPattern` throws a `ParsingException` whenever a field name is duplicated, regardless of whether the types are the same or different. This contradicts the error message ("the attribute [foo] is defined multiple times with different types") and the intended behavior suggested by the test cases in `#N0C5B`. To align with the error message, the check should verify if `!type.equals(prev)`.

#7QWZF, #N0C5B: There is a discrepancy between the implementation of `extractedFields()` and the test case for duplicate field names. The test in `#N0C5B` expects that a pattern with duplicate names (e.g., `%{WORD:foo} %{WORD:foo}`) results in a list containing only one attribute. However, `extractedFields()` in `#7QWZF` maps every entry in the Grok capture configuration directly to a list without deduplication. If the underlying Grok configuration contains multiple captures for the same name, this test will fail as it will receive a list of size 2 instead of 1.
