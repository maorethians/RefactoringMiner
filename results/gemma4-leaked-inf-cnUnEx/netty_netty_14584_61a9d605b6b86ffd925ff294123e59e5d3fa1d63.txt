#6V64K: The use of `Math.min(2, ...)` caps the `CENTRAL_QUEUE_CAPACITY` at a maximum of 2. Since the default value is based on `NettyRuntime.availableProcessors()`, this change effectively nullifies the scaling benefit for any system with more than 2 processors and ignores any system property value greater than 2. If the intention was to ensure a minimum capacity, `Math.max` should be used instead; if a cap was intended, a value of 2 appears unusually low for a high-concurrency allocator.
