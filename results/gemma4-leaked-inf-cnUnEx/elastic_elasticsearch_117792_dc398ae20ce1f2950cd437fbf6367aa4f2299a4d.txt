#1QN8N: The `ReinitializingSourceProvider` uses a `ConcurrentHashMap` to store `SourceProvider` instances keyed by thread ID. While this effectively ensures thread-safety and avoids repeated initialization, it creates a memory overhead proportional to the number of threads accessing the provider. Since these providers are created within the scope of a compute task (as seen in `#HDRS6`), they are likely transient; however, if these objects were to become long-lived, this would result in a memory leak as entries are never removed from the map. Given the current usage pattern, this is acceptable, but it relies on the lifecycle of the `SearchExecutionContext` being short-lived.
