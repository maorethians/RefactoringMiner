#0X6BJ: The change from using an `AttributeMap` (which effectively acted as a set) to an `ArrayList` for collecting resolved attributes from groupings removes deduplication. If the same attribute appears multiple times within the groupings, it will now be passed as duplicates to `NamedExpressions.mergeOutputAttributes`, which may lead to duplicate attributes in the resulting plan.

#8PJ1J: Changing the return type from `UnsupportedAttribute` to `UnresolvedAttribute` is inconsistent with other changes in this chapter (e.g., #SS25M), which move towards using `UnsupportedAttribute` for known fields that cannot be used due to specific constraints. This semantic shift may result in less descriptive error messages for the user, as "unresolved" typically implies a lookup failure rather than a type incompatibility or unsupported operation.
