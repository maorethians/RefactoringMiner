#BCR52, #EAW4C: The logic for marking `copy_to` target fields as "void" in synthetic source has been moved from a set-based approach in `postParse` (`#EAW4C`) to an event-based approach in `createCopyToContext` (`#BCR52`). 
Because `createCopyToContext` is called for every source field that performs a copy operation, target fields that receive data from multiple sources will now have duplicate "void" markers added to `ignoredFieldValues`. This results in redundant `StoredField` entries being written to the Lucene document in `postParse`, whereas the previous implementation using `context.getCopyToFields()` (a `Set`) ensured only one marker per target field was created.
