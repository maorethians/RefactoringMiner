#KB73M, #CHG61, #36QQP, #W8BQ7, #NNZ19, #XNMTB: The implementation of backward compatibility in `readFrom` and `writeTo` methods across `EsRelation` (#KB73M, #CHG61), `EsQueryExec` (#36QQP, #W8BQ7), and `EsSourceExec` (#NNZ19, #XNMTB) is correct. It uses the new `ESQL_SKIP_ES_INDEX_SERIALIZATION` transport version to toggle between the optimized format (pattern + modes map) and the legacy format (`EsIndex`).
One detail: in the legacy path of `writeTo`, a dummy `EsIndex` with an empty mapping is created (`new EsIndex(indexPattern, Map.of(), indexNameWithModes)`). While this effectively removes mappings from serialization even for old nodes (consistent with the goal stated in test history comments), it does create a short-lived object during every serialization call. Given that these plans are typically serialized once per request/fragment, the performance impact is negligible.
