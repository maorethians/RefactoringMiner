#Y0M91: The logic in `unsignedLongAsLongExact` appears to be inverted. A method intended to convert an unsigned value to a signed long "exactly" should return the value if it fits within the signed range (i.e., the decoded result is non-negative) and throw an exception if it overflows (the decoded result is negative). 
The current implementation throws `ArithmeticException` when `l >= 0` and returns the decoded value when `l < 0`. This means it rejects values that might fit in a signed long and accepts those that likely overflow. It should instead decode the value first and then check for overflow:
```java
long result = twosComplement(l);
if (result < 0) {
    throw new ArithmeticException(UNSIGNED_LONG_OVERFLOW);
}
return result;
```
