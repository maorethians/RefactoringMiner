#HP7DM, #2X5B0: The implementation of `Locate.process` (called by `LocateEvaluator`) performs multiple expensive operations for every row in the dataset:
1. It calls `str.utf8ToString()` and `substr.utf8ToString()`, which allocate new Java `String` objects on every iteration. For large pages or long strings, this will lead to significant memory pressure and GC overhead.
2. It calls `UnicodeUtil.codePointCount(str)` followed by `str.utf8ToString()`. Both methods traverse the byte array of the `BytesRef`, resulting in redundant processing.
Consider optimizing this by avoiding full string conversions where possible or using a more efficient search mechanism that operates directly on bytes/codepoints.
