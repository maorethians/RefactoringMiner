#H8WPY: The `process` method returns a value based on the character index returned by `String.indexOf`, rather than the code point index. In Java, `String` uses UTF-16 encoding where some Unicode characters (e.g., emojis) occupy two characters (a surrogate pair). If the input string contains such characters before the match, the returned position will be incorrectly shifted. To fix this, you should calculate the number of code points from the start of the string up to the index found by `indexOf` using `utf8ToString.codePointCount(0, charIndex)`.

#HP7DM, #H8WPY: The implementation of `Locate.process` calls `utf8ToString()` on both the source string and the substring for every single row processed in the evaluator loop. Creating two new `String` objects per row will cause significant performance degradation and high GC pressure when processing large pages. Consider optimizing this by avoiding repeated conversions or using a more efficient byte-level search if possible.
