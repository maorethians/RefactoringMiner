#GA0HQ: The filter `n.getVersion().after(Version.V_8_16_0)` excludes nodes that are exactly version `8.16.0`. In Elasticsearch, when a feature or requirement is introduced at a specific version, the check is typically inclusive (e.g., using `onOrAfter`). If nodes on version `8.16.0` also require this fixup for their system index mapping versions, this should be changed to `onOrAfter(Version.V_8_16_0)`.

#WEDEC: The assertion error message `"Node " + e.getKey() + " is in the cluster but does not have an associated transport version recorded"` is now outdated because the check has been expanded to `CompatibilityVersions` (which includes both transport and mapping versions). The message should be updated to reflect that it is checking for compatibility versions generally, rather than just the transport version.
