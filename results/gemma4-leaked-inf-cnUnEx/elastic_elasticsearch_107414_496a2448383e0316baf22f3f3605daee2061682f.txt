#0VTRR: The implementation of `surrogate()` for `Count` returns `null` when the field is a simple non-list literal (e.g., `COUNT(1)`). This contradicts the accompanying TODO which suggests normalizing such cases to `COUNT(*)`. Returning `null` prevents the surrogate optimization from applying, leaving the expression as-is rather than optimizing it to a more efficient form.

#WNGXM: This change introduces a regression in the `PushStatsToSource` rule. Previously, multiple statistics could be pushed to the source as long as they shared the same name (type). The new logic unconditionally returns `aggregateExec` if there is more than one statistic, regardless of whether they are of the same type, which reduces the optimizer's ability to push aggregations down to the data source.

#QGZHP: The test `testMultiCountAllWithFilter` has been significantly weakened. Detailed assertions verifying the physical plan structure (e.g., checking for `ProjectExec`, `LimitExec`, and `AggregateExec`) and the correctness of the generated Elasticsearch query have been replaced by a single check for the presence of an `EsQueryExec`. This results in a loss of coverage for ensuring that semantically equivalent counts (`count()`, `count(*)`, `count(1)`) are correctly optimized and deduplicated.
