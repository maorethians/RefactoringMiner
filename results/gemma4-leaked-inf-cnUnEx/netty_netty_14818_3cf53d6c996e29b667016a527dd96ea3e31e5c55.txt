#KCC2A: In the `finally` block of `readComplete`, there is a logic error when handling `Native.ERRNO_ECANCELED_NEGATIVE` outside of the `recvBufAllocHandle().isReadComplete()` condition. The code calls `doBeginReadNow()` twice if `pending` is true, and calls it once even if `pending` is false:
```java
} else if (res == Native.ERRNO_ECANCELED_NEGATIVE) {
    if (pending) {
        doBeginReadNow();
    }
    doBeginReadNow();
}
```
This likely should only call `doBeginReadNow()` if `pending` is true, to ensure a read is re-scheduled only when the user has signaled the desire to continue reading after a cancellation.
