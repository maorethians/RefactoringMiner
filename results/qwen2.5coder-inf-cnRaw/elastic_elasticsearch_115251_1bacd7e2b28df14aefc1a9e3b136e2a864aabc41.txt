#82926, #D8GXG: The logic for filtering settings now includes checking against prefixes and explicitly denied settings. However, there is a potential issue with the `EXPLICITLY_DENIED_SETTINGS` check. In both `#82926` and `#D8GXG`, the condition to filter out explicitly denied settings is incorrect. The current implementation will deny any setting that matches the prefix and also exists in `EXPLICITLY_DENIED_SETTINGS`. Instead, it should only deny settings that are exactly in `EXPLICITLY_DENIED_SETTINGS`.
For example, if a setting is "index.routing.include.group_prefix.some_value", it will be incorrectly denied because it starts with a prefix and also matches the condition for being explicitly denied.
Suggested fix:
In both `#82926` and `#D8GXG`, change the filter condition to ensure that settings in `EXPLICITLY_DENIED_SETTINGS` are not included, regardless of whether they match any allowed prefixes. This can be done by adjusting the logical conditions to prioritize explicit denial.
