#XTYE5: Asynchronous Error Handling: In #XTYE5, several methods (e.g., `dataStreamMigrationFailed`) signal failure by throwing an `ElasticsearchException` inside an `ActionListener`. While this works because the listeners are wrapped with `ActionListener.wrap(...)` (which catches exceptions and forwards them to `onFailure`), it is generally more explicit in this codebase to call `markAsFailed(ex)` directly rather than relying on exception propagation through a wrapper.

#D6FWV: Privilege Escalation: The change in #D6FWV to set `.allowRestrictedIndices(true)` for the `REINDEX_DATA_STREAM_USER` is correct and necessary, as system data streams are marked as restricted indices and must be accessible by the internal user performing the migration.

#CTNB2, #18VMT: Abstraction: The introduction of `SystemResourceMigrationInfo` (`#CTNB2`) and `SystemResourceDescriptor` (`#18VMT`) effectively decouples the migrator from the specific details of whether it is handling a concrete index or a data stream, significantly improving the maintainability of the migration loop.

#KKWW7, #6PWQV, #E611S: Unified Matching: Moving `getMatchingIndices` to the `IndexMatcher` interface (`#KKWW7`, `#6PWQV`) allows for polymorphic treatment of system resources in diagnostic services (e.g., `#E611S`), reducing code duplication.

#BVCJV, #XTYE5: The addition of `SystemDataStreamMigrationIT` (`#BVCJV`) provides critical coverage for the new data stream migration path, including a scenario for restarting migration after a failure, which validates the recovery logic implemented in `#XTYE5`.
