#D7008, #Q5MVT: The changes introduce significant performance overhead by calling `stack.resize()` on every `push` and `pop` operation. In the provided `MemoryTrackingTDigestIntArray` implementation, `resize` triggers an `Arrays.fill` call when expanding and performs several checks. 
This pattern appears to be used solely to satisfy the assertions in `get()` and `set()` (which check that the index is within the current logical `size`). Since these assertions are typically disabled in production, this results in unnecessary execution overhead for every stack operation. The stack should instead manage its own logical size and only trigger a resize when the physical capacity of the underlying array is exceeded.
