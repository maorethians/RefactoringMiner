#0YX4V, #6QJHN, #VJ465, #E2Y93: The use of double casting `(List<Attribute>) (List)` to convert `List<NamedExpression>` to `List<Attribute>` is fragile. This bypasses compile-time type checking and will result in a `ClassCastException` at runtime if any element in the list is not an instance of `Attribute`. For deserialization (`#0YX4V`, `#6QJHN`, `#VJ465`), this assumes that all previously serialized `NamedExpression` objects are compatible with the new `Attribute` type.

#E5T60, #VN2MY: The output merging semantics for joins have been reversed. The previous implementation (`#E5T60`) prioritized the left-hand side in case of name conflicts ("left hand side wins"), whereas the new implementation (`#VN2MY`) specifies that "the rightOutput shadows the leftOutput". This is a significant change in behavior for `LEFT JOIN` results.

#VN2MY: The updated `Join.computeOutput` now throws an `UnsupportedOperationException` for any join type other than `LEFT`. The previous implementation contained logic branches for `RIGHT` and `FULL` joins, suggesting a reduction in supported functionality.

#HXZG9: `Lookup.output()` has been changed to throw an `IllegalStateException` when the table is unresolved (`localRelation == null`). This replaces a fallback mechanism that previously allowed the method to return a result based on `matchFields`, potentially breaking components that inspect the plan before resolution is complete.
