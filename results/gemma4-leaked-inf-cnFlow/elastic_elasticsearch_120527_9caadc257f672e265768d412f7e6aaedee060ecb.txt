#33VQT, #ENYZX, #CG8GE, #EBC2B: The current implementation will throw a `QlIllegalArgumentException` when parsing queries that result in certain `UnresolvedRelation` nodes (e.g., those created in `visitMetricsCommand` or `visitJoinCommand`). 
In `#ENYZX` and `#CG8GE`, these nodes are explicitly initialized with a `null` metric name. However, because `UnresolvedRelation` implements `MetricsAware` (`#GX5Y0`), it is passed to `metrics.command()` in `#EBC2B`. The implementation of `metrics.command()` in `#33VQT` strictly forbids null metric names and throws an exception if one is encountered. 
If these nodes are intended to be excluded from metrics (as suggested by the comment in `#CG8GE`), the check in `metrics.command()` should be updated to ignore null values instead of throwing an exception, or the nodes should not implement `MetricsAware`.
