#1N64B, #91T4G: There is a logic inconsistency between the trigger for source synthesis and its implementation. In `#1N64B`, the condition to synthesize the source is expanded to include cases where inference fields are present (`inferenceFields().isEmpty() == false`). However, the implementation of `newSnapshot` in `#91T4G` only checks if recovery source synthesis is enabled (`isRecoverySourceSyntheticEnabled()`) when deciding whether to instantiate a `LuceneSyntheticSourceChangesSnapshot`.
If inference fields are present but `isRecoverySourceSyntheticEnabled()` is false, the code will enter the synthesis block in `#1N64B` but actually use a standard `LuceneChangesSnapshot` via `#91T4G`, which reads the stored source instead of synthesizing it. This likely defeats the purpose of adding the inference fields check to the trigger. The logic in `newSnapshot` should be updated to align with the conditions used in `#1N64B` and `#71WX8`.
