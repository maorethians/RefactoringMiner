#Y0M91: The logic in `unsignedLongAsLongExact` appears to be inverted. If the input `l` is a non-negative signed long, it already represents an unsigned value that fits within a signed long and should be returned as-is. However, the current implementation throws an `ArithmeticException` for `l >= 0` and attempts to convert values where `l < 0`.

#1260F: The method `unsignedLongMedianOf` uses `Arrays.sort(long[])`, which performs a signed sort. Since this method is intended to find the median of unsigned long values (encoded as signed longs), a signed sort will produce an incorrect ordering (e.g., values $\ge 2^{63}$ will be placed at the beginning of the array). This results in an incorrect median calculation for any dataset containing large unsigned values.
