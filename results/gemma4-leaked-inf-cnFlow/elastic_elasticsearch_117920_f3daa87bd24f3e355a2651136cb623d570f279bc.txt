#K33S7, #B4JT9, #94Q6X: The removal of `handleAlreadyShuttingDownWorker()` and the subsequent changes to the shutdown logic in `forcefullyStopProcess` and `stopProcessAfterCompletingPendingWork` result in a regression where pending tasks in the `priorityProcessWorker` queue are no longer notified of failure or rejection.
In `#B4JT9`, calling `shutdownNow()` stops the worker immediately but does not notify the queued tasks; it only returns them as a list (which is currently ignored). Previously, if the worker was already shut down, `notifyQueueRunnables()` was called to ensure all pending requests were failed. To maintain this behavior and avoid leaving requests in an unresolved state, `priorityProcessWorker.notifyQueueRunnables()` should be called after `shutdownNow()`.
Similarly, in `#94Q6X`, the removal of the `isShutdown()` check means that if the worker is already shut down, the code proceeds directly to `signalAndWaitForWorkerTermination()`. If this method returns without timing out (e.g., because the worker is already stopped), `notifyQueueRunnables()` will never be invoked, leaving any remaining tasks in the queue abandoned.
