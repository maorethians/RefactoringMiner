#T78XV: The `typeErrorMessage` method generates an expected error message that does not match the format produced by `TypeResolutions.isType`. Specifically:
1. It uses `[]` as a placeholder for the operation name, whereas the actual code inserts the function's source text (e.g., `[Max]`).
2. It uses the type name (`name`) for both the "found value" and "found type" parts of the message, while the actual code uses the expression's name (which for literals is typically the value itself) for the former.
This will likely cause tests asserting type errors to fail due to string mismatches.

#QVJ6B: In `processPageGrouping`, the variable `allValuesNull` is true if *any* block in the input page is entirely null (`anyMatch(Block::areAllValuesNull)`). This value then forces the `seenGroupIds` range to 0. It is unclear why a single all-null column should invalidate the group ID range for the entire page, regardless of whether that specific column is used as a grouping key.
