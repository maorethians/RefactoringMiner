#Y0M91: The logic in `unsignedLongAsLongExact` appears to be inverted. It currently throws an `ArithmeticException` when the input `l` is non-negative (which would be a valid signed long) and returns a value when `l` is negative (which indicates an unsigned overflow beyond `Long.MAX_VALUE`).

#ZTT7Y: In `unsignedLongAvgWithoutOverflow`, the use of the arithmetic right shift operator (`>>`) will produce incorrect results for values where the most significant bit is set. Since these are treated as unsigned longs, a logical right shift (`>>>`) should be used instead to avoid sign extension.
