#DJ9MA, #YZ9VR: The use of a `ConcurrentMap` to store `SourceProvider` instances keyed by thread ID introduces a potential memory leak. Since entries are never removed from the map, it will grow indefinitely as new threads call `getSource`. Using a `ThreadLocal<SourceProvider>` would be more idiomatic and ensure that providers are cleaned up when threads are garbage collected.

#YZ9VR: Using `currentThread.threadId()` as the map key is risky because JVM thread IDs can be reused after a thread terminates. This could result in a new thread incorrectly inheriting a `SourceProvider` created by a previous, unrelated thread that happened to share the same ID. The previous implementation (though not thread-safe) avoided this by comparing `Thread` object references.
