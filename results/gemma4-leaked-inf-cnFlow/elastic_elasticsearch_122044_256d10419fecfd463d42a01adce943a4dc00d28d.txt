#YNRQX: In `patchJar`, the `InputStream` returned by `jarFile.getInputStream(entry)` is not closed when a class is being patched (the `if (classPatcher != null)` block). This leads to a resource leak of file handles, especially when processing large JAR files. It should be wrapped in a try-with-resources block, similar to how it is handled in the `else` block.

#YNRQX: The `transform` method iterates over `patchersToApply` using `forEach` and calls `patchJar` for each matching configuration. Since `patchJar` creates a new output file based on the input filename (`inputFile.getName().replace(".jar", "-patched.jar")`), if multiple configurations match the same input artifact, subsequent calls will overwrite the previous ones. This results in only the last matching configuration being applied. To fix this, all applicable patchers should be collected into a single map and `patchJar` should be called once.
