#WPNDY: The condition `if (bytesIngested > 0 && bytesProduced > 0)` in `toXContent` is too restrictive. If either metric is zero, neither field will be serialized. This prevents reporting cases where a pipeline ingested data but produced nothing (e.g., due to dropping documents) or vice versa. These should be checked independently or using an OR condition.

#1DEHF: The new `PIPELINE_STAT_COMPARATOR` implementation changes the sorting order from descending to ascending. The original code used `Long.compare(p2Stats..., p1Stats...)`, which sorted pipelines by highest time/count first. The new chain of `comparingLong` uses default natural ordering (ascending), meaning the least active pipelines will now appear first in the stats response.

#637W2: Byte statistics are only recorded for the first pipeline in the execution chain (`pipelines.peekFirst()`). If a request is processed by multiple pipelines, only the first one's metrics are updated with byte counts. This is inconsistent with the per-pipeline granularity of `PipelineStat` and fails to track the throughput of subsequent pipelines in the chain.

#WC4B5: The version ID `8_656_00_0` follows an unusual format compared to standard transport versions (typically `X_Y_Z`). Please verify if this is a typo or intended.
