#G6KR5, #9NZM8: The changes implement a refactoring of how asynchronous ES|QL queries are stopped and their results retrieved. The primary shift is moving from an in-memory map of listeners (`asyncListeners`) maintained within `TransportEsqlQueryAction` to leveraging the cluster's task management system via `AsyncTaskIndexService` and completion listeners on `StoredAsyncTask`.
The logic in `stopQueryAndReturnResult` (#G6KR5) correctly ensures a sequential flow:
1. It attempts to retrieve the task and verify security permissions using the new helper method (`#9NZM8`).
2. If the task is not found or access is denied, it falls back to the standard result retrieval action, which is appropriate as the query may have already finished or the user may lack permissions.
3. If the task exists, it marks the execution info as partial and triggers `finishSessionEarly`.
4. It then ensures that results are only requested after both the "stop" signal has been processed and the task itself has reached a completed state, either by adding a completion listener or executing immediately if already complete.
This approach is more robust than the previous implementation as it removes local state from the coordinating node and relies on the existing task lifecycle.
