#GD6NB: In the `processDoubles`, `processInts`, and `processLongs` methods, there is a critical indexing bug when `valuesBlock.mvSortedAscending()` is true. 
The code uses relative offsets (e.g., `0`, `valueCount - 1`, `lowerIndex`) as arguments to the block's getter methods (`getDouble`, `getInt`, `getLong`). However, according to the `DoubleBlock`/`IntBlock`/`LongBlock` API, these methods require absolute value indices, which start at `getFirstValueIndex(position)`.
For example, in `processDoubles`:
- `valuesBlock.getDouble(0)` should be `valuesBlock.getDouble(firstValueIndex)`
- `valuesBlock.getDouble(valueCount - 1)` should be `valuesBlock.getDouble(firstValueIndex + valueCount - 1)`
- `valuesBlock.getDouble(lowerIndex)` should be `valuesBlock.getDouble(firstValueIndex + lowerIndex)`
The same pattern of error exists in the optimized paths of `processInts` and `processLongs`. This will lead to incorrect results or `ArrayIndexOutOfBoundsException` when the first value index for a position is not 0.
