#B9YWS, #TCNQE, #AQN8A: The logic has changed from preventing a read that would exceed the limit to detecting it after the read has occurred. This allows the underlying stream to be advanced by one byte beyond `maxBytesRead` before an exception is thrown (both in single-byte and bulk reads).

#B9YWS: The exception message now reports the actual number of bytes read (`numRead`) instead of the configured limit (`maxBytesRead`). Since this check occurs after the increment, it will always report `maxBytesRead + 1`, which may be confusing to the user.
