#7HFQ2: The validation logic throws a `ParsingException` whenever a duplicate attribute name is encountered (`if (prev != null)`), regardless of whether the types are identical. This contradicts both the error message ("defined multiple times with different types") and the test case in `#N0C5B`, which expects patterns with duplicate names but identical types to be permitted. The condition should be updated to check if the types actually differ (e.g., `if (prev != null && !prev.equals(type))`).

#7QWZF, #7HFQ2: There is a discrepancy between the validation logic and the attribute extraction. Even if `#7HFQ2` is updated to allow same-type duplicates, `Grok.Parser#extractedFields()` in `#7QWZF` does not perform any deduplication. This would result in the `Grok` logical plan containing multiple attributes with the same name, which contradicts the test case in `#N0C5B` that expects a single attribute to be returned when the same field is defined multiple times with the same type.
