#YM7NQ: In the S3 implementation, `operations` is incremented regardless of whether the response is null, whereas `requests` is only updated if `response != null`. This creates a scenario where the number of logical operations can exceed the number of network requests (`operations > requests`), which is logically counter-intuitive as every operation must involve at least one request. While there is a comment regarding backward compatibility (BWC) for the `requests` count, applying the same BWC constraint to the new `operations` metric or ensuring that `requests` always $\ge$ `operations` would be more consistent with the Azure implementation (#FBAQ7).
