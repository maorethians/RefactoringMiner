#89XMM, #EMHVE: The capability flag `FIX_MV_EXPAND_LIMIT_PUSHDOWN` introduced in `#C3S6Q` is not checked in the implementation logic of the pushdown rule or the physical mapping. This means the feature is enabled by default regardless of the capability setting.

#89XMM: The cast `(int) limitSource.fold()` assumes that the limit expression always folds to an `Integer`. If the expression cannot be folded or returns a different numeric type (e.g., `Long`), this will throw a `ClassCastException`. It is safer to verify the result of `fold()` before casting.

#89XMM, #EMHVE: When a limit is pushed down into an `MvExpand` node and also remains as a `Limit` node below it (e.g., when `mvxLimit` was null), the resulting physical plan will contain two redundant `LimitExec` operators with the same value (`LimitExec -> LimitExec -> MvExpandExec`). While functionally correct, this is sub-optimal.
