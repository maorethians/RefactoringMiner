#0VTRR: The implementation of `surrogate()` for `Count` introduces an inconsistency between how different types of constants are handled. While foldable expressions (e.g., `COUNT(2-1)`) are transformed into a multiplication of `MV_COUNT` and `COUNT(*)`, simple non-null scalar literals (e.g., `COUNT(1)`) return `null`, bypassing the optimization. Although there is a TODO regarding normalization, this results in different execution plans for semantically identical queries depending on whether the constant is a literal or a foldable expression.

#WNGXM: The removal of the check that ensured all statistics had the same name before pushing them to the source suggests that `EsStatsQueryExec` now supports multiple distinct statistics in a single request. This is a performance improvement as it allows more work to be pushed down to the Elasticsearch source.

#9415T, #RC2RR: The logic for resolving aliases in groupings (`combineUpperGroupingsAndLowerProjections`) correctly ensures that grouping attributes are resolved to their underlying expressions from lower projections, preventing redundant attribute tracking and ensuring consistency in the logical plan.
