#NT186: The change from `searchContext.shardTarget().getShardId().id()` to `searchContext.request().shardRequestIndex()` is a semantically correct fix. The `shardRequestIndex` is the ordinal position of this shard request within the coordinating node's list of shard requests, which is the correct identifier for matching shard results back to their corresponding requests. The old `shardId().id()` is a property of the index's shard topology and does not necessarily correspond to the position in the request list (e.g., if not all shards are queried, or if the order differs). This is a proper bug fix.
