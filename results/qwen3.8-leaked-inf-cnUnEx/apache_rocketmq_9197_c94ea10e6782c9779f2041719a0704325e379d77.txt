#2VXS0: The `NotifyResult` class is a result object that is created, populated, and then handed off through a `CompletableFuture`. Making the fields `final` and removing the setters (constructing the object with both values in the constructor) would make it inherently thread-safe and signal to callers that it is immutable. As written, a caller could accidentally mutate it after it has been shared. This is a minor style/robustness point rather than a bug, but it aligns better with the "result" semantics of the class.
