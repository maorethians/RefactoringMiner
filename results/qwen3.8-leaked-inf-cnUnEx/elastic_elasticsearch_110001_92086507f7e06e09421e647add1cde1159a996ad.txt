#XCFTS, #080GS, #28MVQ, #70PH1, #EJ46D, #FTDPG, #B7N6C, #E5PBT: The new assertion logic is strictly weaker than the original. The original `assertThat(list, containsInAnyOrder(values))` verifies that the result contains **exactly** the expected values (no more, no less). The replacement only checks that all expected values are *present* in the result (`set.containsAll(...)`), silently passing if the result contains **extra** unexpected values. If the intent is to relax the check (e.g., to tolerate implementation-specific extra entries), this should be made explicit with a comment explaining why. Otherwise, a regression that produces spurious values in the aggregation result would go undetected.
A clearer and safer formulation that preserves the "all expected values must be present" intent while giving a useful failure message would be:
```java
TreeSet<?> set = new TreeSet<>((List<?>) BlockUtils.toJavaObject(result, 0));
assertThat("Missing expected values", set.containsAll(Arrays.asList(values)), is(true));
```
This avoids the inverted `if` + nested assertion pattern, which is harder to read and makes the pass/fail semantics less obvious.

#XCFTS, #080GS, #28MVQ, #70PH1, #EJ46D, #FTDPG, #B7N6C, #E5PBT: `new TreeSet<>(collection)` will throw a `NullPointerException` if the collection contains any `null` elements, because `TreeSet` relies on natural ordering. If the `VALUES` aggregation can produce a result list that includes `null` (e.g., when the input contains nulls and the implementation does not filter them), this will cause a test crash rather than a clean assertion failure. Consider using a `HashSet` instead (which tolerates nulls) or guarding against nulls before constructing the set.

#XCFTS, #080GS, #28MVQ, #70PH1, #EJ46D, #FTDPG, #B7N6C, #E5PBT: The Yoda-condition style `false == set.containsAll(...)` is unconventional in Java and reduces readability. The idiomatic form is `!set.containsAll(...)` or `set.containsAll(...) == false`. This pattern is repeated across all eight diffs; a small helper method in the shared test base class would also eliminate the duplication.
