#90Y0T: Two subtle changes are bundled here beyond the mechanical builder removal:
1. `jobBuilder.getId()` is now used to resolve the job ID for `datafeedTimingStats`, whereas the old code used `context.getJob().getId()` (i.e., the *built* Job's ID). Although `Job.Builder#getId()` and `Job#getId()` return the same value in practice, this is a semantic shift from "the built object's identity" to "the builder's field." If the builder's `id` could ever diverge from the built job's `jobId` (e.g., through a future builder mutation), this would silently break.
2. `jobBuilder.build()` is now invoked *inside* the async `timingStats` callback rather than before the async chain. This means the builder is consumed later in the lifecycle. If any retry or re-invocation of the callback occurs, `build()` would be called again on a potentially mutated builder. Consider building the `Job` once before the async chain (as the old code did) and capturing the result in a local variable.
