#H8WPY: The `process` method's early-exit check `str.length < substr.length` compares byte lengths. While this is a valid optimization (a shorter byte sequence cannot contain a longer one), it's worth noting that the rest of the logic operates in code points. This is correct but could be slightly confusing to readers. More importantly, the `indexStart` method handles the `start` parameter conversion from 1-based to 0-based and negative offsets, but there is no guard against `start` being so negative that `codePointCount + start` overflows. In practice this is unlikely given realistic string sizes, but a defensive `Math.max(0, ...)` is already applied, so this is safe.
