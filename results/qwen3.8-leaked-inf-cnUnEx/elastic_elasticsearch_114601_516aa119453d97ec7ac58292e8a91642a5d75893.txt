#8DNMQ: The Javadoc documents `IllegalArgumentException` for ambiguous paths but does not mention the `IllegalStateException` thrown when `extractSuffixMaps` returns an empty list. Even though the comment says "This should never happen," a defensive `IllegalStateException` is still a contract that callers could encounter. Consider either documenting it in the `@throws` section or, better, converting it to an `IllegalArgumentException` with a descriptive message (e.g., `"Path [" + path + "] could not be resolved in the provided map"`) so callers see a single, documented exception type for all failure modes.

#HEM3Z: When `currentValue` is a `List`, the method recurses into every element and aggregates results. If a list contains multiple maps and only a subset of them contain the target key, the non-matching maps each contribute a fallback `SuffixMap` (via the `if (suffixMaps.isEmpty())` branch in the Map case), producing an ambiguity exception. For example, inserting `"a.b"` into `{"a": [{"x": 1}, {"y": 2}]}` would throw `IllegalArgumentException` because the second map doesn't have key `"x"` and falls back to inserting `"b"` there. This is a safe-by-default design, but it means that updating a field in a list of documents where not every document has that field will fail. If this is intentional, a brief comment at the list-recursion site explaining *why* non-matching elements produce fallbacks (and thus ambiguity) would help future readers understand the behavior is deliberate rather than an oversight.

#V6TZN: The `lastIndexOf(leafName())` approach correctly identifies the parent path for all valid inputs (verified with cases like `"bar.bar"`, `"a.b.c"`, and dotted leaf names). However, when the parent object mapper is not found in `mappers.objectMappers()`, the thrown `IllegalStateException` message says the field "does not have a parent object mapper." In practice, the most common reason for a missing parent mapper is that a *grandparent* object has `subobjects` disabled, which prevents intermediate object mappers from being registered. The current message doesn't hint at this root cause, which could make debugging harder. Consider appending a hint such as `" (this may be caused by subobjects being disabled on an ancestor object field)"` to the `IllegalStateException` message.
