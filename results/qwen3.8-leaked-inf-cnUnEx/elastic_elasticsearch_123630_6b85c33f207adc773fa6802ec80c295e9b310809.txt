#ANQNQ: The test asserts `getSuppressed().length < MAX_DELETE_EXCEPTIONS`, which correctly verifies the cap is not exceeded. However, because `blobs` is a random list of size `1..(20 * maxBulkDeleteSize)` and the batch size is `maxBulkDeleteSize`, the number of failed delete requests can be as low as 1 (e.g., 1 blob with batch size 10). In that case only 1 exception is stored (0 suppressed), and the assertion passes trivially without ever exercising the cap. Consider asserting `equalTo(MAX_DELETE_EXCEPTIONS - 1)` when the number of generated batches is guaranteed to exceed the cap, or at minimum add a guard that the random parameters produce at least `MAX_DELETE_EXCEPTIONS` batches so the test is meaningful on every run.
