#3MMWQ: In `testSynthesizeIdRandom`, a new variable `numberOfMerics` is declared and used to size the `ArrayList`, but the loop that populates it iterates over `numberOfDimensions` instead:
```java
int numberOfMerics = randomIntBetween(1, 6);
List<String> metricNames = new ArrayList<>(numberOfMerics);
for (int j = 1; j <= numberOfDimensions, j++) {   // <-- should be numberOfMerics
    metricNames.add(randomAlphaOfLength(4));
}
```
This means the number of metric names is always equal to the number of dimensions, and `numberOfMerics` is effectively dead code. The test no longer exercises varying metric-name counts independently of dimension counts.

#XBX2V: The field name used in the exclusion check does not match the actual field name defined in the mapper. The mapper declares:
```java
public static final String NAME = "_ts_metric_names_hash";  // note the 's'
```
But `PerFieldFormatSupplier.excludeFields` checks:
```java
fieldName.equals("_ts_metric_name_hash") == false  // missing 's'
```
Because of this typo, `_ts_metric_names_hash` will still be excluded from the TSDB codec (the `startsWith("_")` branch will match and none of the equality checks will save it), which is the opposite of the stated intent. The field should be kept in the TSDB codec to benefit from the same optimizations as `_tsid` and `_ts_routing_hash`.

#HG7BY: The version gate for writing the `_ts_routing_hash` doc-values field is tightened from `onOrAfter(TIME_SERIES_ROUTING_HASH_IN_ID)` to `onOrAfter(TIME_SERIES_METRIC_NAMES_HASH_IN_ID)`. For indices created between those two versions, new documents will no longer get the routing-hash doc-values field. However, the `IdLoader` path (see #TMJ4T) still unconditionally asserts the field is present when `builders == null`:
```java
found = routingHashDocValues.advanceExact(docId);
assert found;
```
If a document in such an index is indexed after this change, the assertion will fire during synthetic-source ID reconstruction. Consider whether the condition should remain `onOrAfter(TIME_SERIES_ROUTING_HASH_IN_ID)` (or whether the `IdLoader` needs a fallback for the absent field).
