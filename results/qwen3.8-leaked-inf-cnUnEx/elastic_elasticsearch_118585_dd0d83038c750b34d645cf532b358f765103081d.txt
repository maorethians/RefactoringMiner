#PF9T2, #T6VHJ, #6BQK2: The `rewriteFieldDocs` method (and by extension `rewriteTopFieldDocs` and `rewriteTopFieldGroups`) mutates the original `FieldDoc` objects in place:
```java
newDocs[pos] = docIdToFieldDoc.get(doc.doc);
newDocs[pos].score = doc.score;
newDocs[pos].fields[0] = doc.score;
```
This means the `FieldDoc` instances that were part of the original `topDocs.scoreDocs` array are modified. If any other component holds a reference to those objects (e.g., a collector that cached them, or a concurrent request sharing the searcher), they will observe the mutated scores. Consider creating new `FieldDoc` instances instead of mutating the originals, or at minimum add a comment explaining why in-place mutation is safe in this context.

#2E3P0: `validateSortFields` does not guard against sort arrays with more than 2 fields. If a user specifies `[score, _shard_doc, some_other_field]`, the method returns `true` because it only checks `fields[0]` and `fields[1]`, silently ignoring any additional sort fields. This could lead to incorrect rescore behavior since the rescore phase assumes the result ordering is determined solely by score (and optionally `_shard_doc` as a tiebreaker). Consider adding:
```java
if (fields.length > 2) {
    return false;
}
```

#PF9T2: In the public constructor, `extractMinWindowSize(rescorers)` is called (via the `super(...)` call) before the `rescorers.isEmpty()` check. If `rescorers` is an empty list, `extractMinWindowSize` returns `Integer.MAX_VALUE`, which is passed as `rankWindowSize` to the parent constructor before the `IllegalArgumentException` is thrown. While this doesn't cause a crash (the exception is thrown immediately after), it's cleaner to validate before calling `super`. Since Java requires `super()` to be the first statement, a practical fix would be to move the empty check into a static factory or to accept that the parent briefly holds an invalid value. At minimum, a brief comment explaining the ordering constraint would help future readers.

#G65N5: The block that populates `FieldDoc#score` from `fields[0]`:
```java
Arrays.stream(topDocs.scoreDocs).forEach(t -> {
    if (t instanceof FieldDoc fieldDoc) {
        fieldDoc.score = (float) fieldDoc.fields[0];
    }
```

This mutates every `FieldDoc` in the query result's top docs. While the net effect is correct, the double mutation makes the data flow harder to reason about. A brief comment or a single unified pass would improve clarity.
