#R6T63: The `case null, default` in the switch is a valid and appropriate way to explicitly handle a null `inputDataType` alongside the default case. This is consistent with the other changes in the chapter.

#DNT6F: Adding `@Nullable` to `inputDataType` correctly documents the contract that this field may be null (e.g., when deserialized from a pre-V_8_14_0 transport version).

#8YEET: The deserialization change is a clean simplification. The old code called `DataType.fromTypeName("unknown")` for pre-V_8_14_0 versions, which relied on "unknown" not being a registered type name to yield `null`. The new code directly assigns `null`, which is clearer and avoids a fragile implicit dependency on the type registry. The wire format is preserved (no string is read for old versions in either case).
