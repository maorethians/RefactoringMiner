#AC2PS, #S4KZ2, #HAS7G: The `createSettings` method applies `commonSettingsConsumer` *after* `settingsConsumer`, meaning common settings can silently override any value set by the specific (baseline/contender) consumer. In the current code there is no overlap, so this is harmless, but if a future subclass sets a value in `baselineSettings`/`contenderSettings` that `commonSettings` also sets, the common value will win — which is the opposite of the more conventional "defaults first, overrides last" pattern. Consider applying `commonSettingsConsumer` first and `settingsConsumer` second, or at minimum adding a brief comment documenting the intended precedence.

#YK1DQ: `prettyPrintList` calls `Object::toString` on every element without a null guard. If any element in the array or list is `null`, this will throw a `NullPointerException` at the exact moment the test is trying to produce a diagnostic message. A small safeguard such as `list.stream().map(e -> String.valueOf(e)).collect(...)` would make the error reporting robust.
