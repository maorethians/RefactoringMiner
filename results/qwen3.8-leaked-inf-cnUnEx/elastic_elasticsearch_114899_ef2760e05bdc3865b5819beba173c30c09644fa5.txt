#FSSQF, #REQ0K: The capability flag and the logic change are consistent with each other. The `computeReferences` fix correctly removes the alias's own attribute from the combined reference set, so that an `Alias` used as a grouping key in `STATS BY` is not treated as a resolvable source reference. The actual field references inside the alias's expression are preserved (they were added via `exp.references()`), which is the desired behavior.
One minor observation on `#REQ0K`: the loop unconditionally removes the alias attribute for **every** `Alias` in `groupings`, not just those wrapping foldable expressions. If the intent (per the capability name `FIX_STATS_BY_FOLDABLE_EXPRESSION`) is to only skip references for foldable aliases, a non-foldable alias's attribute would also be stripped here. In practice this is likely harmless because an alias's own name was never a source-field reference to begin with, but it is worth confirming that no downstream consumer of `computeReferences` relies on the alias attribute being present in the set for non-foldable cases.
