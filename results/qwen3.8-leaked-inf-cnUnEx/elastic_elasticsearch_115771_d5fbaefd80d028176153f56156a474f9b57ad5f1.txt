#C32DQ: The integration test has a type mismatch in `getUpgradedNodesAddresses()`:
```java
.filter(id -> getNodesAttribute(objectPath, id, "version").equals(Build.current().version()))
```
`getNodesAttribute` returns a `String` (the version string from the `_nodes` API response, e.g. `"8.17.0"`), while `Build.current().version()` returns a `Version` object. `String.equals(Object)` checks `instanceof String` first, so this comparison will always be `false`. The `upgradedNodes` list will always be empty, causing `String.join(",", upgradedNodes)` to produce an empty string and `initClient()` to fail.
The fix should be either:
```java
.filter(id -> getNodesAttribute(objectPath, id, "version").equals(Build.current().version().toString()))
```
or:
```java
.filter(id -> Version.fromString(getNodesAttribute(objectPath, id, "version")).equals(Build.current().version()))
```

#GA0HQ: The second query stream is added unconditionally on every cluster state change (unlike the first, which is gated by `featureService.clusterHasFeature(...)`). While the overhead is minimal (just an in-memory stream filter), on a large cluster with many nodes this iterates all nodes on every state change. Consider whether a lightweight guard (e.g., checking if any node is above the version threshold before building the stream) would be worthwhile, or at minimum add a brief comment explaining why no feature gate is needed here (the comment block above does explain the reasoning, which is good).

#WEDEC: The condition:
```java
if (Objects.equals(recordedTv, INFERRED_TRANSPORT_VERSION) || systemIndexMappingsVersion.isEmpty()) {
```
will trigger an update whenever `systemIndexMappingsVersion` is empty, even if the transport version is already correct. This is intentional (to backfill mappings versions), but note that `putCompatibilityVersions` will overwrite the existing (correct) transport version with `e.getValue().transportVersion()` from the response. If the response's transport version differs from what's already recorded (e.g., the node was updated between the query and the state application), this could regress the recorded value. Consider whether the update should preserve the existing transport version when it's already non-inferred:
```java
TransportVersion tvToUse = Objects.equals(recordedTv, INFERRED_TRANSPORT_VERSION)
    ? e.getValue().transportVersion()
    : recordedTv;
builder.putCompatibilityVersions(e.getKey(), tvToUse, e.getValue().systemIndexMappingsVersion());
```
