#9C19E, #2T3QZ: The change to `DEFAULT_INDICES_OPTIONS` from `strictExpandOpen()` to `strictExpandOpenAndForbidClosed()` is a behavioral breaking change for any existing callers that relied on the previous default. Previously, explicitly targeting a closed index would not necessarily throw; now it will. If this is intentional (which the tests suggest), consider whether a deprecation or migration note is warranted in the release notes, since downstream clients using the default options will see new `IndexClosedException`s where they previously did not.
