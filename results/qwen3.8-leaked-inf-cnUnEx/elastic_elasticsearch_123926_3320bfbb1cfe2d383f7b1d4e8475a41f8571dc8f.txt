#0F7BT: This adds a "Test System Data Stream" (feature `"sds-1"`, data stream `".sds-1"`) to `SERVER_SYSTEM_FEATURE_DESCRIPTORS` in the server module. This appears to be test scaffolding that should not be in production code. Every Elasticsearch node would register this system data stream, which is almost certainly unintended. If this is needed for integration tests, it should be registered via a test plugin (similar to how `AbstractFeatureMigrationIntegTest.TestPlugin` registers `SYSTEM_DATA_STREAM_DESCRIPTOR`) rather than in the server's static feature map.

#RG2JX: There is a missing `else` (or early return) after the `delegate.onFailure(...)` call. When `startMigrationResponse.isAcknowledged()` is `false`, the code calls `delegate.onFailure(...)` and then **falls through** to `checkDataStreamMigrationStatus(migrationInfo, delegate)`. This means:
1. The listener is completed with a failure, and then
2. A new async status-check is initiated on the same (already-completed) delegate.
This will cause a double-completion of the listener and an unnecessary (and potentially confusing) status poll for a migration that never started. The `checkDataStreamMigrationStatus` call should be in an `else` branch:
```java
if (startMigrationResponse.isAcknowledged() == false) {
    logger.error("failed to migrate indices from data stream [{}]", dataStreamName);
    delegate.onFailure(new ElasticsearchException(...));
} else {
    checkDataStreamMigrationStatus(migrationInfo, delegate);
}
```

#PDMSZ: The error message `"error occurred while reindexing data stream [" + migrationInfo + "]"` relies on `SystemDataStreamMigrationInfo.toString()`, which is not overridden. The default `Object.toString()` will produce something like `SystemDataStreamMigrationInfo@3f2a1b4c`, making the log message unhelpful for debugging. Use `migrationInfo.getDataStreamName()` (or `migrationInfo.getCurrentResourceName()`) instead.

#NZ03Q: Javadoc typo: `@link Metadata}` should be `{@link Metadata}`. The opening brace is missing, so the Javadoc link will not render.

#SM9MW: The Javadoc for `getThreadPoolNames()` says "for operations on this **system index**", but this interface now covers both system indices and system data streams. The wording should be "system resource" to match the interface's scope.
