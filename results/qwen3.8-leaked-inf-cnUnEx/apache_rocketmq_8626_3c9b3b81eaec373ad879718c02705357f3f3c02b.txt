#EBER0, #E4TJX, #X4JHV: The setter `setUpdateNameServerAddrPeriod` does not validate the input. If a non-positive value (0 or negative) is supplied via configuration, `scheduleAtFixedRate` in `BrokerController#initializeScheduledTasks` will throw an `IllegalArgumentException` at startup, causing the broker to fail. Consider adding a guard:
```java
public void setUpdateNameServerAddrPeriod(int updateNameServerAddrPeriod) {
    if (updateNameServerAddrPeriod <= 0) {
        throw new IllegalArgumentException("updateNameServerAddrPeriod must be positive, got: " + updateNameServerAddrPeriod);
    }
    this.updateNameServerAddrPeriod = updateNameServerAddrPeriod;
}
```

#3BVFB: The configured period is read exactly once when the scheduled task is registered (`this.brokerConfig.getUpdateNameServerAddrPeriod()` is evaluated at scheduling time, not on each tick). This means that if the value is changed at runtime (e.g., via a config-reload mechanism), the already-scheduled task will continue using the original interval until the broker is restarted. If the intent is to support dynamic reconfiguration, the period would need to be read inside the `run()` method and the task rescheduled. If the "configurable" scope is limited to pre-startup configuration only, the current approach is fine, but the Javadoc in `BrokerConfig` could clarify that the value is applied at startup.
