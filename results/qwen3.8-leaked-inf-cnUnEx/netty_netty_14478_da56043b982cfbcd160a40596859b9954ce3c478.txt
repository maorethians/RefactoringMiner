#MG8Q4: The modulo constant is incorrect. `0xFFFFFFFFL` is `2^32 - 1`, but a 32-bit unsigned integer wraps at `2^32`. Using `% 0xFFFFFFFFL` means:
- The valid value `0xFFFFFFFF` (max uint32) is never produced (it maps to `0`).
- The wrap boundary is off by one.
The fix should use either:
```java
return (sequenceNumber + value) & 0xFFFFFFFFL;
```
or equivalently:
```java
return (sequenceNumber + value) % 0x100000000L;
```
The bitwise AND is the more idiomatic way to mask to 32 bits in Java.

#Z9Y5T: The test reuses the same `ByteBuf payload` across all loop iterations without resetting its reader index. After the first `writeInbound(payload)` call, the handler's `writeBytes(payload)` consumes the buffer (advances reader index to writer index). On every subsequent iteration, `packet.readableBytes()` will be `0`, so no meaningful data is written and the sequence numbers barely advance.
The assertion `bytesWritten.get()).isGreaterThan(2 * (fourGB + 1000))` will fail because only ~65 KB is actually written per direction.
Fix: create a fresh buffer each iteration, or reset the reader index:
```java
for (int i = 0; i < ((fourGB / chunkSize) + 2); i++) {
    payload.readerIndex(0);
    embeddedChannel.writeInbound(payload);
}
```
(or use `payload.duplicate()` / `payload.copy()` per iteration).
