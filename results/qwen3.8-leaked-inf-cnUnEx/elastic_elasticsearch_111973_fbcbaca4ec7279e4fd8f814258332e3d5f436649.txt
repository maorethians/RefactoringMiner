#9929M: The two branches handle ordering inconsistently: when `size() > 3`, the values are sorted before taking the first 3, but when `size() <= 3`, the raw `Set` is appended as-is. If the underlying set is a `HashSet` (rather than a `LinkedHashSet`), the `<= 3` path will produce a non-deterministic order in the error message, while the `> 3` path is always alphabetically sorted. Consider sorting in both branches for consistent, deterministic output:
```java
List<String> sorted = e.getValue().stream().sorted().collect(Collectors.toList());
if (sorted.size() <= 3) {
    errorMessage.append(sorted);
} else {
    errorMessage.append(sorted.subList(0, 3));
    errorMessage.append(" and [").append(sorted.size() - 3).append("] other ");
    errorMessage.append(sorted.size() == 4 ? "index" : "indices");
}
```
This also avoids the repeated `e.getValue().size()` calls and the string-concatenation for the bracketed count.

#T9VA8: The test exercises the `> 3` path with 5 indices (verifying the plural "indices"), but the singular branch (`size() == 4` → "index") is not covered. Adding a case with exactly 4 indices for one of the types would guard against a regression in the singular/plural logic.
