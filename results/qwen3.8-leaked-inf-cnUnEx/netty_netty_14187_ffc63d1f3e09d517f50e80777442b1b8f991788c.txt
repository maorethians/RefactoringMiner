#FC7PS: The response line separator appears to be `\n\r\n` (LF CR LF) rather than the standard `\r\n` (CRLF). This is likely a typo — the intended format for an HTTP response should be:
```java
version + " 200 OK\r\nHost: whatever\r\n\r\n"
```
While the test may still pass (since the decoder reads up to the first line terminator and the version validation fails before line-ending semantics matter), using a non-standard line ending in a test can mask issues and makes the test harder to reason about.
