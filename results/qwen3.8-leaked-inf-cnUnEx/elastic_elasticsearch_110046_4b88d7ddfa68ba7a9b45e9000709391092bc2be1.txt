#DVC3F7908NV1: In the `while` loop that builds the error message, the counter `i` is initialized to `0` but **never incremented**. The old `for` loop had `i++` in its update clause. Without it, `i > 0` is always `false`, so the `"; "` separator is never appended. Multiple parsing errors will be concatenated with no delimiter.

#17GR6RZVJZDB, #3GRYQ9PQXBVK: `equals()` and `hashCode()` include `tokenToParam` and `parsingErrors`, both of which are mutated after construction (via `addTokenParam` and `addParsingError`). This means an object's hash code and equality change over its lifetime, which violates the practical contract expected of `hashCode()` (e.g., if the object were ever used as a `HashMap` key, it would become unreachable after mutation). If full-state comparison is truly needed for tests, a dedicated comparison method or comparing only the immutable fields (`params`, `nameToParam`, `paramsCount`) would be safer.
