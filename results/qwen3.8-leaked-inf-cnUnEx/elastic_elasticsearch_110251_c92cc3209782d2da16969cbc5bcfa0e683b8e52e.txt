#TZZGT: The `startsWith` check is too broad and will produce false positives. Consider a mapping with a nested object at path `foo` and a sibling keyword field `foobar`. If the sort field is `foobar`, the check `"foobar".startsWith("foo")` evaluates to `true` and incorrectly rejects a valid configuration. The sort field `foobar` is a sibling of the nested object `foo`, not a child of it.
The fix should anchor on the dot separator:
```java
if (field.equals(nestedObjectMapper.fullPath()) || field.startsWith(nestedObjectMapper.fullPath() + ".")) {
```
This ensures only fields that are actually *under* the nested object (e.g., `foo.bar`) are rejected, while siblings (e.g., `foobar`) are allowed.

#VJM77: The test does not cover the sibling-field case that the `startsWith` bug above would break. Adding a case where the sort field is a sibling of the nested object (e.g., sort field `foobar` with nested object `foo`) would both guard against the regression and document the intended behavior that only sub-fields of a nested object are disallowed.
