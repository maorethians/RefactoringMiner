#FT0CW: The `TermsQueryBuilder.doCoordinatorRewrite` logic is incorrect for OR semantics. A terms query matches if **any** of its values match. The current loop returns `MatchNoneQueryBuilder` as soon as it encounters the first value that doesn't match, even if a subsequent value would match. For example, with `values = ["data_frozen", "data_hot"]` and tier = `"data_hot"`, the first iteration (`"data_frozen"`) produces `MatchNoDocsQuery` and the method immediately returns `MatchNone` — but the correct result is `MatchAll` because `"data_hot"` matches.
The fix should be: iterate all values, and only return `MatchNone` if **none** of them produce `MatchAllDocsQuery`. If **any** produces `MatchAllDocsQuery`, return `MatchAll`.

#H9T2D: The condition `Regex.isMatchAllPattern(defaultField)` (i.e., `defaultField` is `"*"`) makes the rewrite apply when the query_string query targets **all** fields, not just `_tier`. In that case, the original query would match documents based on any field containing the query text, but the rewrite treats it as a pure `_tier` term comparison. If the tier doesn't match the query text, the rewrite returns `MatchNone` and the shard is skipped — but the original query could still have matched documents via other fields. This is a correctness risk. Consider restricting the condition to only `defaultField.equals(DataTierFieldMapper.NAME)` and removing the `isMatchAllPattern` branch.

#82G9Z, #SKR82: Both `PrefixQueryBuilder.doCoordinatorRewrite` and `WildcardQueryBuilder.doCoordinatorRewrite` hardcode `true` for the `caseInsensitive` parameter when calling `prefixQuery`/`wildcardQuery`. Each of these builders has its own `caseInsensitive` field that the user can set. For consistency with `TermQueryBuilder` (which passes its own `caseInsensitive` via the helper) and to respect the user's intent, these should use `this.caseInsensitive` instead of the literal `true`.

#382T1: Typo in the Javadoc: `DataTierFiledMapper.NAME` should be `DataTierFieldMapper.NAME` (missing the second `l` in "Field").

#P45EV: `indexMetadata.getTierPreference()` is called twice (once for `.isEmpty()`, once for `.getFirst()`). While functionally safe here, storing the result in a local variable is cleaner and avoids the redundant call:

List<String> tierPreference = indexMetadata.getTierPreference();
String tier = tierPreference.isEmpty() == false ? tierPreference.getFirst() : "";
