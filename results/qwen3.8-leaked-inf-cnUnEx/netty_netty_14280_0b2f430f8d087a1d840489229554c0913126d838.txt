#X2HEF, #CGVK8, #6P7W7: The refactoring moves `validateToken` from `HttpHeaderValidationUtil` to `HttpUtil`, which is a reasonable consolidation. However, the change to `HttpMethod`'s constructor (#CGVK8) introduces a **behavioral breaking change** that goes beyond a simple relocation:
- **Old behavior:** Only rejected ISO control characters and whitespace (`Character.isISOControl(c) || Character.isWhitespace(c)`).
- **New behavior:** Rejects any character not in the tchar set, which additionally rejects `(`, `)`, `,`, `/`, `:`, `;`, `<`, `=`, `>`, `?`, `@`, `"`, `[`, `\`, `]`, `{`, `}`, and all non-ASCII characters.
While the new validation is more spec-compliant (RFC 7230 §2.7), this will break any existing code that constructs `HttpMethod` instances with characters like `/` or `:` (e.g., custom or vendor-specific method names). If this is intentional, it should be called out in the release notes as a breaking change. If it is not intended to be breaking, the old validation logic should be preserved for `HttpMethod` and the stricter token validation applied only to header names.
Additionally, the exception message format changed from `"invalid character in name"` to `"Illegal character in HTTP Method: 0x..."`. Any downstream code that parses or matches on the message string will break.

#3JTM2: Minor: the local variables are named `mehtodNameAscii` and `mehtodName` — "mehtod" is a transposition typo for "method". Consider renaming to `methodNameAscii` / `methodName` for clarity.

#6P7W7: `validateToken` is now `public` on `HttpUtil`, making it part of the public API surface of a broadly-used utility class. Previously it lived in the more narrowly-scoped `HttpHeaderValidationUtil`. If the intent is to keep this as an internal implementation detail (with `validateAsciiStringToken` and `validateCharSequenceToken` already being `private`), consider whether `validateToken` should also be `package-private` or `protected` rather than `public`, to avoid committing to it as a stable public API. If it is meant to be public, that's fine, but it's worth a conscious decision.
