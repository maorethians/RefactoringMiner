#S1DAF, #CECJZ: In both `doBulk` and `matchAllSearch`, the entity is consumed in the outer `finally` block via `EntityUtils.consumeQuietly(response.getEntity())`. However, `entityAsMap(Response)` almost certainly delegates to `entityAsMap(HttpEntity)` (shown in #QQYA4), which already consumes the entity in its own `finally`. This means the entity is consumed twice. While `EntityUtils.consumeQuietly` is idempotent (a no-op on an already-consumed entity), the outer `finally` blocks are redundant and add noise. If the intent is to guard against `assertOK` throwing *before* `entityAsMap` is reached, a simpler pattern would be:
```java
Response bulkResponse = adminClient().performRequest(bulkRequest);
try {
    assertOK(bulkResponse);
    var bulkMap = entityAsMap(bulkResponse);
    assertThat((boolean) bulkMap.get("errors"), is(equalTo(false)));
} finally {
    EntityUtils.consumeQuietly(bulkResponse.getEntity());
}
```
…only if `entityAsMap(Response)` does *not* already consume. If it does (by delegating to the `HttpEntity` overload), the `finally` can be dropped entirely and the code simplifies to:
```java
Response bulkResponse = adminClient().performRequest(bulkRequest);
assertOK(bulkResponse);
var bulkMap = entityAsMap(bulkResponse);
assertThat((boolean) bulkMap.get("errors"), is(equalTo(false)));
```
Worth confirming which overload is actually invoked and removing the redundant consumption to avoid confusion for future readers.
