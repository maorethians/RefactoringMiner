#FPRGN: The `updateTopicList` method appends the separator after *every* topic, producing a trailing separator (e.g. `"topic1;topic2;"`). While `StringUtils.split` in `fetchTopicList` happens to tolerate this by ignoring trailing empty tokens, it is fragile and makes the wire format slightly harder to reason about. Consider using `String.join(TOPIC_NAME_SEPARATOR, topicList)` instead, which produces a clean `"topic1;topic2"` without the trailing delimiter.

#K3TZ6, #W1J8K: The refactoring changes the order of validation checks. In the original code, the topic-config existence check ran *before* the subscription check inside the per-topic loop. After the refactor, the subscription check is performed up-front in `getTopicsForCollecting`, so a topic that has neither a config nor a subscription will now produce the "topic does not exist in consumer group's subscription" warning instead of the "topic config does not exist" warning. This is a subtle behavioral change in log output and in which topics get filtered out when both conditions are true. If this is intentional, a brief note in the commit message or a code comment would help future readers understand the deliberate reordering.

#W1J8K: The local variable `group` is extracted at the top of the method and passed to `getTopicsForCollecting`, but the remainder of the loop body still calls `requestHeader.getConsumerGroup()` repeatedly (for `queryOffset`, `queryPullOffset`, `tpsGroupGetNums`). Using the already-extracted `group` variable consistently would improve readability and avoid repeated getter calls on the header object.
