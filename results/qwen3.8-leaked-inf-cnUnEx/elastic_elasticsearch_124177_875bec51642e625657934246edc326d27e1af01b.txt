#QJ0QW, #1PP4T, #2FTYC: The `BEFORE_REGEX` uses `([\\s,]*)` (zero-or-more), which means the group can match an empty string. Combined with the lack of a word-boundary anchor, the pattern `([\\s,]*)LP([\\s,]|$)` could match `LP` as a substring of a longer identifier. For example, if an error message ever contained `SOME_LP `, the before-group would match empty, `LP` would match, and the after-group would match the trailing space — producing `SOME'(' ` instead of leaving the original text intact.
Adding `\b` word boundaries around the token name would make the patterns robust against this:
```java
private final Pattern REPLACE_LP = Pattern.compile("\\b" + BEFORE_REGEX + "LP" + AFTER_REGEX + "\\b");
```
(Or equivalently, place `\b` immediately before and after the literal token name.) The risk is low in practice since ANTLR error messages use token names as standalone words, but the fix is cheap and eliminates the edge case.
