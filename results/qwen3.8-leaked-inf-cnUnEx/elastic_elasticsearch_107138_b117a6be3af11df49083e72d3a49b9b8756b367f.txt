#TY96E: The initial validation assertion is inconsistent with how `onSnapshotBuild` is set. The request is parsed with `parseEsqlQueryRequest(json, randomBoolean())`, so `request.onSnapshotBuild` is a random value. However, the assertion branches on `Build.current().isSnapshot()`, which is independent of the request's `onSnapshotBuild` field.
Looking at the `validate()` logic, the SNAPSHOT version is rejected when `onSnapshotBuild == false` (the request's field), not when the build itself is non-snapshot. This means:
- If `randomBoolean()` returns `false` but `Build.current().isSnapshot()` is `true`, the test expects `assertNull(request.validate())` but validation will actually fail.
- If `randomBoolean()` returns `true` but `Build.current().isSnapshot()` is `false`, the test expects a validation error but validation will actually pass.
This makes the test flaky. The fix should either use a deterministic value for the initial parse (e.g., `parseEsqlQueryRequest(json, false)` and assert the error, or `parseEsqlQueryRequest(json, true)` and assert success), or capture the random value and branch on it:
```java
boolean onSnapshot = randomBoolean();
EsqlQueryRequest request = parseEsqlQueryRequest(json, onSnapshot);
if (onSnapshot) {
    assertNull(request.validate());
} else {
    assertNotNull(request.validate());
    assertThat(request.validate().getMessage(), containsString(errorOnNonSnapshotBuilds));
}
```
