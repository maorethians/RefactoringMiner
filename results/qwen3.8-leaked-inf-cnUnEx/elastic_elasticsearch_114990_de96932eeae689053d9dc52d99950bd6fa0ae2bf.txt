#3JV0C: In the `matches` override, when `caseInsensitive` is `true`, only the `pattern` is lowercased before calling `Regex.simpleMatch`, but the `tierPreference` value is not. Since `Regex.simpleMatch` is case-sensitive, a case-insensitive match would fail if the tier preference contained any uppercase characters. For example, pattern `"DATA_FROZEN"` becomes `"data_frozen"`, but if the tier value were `"Data_Frozen"`, the match would incorrectly return `false`.
While Elasticsearch tier names are conventionally all-lowercase (`data_hot`, `data_frozen`, etc.), making this a low-risk issue in practice, the fix is straightforward and would make the method robust:
```java
if (caseInsensitive) {
    pattern = Strings.toLowercaseAscii(pattern);
    tierPreference = Strings.toLowercaseAscii(tierPreference);
}
```
