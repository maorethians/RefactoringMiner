#DSCMQ, #2KTMQ: Broadening the caught exception from `ResourceAlreadyExistsException` to `ElasticsearchException` weakens the test's assertion. The test is named `testDuplicateDownsampleRequest`, which implies it should verify that a *specific* "resource already exists" error is raised for duplicate requests. By catching the parent `ElasticsearchException`, the test would also pass if an unrelated `ElasticsearchException` (e.g., a permission error, a different conflict type, or a generic internal error) were thrown, making it harder to detect regressions in the error-path logic.
If the implementation now throws a different concrete exception, consider catching that specific type instead. If the broader catch is intentional (e.g., the exception type may vary), add an assertion on `e.type()` or the error message to still verify the expected error semantics.
