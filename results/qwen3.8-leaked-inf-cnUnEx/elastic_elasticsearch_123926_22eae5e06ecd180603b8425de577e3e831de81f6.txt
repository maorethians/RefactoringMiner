#SM9MW, #2S5ZN, #CHB01: The `SystemResourceDescriptor.getOrigin()` method and the `SystemDataStreamDescriptor.origin` field can be `null` (several test call-sites pass `null`, e.g. `#ZXCTG`), yet neither the interface method nor the field carries a `@Nullable` annotation. The `SystemIndexDescriptor.getOrigin()` Javadoc also doesn't mention nullability. Since `createClient()` in `SystemResourceMigrationInfo` passes the result directly to `new OriginSettingClient(baseClient, this.getOrigin())`, a null origin could cause a subtle NPE downstream. Consider adding `@Nullable` to the interface method and documenting that the origin is optional.

#A6PV2: The `nodeSettings` override in `DataStreamMigrationIT` is a no-op:
```java
@Override
protected Settings nodeSettings(int nodeOrdinal, Settings otherSettings) {
    return Settings.builder().put(super.nodeSettings(nodeOrdinal, otherSettings)).build();
}
```
It creates a new `Settings` object with identical content. If no additional settings are needed, this override can be removed entirely. If it's a placeholder for future settings, a brief comment explaining the intent would help.

#3ETWE: The condition on this line relies on `&&` binding tighter than `||`:
```java
if (errors != null && errors.isEmpty() == false || status.exception() != null) {
```
While the precedence is correct as written, adding explicit parentheses would make the intent immediately clear and prevent a future edit from accidentally changing the logic:
```java
if ((errors != null && errors.isEmpty() == false) || status.exception() != null) {
```
