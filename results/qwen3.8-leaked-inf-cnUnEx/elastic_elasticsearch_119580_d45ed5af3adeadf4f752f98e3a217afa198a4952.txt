#3ZC6V, #4SHDZ, #X771N: In the backward-compatibility branch, a temporary `EsIndex` is allocated on every write to an older peer:
```java
new EsIndex(indexName, Map.of(), indexNameWithModes).writeTo(out);
```
This is functionally correct, but it creates a short-lived object per serialization call. Given that `EsIndex.writeTo` simply writes `name`, `mapping`, and `indexNameWithModes` in sequence, an alternative would be to inline the three writes directly (writeString, writeMap with empty map, writeIndexNameWithModes) to avoid the allocation. This is a minor performance nit rather than a correctness issue, and the current approach is perfectly readable, so it's a judgment call.
