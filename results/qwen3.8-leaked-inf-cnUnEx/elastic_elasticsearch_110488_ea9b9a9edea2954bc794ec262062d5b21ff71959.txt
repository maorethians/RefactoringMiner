#BANQQ: Changing the ambiguity handling from returning a soft error (an `UnresolvedAttribute` with a message) to throwing `IllegalStateException` is a significant contract change for `maybeResolveAgainstList`. All callers of this utility previously received a list they could inspect; now they must handle an exception. If there is any remaining code path where a user-supplied query could still produce an ambiguous reference (e.g., a query that bypasses the new ROW deduplication in `#P3ZDT`), this will surface as an unhandled 500 rather than a clean ESQL error. Please confirm that every caller is updated and that no user-reachable path can still trigger this after the `UNIQUE_NAMES` fix is in place.

#MYTMH: The duplicate-detection loop uses short-circuit `||`:
```java
if (outputAttributeNames.add(outputAttr.name()) == false || outputAttributeIds.add(outputAttr.id()) == false)
```
When a name duplicate is found, `outputAttributeIds.add(...)` is skipped, so that id is never recorded. A subsequent attribute with the *same id* but a *different name* would then pass both checks and go unreported. In practice this is unlikely (ids are usually derived from names), but if you want the validation to be exhaustive, consider tracking both sets unconditionally before evaluating the condition.

#EQ9T3: `unionFieldAttributes` is now an instance field on `ResolveUnionTypes`, making the rule stateful. The `apply` method resets it at the top, which is correct for sequential re-application, but if the same rule instance is ever shared across concurrent analysis threads (e.g., a shared rule list in a thread-pool context), this would be a data race. If the analyzer framework guarantees single-threaded use per plan, this is fine, but a brief comment noting that assumption would help future maintainers.

#P3ZDT: The unchecked cast `(List<Alias>) (List) mergeOutputExpressions(...)` is necessary given the generic signature of `mergeOutputExpressions`, but it silently discards type safety. A small helper or a `@SuppressWarnings`-annotated local method would make the intent clearer and keep the cast in one well-documented place rather than inline in the visitor.
