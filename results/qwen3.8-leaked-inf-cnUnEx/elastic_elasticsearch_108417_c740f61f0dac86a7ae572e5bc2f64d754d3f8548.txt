#YYPGY, #J2CZB, #9H8GF: The `XContentBuilder` is closed twice: once inside `cloneDocumentParserContext` (via `BytesReference.bytes(builder)`) and again by the caller (`encodeXContentBuilder` in `#9H8GF`, or the explicit `BytesReference.bytes(tuple.v2())` in `#YYPGY`). `BytesReference.bytes` calls `xContentBuilder.close()` before reading the stream. Although `ByteArrayOutputStream.close()` is a no-op, this is fragile and incorrect — if the builder ever wraps a `BytesStream`, the second close/read will fail.
Suggested fix: extract the `BytesReference` once before calling `cloneDocumentParserContext`, and pass the `BytesReference` (not the builder) into `cloneDocumentParserContext`. For example:
```java
static Tuple<DocumentParserContext, XContentBuilder> cloneSubContext(DocumentParserContext context) throws IOException {
    var tuple = cloneSubContextParserConfiguration(context);
    BytesReference bytes = BytesReference.bytes(tuple.v2()); // close once
    DocumentParserContext sub = context.switchParser(
        XContentHelper.createParserNotCompressed(tuple.v1(), bytes, context.parser().contentType())
    );
    sub.setSourceTracked(true);
    sub.parser().nextToken();
    return Tuple.tuple(sub, tuple.v2());
}
```
And refactor `cloneDocumentParserContext` to accept a `BytesReference` instead of an `XContentBuilder`.

This is a naming inconsistency that will confuse readers — the field should be renamed to `storeArraySource` to match the new convention. #5B9RM: The array-filtering logic builds a `Set<String> arrays` from `NameValue::name` and checks `arrays.contains(field.fieldName())`. However, the `NameValue.name` is set to a **full path** (e.g., `"path.to"`) for non-root cases (see `#9H8GF`: `context.parent().name() + "." + arrayFieldName`), while `field.fieldName()` likely returns the **simple** field name (e.g., `"to"`). If that's the case, the `contains` check will never match, the field will be written both as a regular field *and* as part of the ignored value, producing duplicate data in the synthetic source.
Please verify that `field.fieldName()` returns the same fully-qualified name that is stored in `NameValue.name`. If it returns only the simple name, the comparison should use `ignored.getFieldName()` (the simple name) instead of `ignored.name`.
