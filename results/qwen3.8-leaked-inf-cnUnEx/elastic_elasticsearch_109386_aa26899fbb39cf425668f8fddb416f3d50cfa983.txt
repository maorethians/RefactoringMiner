#KSTPN, #8N9WN: `2L ^ 50` is a bitwise XOR (yielding `48`), not exponentiation. The comment says "2L^50 fits in the mantissa of a double" but the code computes `2 XOR 50 = 48`. The intended expression is `2L << 50` (bit shift). As written, both `DoubleBucketedSortTests` and `LongBucketedSortTests` generate random values in the range `[-48, 48]` instead of `[-2^50, 2^50]`, completely defeating the purpose of testing precision at the boundary of double's mantissa.
Fix:
```java
return randomLongBetween(-(2L << 50), 2L << 50);
```

#KSTPN: The `collect` override casts the double to a long before passing it to `DoubleBucketedSort.collect(double, long)`:
```java
sort.collect((long) value, bucket);
```
This truncates the fractional part, meaning the double sort is only ever tested with integer values. The cast should be removed so the full double value is passed through:
```java
sort.collect(value, bucket);
```
Without this fix, the `DoubleBucketedSort` is never exercised with non-integer doubles, leaving its `betterThan` (which uses `Double.compare`) and heap ordering untested for fractional values.

#YTMFM: `Collections.shuffle(Arrays.asList(values), random())` is a no-op when `values` is a primitive array (`double[]` or `int[]`). `Arrays.asList(T...)` with a `double[]` argument creates a `List<double[]>` containing a single element (the array itself), so `shuffle` has nothing to reorder. The same issue exists in `testManyBuckets` with `int[] buckets`.
The values are never actually shuffled, so these tests don't exercise random insertion order. Consider using a boxed array or a manual Fisher-Yates shuffle:
```java
Double[] boxed = Arrays.stream(values).boxed().toArray(Double[]::new);
Collections.shuffle(Arrays.asList(boxed), random());
// then copy back or use boxed directly
```
