#MNFNV, #XWATH, #5TYM6, #EAPZF, #YB3B1, #ST4EC, #H08EF, #5WPT5, #EPYGM: Several test sites construct `NestedObjectMapper.Builder` with `null` for the new `indexSettings` parameter. While none of these specific tests currently invoke `syntheticFieldLoader()` (which would NPE on `indexSettings.getSkipIgnoredSourceRead()` in `SourceLoader.Synthetic`), this is a latent fragility. If any of these helpers are later reused in a test that exercises synthetic source reconstruction, the null will cause a `NullPointerException`. Consider either:
- Annotating the `indexSettings` parameter as `@Nullable` in `NestedObjectMapper.Builder` and adding a null-guard in `SourceLoader.Synthetic` (e.g., treat null as "read enabled" to preserve prior behavior), or
- Providing a minimal `IndexSettings` instance in these test helpers (as done in `#WDBMK` and `#ZBWAY`) to make the contract explicit.

#N6P60: The `requiredStoredFields` set is computed once at `SourceLoader.Synthetic` construction time based on the current value of `skipIgnoredSourceRead`. Since this is a dynamic setting, a loader created before the setting is flipped will retain the old behavior until it is recreated. This is consistent with how other dynamic settings interact with per-request objects in this codebase (e.g., `SearchExecutionContext` is rebuilt per search), so it is acceptable. Just noting it for awareness: the setting takes effect on the next request/search context creation, not retroactively on in-flight ones.
