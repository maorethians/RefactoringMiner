#9415T: The two unchecked casts `(Attribute) expr` and `(Attribute) aliases.resolve(attr, attr)` will throw `ClassCastException` at runtime if the invariant "groupings must be attributes at this point" is ever violated. The comment documents the assumption, which is reasonable for an internal optimizer rule. However, `Alias.unwrap(ne)` returns `Expression`, not `Attribute`—if a lower projection's alias child were ever a non-attribute expression (e.g., a function call), the second cast would fail. Consider either:
- Adding an `instanceof Attribute` guard with a clear error message, or
- Narrowing the `AttributeMap` value type to `Attribute` (i.e., `AttributeMap<Attribute>`) so the compiler enforces the contract at the `put` site rather than at the `resolve` site.
This is a minor robustness point; the current code is correct under the existing optimizer invariants.
