#K0P17: Missing `return` after the early-exit `doPayload(listener)` call. After `doPayload` invokes `listener.onResponse(...)`, execution falls through to the rest of `tumbleWindow`, which will call `checkMissingEvents` and eventually invoke the listener a second time (either via another `doPayload` or via `advance`). `ActionListener` must be completed exactly once. Add `return;` immediately after `doPayload(listener);`:
```java
if (allowPartialSequenceResults == false && shardFailures.isEmpty() == false) {
    doPayload(listener);
    return;  // <-- missing
}
```

#0QC7B: The request body fields are written as JSON strings instead of JSON booleans. `builder.field("allow_partial_search_results", String.valueOf(allowPartialSearchResults))` calls the `field(String, String)` overload, producing `"allow_partial_search_results": "true"` (a string). The server-side parser uses `declareBoolean` → `XContentParser::booleanValue`, which expects a JSON boolean. This will cause a parse error at runtime. Use the `Boolean` overload instead:
```java
builder.field("allow_partial_search_results", allowPartialSearchResults);
builder.field("allow_partial_sequence_results", allowPartialSequenceResults);
```
The same applies to the `else if (randomBoolean())` branch where `builder.field("allow_partial_search_results", randomBoolean())` is correct (uses the `boolean` overload), but the `String.valueOf(...)` calls in the `if` branch are not.

#ERQ1H, #VZWBY: Inconsistent setting key naming. The search-results setting is `xpack.eql.default_allow_partial_results` (missing the word "search"), while the sequence-results setting is `xpack.eql.default_allow_partial_sequence_results`. The request-level parameters are `allow_partial_search_results` and `allow_partial_sequence_results`. The cluster setting for search results should be `xpack.eql.default_allow_partial_search_results` for symmetry and to avoid confusion about scope.

#4MY7X: The first line `payload.shardFailures();` is a redundant call whose return value is discarded. It appears to be a leftover. Remove it:
```java
public static Results fromPayload(Payload payload) {
    List<?> values = payload.values();
    return new Results(

        payload.timeTook(),

```

#5AQ6E, #CZ9YB: The `addShardFailures(SearchResponse)` method is duplicated verbatim in both `TumblingWindow` and `SampleIterator`, including the same `// TODO find a better way to deduplicate` comment. Consider extracting this into a shared utility (e.g., in `RuntimeUtils` or a small helper) to avoid divergence. Additionally, using `shardFailure.toString()` as the deduplication key is fragile — `toString()` includes the full stack trace of the cause, so two logically identical failures on different shards would produce different keys, defeating the deduplication.

#ZGBG3: The `declareObjectArray` parser for `shard_failures` uses `(p, c) -> ShardSearchFailure.EMPTY_ARRAY` as the element parser. This causes `T` to be inferred as `ShardSearchFailure[]`, so the consumer receives a `List<ShardSearchFailure[]>`. However, the `EqlSearchResponse` constructor expects `ShardSearchFailure[]` for that parameter. This type mismatch will likely cause a runtime error when the `InstantiatingObjectParser` attempts to invoke the constructor. Since `ShardSearchFailure` has no standard XContent deserializer, consider either (a) adding a proper `fromXContent`-style parser, or (b) declaring the field with a parser that produces the correct type, or (c) handling `shard_failures` outside the `InstantiatingObjectParser` if it is only needed for serialization.

#GCMP1: The new nullable fields `allowPartialSearchResults` and `allowPartialSequenceResults` are always serialized (writing `null` when unset), while other nullable fields in the same method (e.g., `tiebreakerField`, `waitForCompletionTimeout`, `keepAlive`) are conditionally written only when non-null. For consistency with the surrounding style, consider guarding with a null check:
```java
if (allowPartialSearchResults != null) {
    builder.field(KEY_ALLOW_PARTIAL_SEARCH_RESULTS, allowPartialSearchResults);
}
if (allowPartialSequenceResults != null) {
    builder.field(KEY_ALLOW_PARTIAL_SEQUENCE_RESULTS, allowPartialSequenceResults);
}
```
