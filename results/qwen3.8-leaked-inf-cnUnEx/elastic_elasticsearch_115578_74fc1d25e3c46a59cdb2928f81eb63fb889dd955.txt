#HCRM8: The completion condition `if (valueAssertions.isEmpty())` does not account for the newly introduced `histogramAssertions` map. If all value assertions are satisfied but histogram assertions are still pending (or vice versa), the latch will count down prematurely and the test may pass without all assertions being verified. The condition should be:
```java
if (valueAssertions.isEmpty() && histogramAssertions.isEmpty()) {
    finished.countDown();
}
```

#HCRM8: In the histogram assertion logic, if a single APM message carries more counts than the expected total (e.g., expected = 2 but the message contains 3 counts), `remaining` becomes negative. The code then enters the `else` branch, logs "PENDING" with a negative value, and stores the negative number back into the map. The assertion will never reach `remaining == 0` and the test will time out. Consider using `remaining <= 0` as the success condition, or at minimum logging a distinct error for the over-count case.

#HCRM8: `Collectors.joining()` is called without a separator argument, so the remaining assertion keys in the timeout message will be concatenated with no delimiter (e.g., `"es.test.double_histogram.histogrames.test.long_histogram.histogram"`). Use `Collectors.joining(", ")` for readability.
