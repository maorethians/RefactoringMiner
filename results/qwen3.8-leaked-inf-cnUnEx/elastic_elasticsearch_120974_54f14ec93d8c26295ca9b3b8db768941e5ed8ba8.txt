#BCR52, #EAW4C: The old code in `postParse` iterated over `context.getCopyToFields()`, which is a `Set<String>`, guaranteeing each target field was voided exactly once. In the new code, `createCopyToContext` is invoked once per source field that declares a `copy_to` to a target. If multiple source fields copy_to the same target (e.g., both `a` and `b` have `copy_to: ["c"]`), a `voidValue()` entry for `"c"` will be added to `ignoredFieldValues` twice. The practical impact is minimal (the encoded value is identical and idempotent), but it does produce redundant `StoredField` entries in the Lucene document and diverges from the previous deduplicated behavior. Consider either deduplicating (e.g., tracking already-voided fields in the context) or documenting that duplicates are intentionally tolerated.
