#6TZMA, #G5AFD: The two `writeJSONFile` static methods introduced/modified in this PR have inconsistent parameter ordering for the last two arguments:
- `FileSettingsServiceIT.writeJSONFile(String node, String json, AtomicLong versionCounter, Logger logger)` (#6TZMA)
- `RoleMappingFileSettingsIT.writeJSONFile(String node, String json, Logger logger, AtomicLong versionCounter)` (dependency shown for #G5AFD)
Both methods perform the same logical operation (write a formatted JSON settings file to a node's watched path). Having the same method name with swapped parameter types (`AtomicLong` vs `Logger`) in two closely-related test classes is a source of subtle call-site bugs. I'd recommend aligning the parameter order across both methods (e.g., always `..., Logger logger, AtomicLong versionCounter` or vice versa) to reduce the risk of accidentally passing them in the wrong order.
