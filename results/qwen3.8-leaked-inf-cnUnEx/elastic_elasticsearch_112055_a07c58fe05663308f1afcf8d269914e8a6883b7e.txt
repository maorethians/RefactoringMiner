#T7GHK: The `ascending` method for doubles computes the median of two middle values as `(values.getDouble(middle - 1) + values.getDouble(middle)) / 2`, which can overflow to `Infinity` when both values are near `Double.MAX_VALUE` (e.g., `[Double.MAX_VALUE, Double.MAX_VALUE]` yields `Infinity` instead of `Double.MAX_VALUE`). This is inconsistent with `doubleMedianOf`, which correctly uses the overflow-safe form `values[middle - 1] / 2 + values[middle] / 2`. The `ascending` method should use the same overflow-safe formula:
```java
double median = count % 2 == 1
    ? values.getDouble(middle)
    : values.getDouble(middle - 1) / 2 + values.getDouble(middle) / 2;
```

#6ENPC: In the `overflowCasesFor` calls for `DataType.UNSIGNED_LONG`, the expected results (`maxMinMad`, `maxZeroMad`, `minZeroMad`) are `BigInteger` values, while the evaluator produces `long` results in unsigned encoding. Compare this with `makeCases`, which explicitly converts the expected result via `DataTypeConverter.convert(expectedResult, type)` and then `NumericUtils.asLongUnsigned(bi)`. The `overflowCasesFor` method does not perform this conversion, so the `equalTo(maxMinMad)` matcher will compare a `long` against a `BigInteger` using `equals()`, which will always be `false`.
