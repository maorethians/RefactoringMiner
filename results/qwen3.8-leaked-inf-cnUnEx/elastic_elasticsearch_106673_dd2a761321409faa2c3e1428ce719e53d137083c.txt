#SMZWG, #WC83G: The `SINGLE_NULL_VALUE` static field is shared across all calls to `emptyRow`, and each call invokes `block.incRef()`. This is fine for the happy path where the execution engine eventually calls `decRef()`, but if a plan containing this `LocalRelation` is discarded without execution (e.g., during optimization testing, plan comparison, or error paths), the reference count on the static block will leak. Consider whether the plan lifecycle guarantees a `decRef()` in all cases, or whether a defensive `try/finally` or a plan-disposal hook is needed.

#JYE1N: The cast `(NamedExpression) aggregate.groupings().get(0)` is an unchecked downcast from `Expression` to `NamedExpression`. The `Aggregate.groupings()` method returns `List<Expression>`, so the type system does not guarantee that the first element is a `NamedExpression`. While in practice groupings are typically `Attribute` instances (which extend `NamedExpression`), a malformed or future plan node could hold a plain `Expression` here, causing a `ClassCastException` at runtime. Consider either:
- Adding an `instanceof` check with a fallback (e.g., wrapping in an `Alias` or throwing a descriptive `IllegalStateException`), or
- Changing the `Aggregate` API to expose groupings as `List<? extends NamedExpression>` if that invariant is truly guaranteed.

#KMHG9, #7ZADC: The tests cover both branches of the new logic (no groupings → `emptyRow`, groupings present → retained grouping as aggregate). One gap: there is no test for the case where `remaining` is non-empty but the aggregate still has groupings (the `else` branch at the outer level). This path is unchanged from before, so it may already be covered elsewhere, but a quick assertion that the grouping is preserved alongside surviving aggregates would make the test suite more robust against regressions in this method.
