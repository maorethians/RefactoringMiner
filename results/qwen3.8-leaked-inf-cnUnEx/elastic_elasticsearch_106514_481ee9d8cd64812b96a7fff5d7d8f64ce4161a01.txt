#32PGD: In `AliasActionResult.build`, a `REMOVE` action with `numAliasesRemoved == 0` unconditionally produces an `AliasesNotFoundException` (404), without consulting `action.mustExist()`. When a caller explicitly sets `mustExist: false` (or omits it), the documented contract is that a missing alias is a no-op. Yet the response will still carry `errors: true` and a per-action `status: 404`, which contradicts the caller's intent and is a behavioral regression from the previous "silent success" path.
Consider gating the error on the flag, e.g.:
```java
if (action.actionType() == AliasActions.Type.REMOVE
        && numAliasesRemoved == 0
        && (action.mustExist() == null || action.mustExist())) {
    return buildRemoveError(indices, action);
}
```
or, if the intent is to *always* surface "alias not found" as informational, the `errors` boolean and the 404 status should be decoupled so that a `mustExist: false` miss doesn't flip the top-level `errors` flag to `true`.
