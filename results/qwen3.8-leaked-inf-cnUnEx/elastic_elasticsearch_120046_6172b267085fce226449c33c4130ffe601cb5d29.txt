#N6WG7, #PH9TX, #TFKJN, #AHZBB, #H74X9, #T4V33, #C231A, #FM5T8: Making `ProxyRequest`, `ProxyRequestHandler`, and `CancellableProxyRequest` (and their constructors) public significantly expands the public API surface of `TransportActionProxy`. These are internal implementation details of the proxy mechanism. A cleaner approach would be to add a dedicated factory/registration method on `TransportActionProxy` (e.g., `registerBwCProxyAction(...)`) that encapsulates the construction of `ProxyRequest` and `ProxyRequestHandler` internally, keeping these classes private. This would:
- Preserve encapsulation of the proxy mechanism's internals.
- Make the BwC translation pattern reusable without leaking implementation types into callers.
- Avoid forcing all future callers to know the internal class hierarchy and constructor signatures.
Additionally, `CancellableProxyRequest` is not referenced anywhere in this chapter's new code (#ATN7A uses `ProxyRequest` directly). Making it public appears to be an unnecessary API surface increase for this change.
