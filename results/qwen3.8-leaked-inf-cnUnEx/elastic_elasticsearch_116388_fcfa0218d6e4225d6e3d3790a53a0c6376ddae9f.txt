#GCMP1: `toXContent` always writes both new fields (even when null, producing `"field": null` in JSON). Other optional fields in the same method (e.g., `tiebreakerField`, `waitForCompletionTimeout`) are conditionally written. Minor inconsistency, but likely intentional for round-trip fidelity.

#MAWDJ: The `shard_failures` deserialization is a no-op placeholder (always returns `EMPTY_ARRAY`). The TODO acknowledges this, but it means any client deserializing the response from JSON will silently lose shard failure information.

#K0P17: The early-exit guard calls `doPayload(listener)` (which invokes `listener.onResponse(...)`) but does **not** return. Execution falls through to the rest of `tumbleWindow`, which eventually calls `checkMissingEvents(() -> advance(c, listener), listener)` — using the same listener a second time. This will cause a double-response (or an `IllegalStateException` from the `ActionListener` implementation) whenever `allowPartialSequenceResults == false` and shard failures are present.
```java
if (allowPartialSequenceResults == false && shardFailures.isEmpty() == false) {
    doPayload(listener);
    return;  // <-- missing
}
```

#4MY7X: The first `payload.shardFailures()` call on its own line has its return value discarded and is immediately followed by a second call to the same method inside the `Results` constructor. This is a leftover from refactoring and should be removed.
