#S3R31: **Critical bug: Missing `return` after the sorted-ascending path causes double-append.**
In `processDoubles`, `processInts`, and `processLongs`, when `valuesBlock.mvSortedAscending()` is true, the code appends a result value inside the `if` block but then **falls through** to the unsorted path below, which appends a *second* value for the same position. The builder will contain two values where only one is expected, corrupting the output block.
For example in `processDoubles`:
```java
if (valuesBlock.mvSortedAscending()) {
    // ... appends a value ...
}
// No return here! Execution continues:
var values = new double[valueCount];
for (int i = 0; i < valueCount; i++) {
    values[i] = valuesBlock.getDouble(firstValueIndex + i);
}
Arrays.sort(values);
// ... appends ANOTHER value ...
```
A `return;` is needed at the end of the `if (valuesBlock.mvSortedAscending())` block (after the inner if/else-if/else).

#S3R31: **Critical bug: Sorted-ascending path uses relative indices instead of absolute value indices.**
In the sorted-ascending branch, the code calls `valuesBlock.getDouble(0)`, `valuesBlock.getDouble(valueCount - 1)`, `valuesBlock.getDouble(lowerIndex)`, etc. However, `getDouble(int valueIndex)` expects an **absolute** value index. The values for position `p` start at `firstValueIndex`, so the correct calls should be:
- `valuesBlock.getDouble(firstValueIndex)` instead of `valuesBlock.getDouble(0)`
- `valuesBlock.getDouble(firstValueIndex + valueCount - 1)` instead of `valuesBlock.getDouble(valueCount - 1)`
- `valuesBlock.getDouble(firstValueIndex + lowerIndex)` instead of `valuesBlock.getDouble(lowerIndex)`
- `valuesBlock.getDouble(firstValueIndex + upperIndex)` instead of `valuesBlock.getDouble(upperIndex)`
The same issue exists in `processInts` (with `getInt`) and `processLongs` (with `getLong`). When `firstValueIndex != 0` (i.e., position > 0), these will read from the wrong position's data.

#S3R31: **Bug: `foldable()` does not check the `percentile` argument.**
```java
@Override
public boolean foldable() {
    return field.foldable();
}
```
For constant folding to be valid, **all** arguments must be foldable. If `percentile` is a non-foldable expression (e.g., a column reference), the whole expression cannot be folded. This should be:
```java
return field.foldable() && percentile.foldable();
```

#S3R31: **Minor: `@Param(name = "number")` is misleading for the multivalue field parameter.**
```java
@Param(name = "number", type = { "double", "integer", "long" }, description = "Multivalue expression.") Expression field,
```
The parameter name `"number"` suggests a scalar numeric value, but this is actually a multivalue field. The internal evaluator naming uses `"values"` for this parameter (e.g., `MvPercentileDoubleDoubleEvaluator[values=..., percentile=...]`). Consider renaming to `"values"` or `"field"` for consistency and clarity.
