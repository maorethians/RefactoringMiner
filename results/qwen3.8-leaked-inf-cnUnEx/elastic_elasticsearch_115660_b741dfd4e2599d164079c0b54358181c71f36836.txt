#X4XRB: The new regex `\b1:(\d+)\b` is significantly looser than the previous `"Line (\\d+):(\\d+):"` pattern. While it correctly handles the intended "Line 1:22:" → "Line 1:22+offset:" transformation, it will also match any `1:<digits>` sequence appearing anywhere in the warning message body. For example, a hypothetical warning like `"Line 1:5: column [a] has ratio 1:2"` would have its `"1:2"` incorrectly rewritten to `"1:" + (2 + offset)`. The old pattern anchored on the `"Line "` prefix and trailing `":"`, making it immune to such false positives.
Consider tightening the pattern to something like `"Line 1:(\\d+):"` (keeping the structural anchors) while still using `replaceAll` to handle multiple occurrences, which would preserve the safety of the original approach without the line-number check:
```java
final String pattern = "Line 1:(\\d+):";
testCase.adjustExpectedWarnings(warning -> regex.matcher(warning).replaceAll(match -> {
    int position = Integer.parseInt(match.group(1));
    return "Line 1:" + (position + offset) + ":";
}));
```
