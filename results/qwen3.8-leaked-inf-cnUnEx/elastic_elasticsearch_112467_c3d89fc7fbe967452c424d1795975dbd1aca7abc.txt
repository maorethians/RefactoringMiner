#3JVJS: The floating-point equality check `v == 180` is acceptable here since this is a test helper comparing against a known constant (the antimeridian). However, if any of the `lons` values could ever be the result of arithmetic (e.g., `360 - 180` computed at runtime), a tolerance-based comparison (`Math.abs(v - 180) < epsilon`) would be more robust. In a test context where values are set as literals, the current form is fine.
