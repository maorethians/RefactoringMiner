#6KD5S: The `mvSortedAscending()` fast-path in all three `process*` methods has two critical bugs:
1. **Missing `return`**: After the `if (valuesBlock.mvSortedAscending()) { ... }` block, execution falls through to the unsorted path (copy → sort → append), causing **two** values to be appended to the builder for a single position. A `return;` is needed at the end of the sorted-ascending branch.
2. **Wrong indices**: The sorted path uses absolute value indices (`0`, `valueCount - 1`, `lowerIndex`, `upperIndex`) instead of position-relative ones (`firstValueIndex`, `firstValueIndex + valueCount - 1`, `firstValueIndex + lowerIndex`, `firstValueIndex + upperIndex`). For any position other than the first in a multi-position page, this reads values from the wrong position.
Example from `processDoubles` (same pattern in `processInts` and `processLongs`):
```java
if (valuesBlock.mvSortedAscending()) {
    if (percentile == 0) {
        builder.appendDouble(valuesBlock.getDouble(0));  // should be firstValueIndex
    } else if (percentile == 100) {
        builder.appendDouble(valuesBlock.getDouble(valueCount - 1));  // should be firstValueIndex + valueCount - 1
    } else {
        var result = calculateDoublePercentile(fraction,
            valuesBlock.getDouble(lowerIndex),   // should be firstValueIndex + lowerIndex
            valuesBlock.getDouble(upperIndex));  // should be firstValueIndex + upperIndex
        builder.appendDouble(result);
    }
    return;  // <-- missing
}
```
This would produce incorrect results (and a corrupted output block with double the expected value count) whenever the input block is marked as sorted ascending and the position is not the first.

#SZJB3: This evaluator is missing the `try/catch (IllegalArgumentException)` around the `MvPercentile.process(...)` call that all other sibling evaluators (e.g. `MvPercentileDoubleIntegerEvaluator`, `MvPercentileDoubleDoubleEvaluator`, etc.) include. If this class is ever instantiated, an out-of-range percentile will propagate as an unhandled exception instead of being registered as a warning and producing a null.
Note: `MvPercentile.toEvaluator()` references `MvPercentileDoubleIntegerEvaluator` (not `MvPercentileDoubleIntEvaluator`), so this class appears to be unused. If it is indeed dead code, consider removing it to avoid confusion; if it is intended for use, add the missing exception handling.
