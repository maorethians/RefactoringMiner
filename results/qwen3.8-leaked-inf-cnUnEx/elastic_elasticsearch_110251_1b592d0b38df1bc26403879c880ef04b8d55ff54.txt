#N4HG7: The `startsWith` check is too broad and will produce false positives. Consider a nested object at path `foo` and a top-level sort field `foobar`:
```java
"foobar".startsWith("foo")  // true — incorrectly rejected
```
Because Elasticsearch field paths are dot-separated, a field is "under" a nested object only if it equals the path or begins with `path + "."`. The check should be:
```java
if (field.equals(nestedObjectMapper.fullPath())
    || field.startsWith(nestedObjectMapper.fullPath() + ".")) {
```
As written, any top-level field whose name happens to start with the same characters as a nested object's path will be wrongly rejected.

#VJM77: The updated test does not cover the prefix-collision edge case described above (e.g., sort field `foobar` with a nested object `foo`). Adding a case that asserts this combination is *allowed* would both document the intended behavior and guard against the `startsWith` bug.
