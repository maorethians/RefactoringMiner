#J6RVJ: The `finally` block only deletes the `sensor_data` index, but `lookupExplosionData` (shown in the dependency) creates both `sensor_data` and `sensor_lookup`. Compare with `#50YFM` (`lookupExplosionNoFetch`) and `#DK4AD` (`lookupExplosionBigString`), which both clean up both indices. The missing `deleteIndex("sensor_lookup")` will leak the index across test runs.

#B6WXG: The lambda `attempt -> fetchMvLongs()` ignores the `attempt` parameter entirely, so the retry loop in `assertCircuitBreaks` will issue five identical requests if the circuit breaker doesn't trigger on the first try. Every other call site in this chapter scales the workload via `attempt * N` (e.g. `attempt * 5000`, `attempt * 2000`). If `fetchMvLongs()` doesn't break on the first attempt, it won't break on subsequent ones either, making the retry mechanism a no-op here. Consider either giving `fetchMvLongs` a scalable parameter (like the other helpers) or calling it directly without the retry wrapper.

#TZQVM: The `fail` message is off by one. After the loop exits, `attempt` has been incremented to `MAX_ATTEMPTS + 1` (i.e. 6), so the message reads "giving up circuit breaking after 6 attempts" even though only 5 attempts were actually made. Use `MAX_ATTEMPTS` in the message instead:
```java
fail("giving up circuit breaking after " + MAX_ATTEMPTS + " attempts");
```
