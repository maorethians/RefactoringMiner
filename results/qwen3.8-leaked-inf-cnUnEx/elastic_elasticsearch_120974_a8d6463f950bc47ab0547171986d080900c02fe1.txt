#BCR52: The old code in `postParse` iterated over `context.getCopyToFields()`, which is a `Set<String>`, guaranteeing each target field received at most one `voidValue()` entry. In the new code, `createCopyToContext` is invoked once per (source-field → target-field) copy-to pair. If multiple source fields copy to the same target (e.g., field `a` has `copy_to: [z]` and field `b` also has `copy_to: [z]`), two identical `voidValue()` entries for `z` will be appended to `ignoredFieldValues`. This is functionally harmless (the void marker simply suppresses the field in synthetic source), but it produces redundant stored-field entries and grows the ignored-source payload unnecessarily. Consider guarding against duplicates, e.g., by checking whether a `voidValue()` entry for `copyToField` already exists in `ignoredFieldValues` before adding, or by tracking already-processed copy-to targets in a set on the context.
