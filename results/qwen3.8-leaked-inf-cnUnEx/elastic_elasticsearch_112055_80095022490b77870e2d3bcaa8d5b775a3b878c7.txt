#8JSBF: The `ascending` method for Long and the `ascendingUnsignedLong` method both pass `longs.count` to `unsignedLongMedianOf` instead of the `count` parameter. Since the ascending path is taken *instead of* the `process` path (the generated evaluators branch on `mvSortedAscending()`), `longs.count` is still `0` at that point. This causes `unsignedLongMedianOf` to compute `values[middle - 1]` → `values[-1]`, throwing an `ArrayIndexOutOfBoundsException` at runtime.
The Int and Double `ascending` methods in the same class correctly use the `count` parameter:
```java
return Math.toIntExact(longMedianOf(longs.values, count));   // Int — correct
return doubleMedianOf(doubles.values, count);                 // Double — correct
```
Both occurrences should be:
```java
// ascending (Long)
return NumericUtils.unsignedLongAsLongExact(unsignedLongMedianOf(longs.values, count));
// ascendingUnsignedLong
return unsignedLongMedianOf(longs.values, count);
```
