#XY8GM: The refactored offset-correction logic for the insertion case (`charDelta > 0`) now emits one `addOffCorrectMap` entry per inserted character instead of a single boundary entry. This is a meaningful semantic change: the old code recorded a single correction at `normalizedCharPos + numChars` with value `lastDiff - charDelta`, while the new code records corrections at `normalizedCharPos + (end - startIter) + i` with value `lastDiff - i` for each `i` in `[0, charDelta)`. Please confirm that downstream consumers of the offset-correction map (e.g., the token-position mapping in `NlpTokenizer.tokenize`) are compatible with receiving multiple adjacent entries rather than a single cumulative one. If the map is expected to hold at most one entry per output position, the loop is correct; if it was previously relying on a single "delta" entry to shift all subsequent positions, the behavior will differ.
