#2CED5: The profiler results are now set *inside* the `try` block, so they are skipped when a `TimeExceededException` is caught. In the previous code, if `RescorePhase.execute` handled a timeout internally (setting the partial-results flag and returning normally), execution would continue through `SuggestPhase.execute` and reach the profiler code, so `profileResults` would still be populated. Now, any timeout during rescore or suggest means the profiler results are never attached to the `QuerySearchResult`. This is a subtle behavioral change: users who enable profiling to debug a timeout will no longer see partial profiler output in the response. If this is intentional (incomplete profiler data is misleading), it's fine, but it's worth confirming since it changes the observable behavior of the `profile` API on timed-out searches.
