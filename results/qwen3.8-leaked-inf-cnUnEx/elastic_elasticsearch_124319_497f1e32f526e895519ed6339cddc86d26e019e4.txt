#F4DFD, #NMZDW: The method performs several unchecked casts and dereferences without null guards. If the REST API response is malformed or the data stream does not exist (e.g., a 404 body that still parses into a map), `response.get("data_streams")` could return `null`, causing a `NullPointerException` at `dataStreams.size()` rather than a clear assertion failure. Consider adding a null check or an explicit `assertThat(dataStreams, notNullValue())` before the size assertion to produce a more diagnostic test failure message. The same applies to `indices` before calling `.stream()` on it. Both helper methods assert that exactly one data stream is returned and that its name matches the input, which is a good defensive check. However, the two implementations are not perfectly symmetric in their error diagnostics: the `ESIntegTestCase` version will throw a typed `AssertionError` from `assertThat`, while the `ESRestTestCase` version will throw a `NullPointerException` if the expected keys are missing from the parsed JSON. Aligning the null-safety would make failure messages consistent across the two test frameworks.
