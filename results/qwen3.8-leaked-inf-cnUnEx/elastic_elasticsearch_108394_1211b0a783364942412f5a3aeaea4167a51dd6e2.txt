#SA564: The `shouldRecreateDestinationIndex` flag is only reset to `false` in the success path of `doMaybeCreateDestIndex`. However, if the destination index already exists (i.e., `destIndexMappings` is non-empty), the code falls into the `else` branch and the flag is never cleared. Since `TransformContext` is shared across runs, the flag will remain `true` indefinitely. This causes two side-effects on every subsequent `onStart`:
1. In `changedSourceListener`, the condition `shouldMaybeCreateDestIndex == false` is always false, forcing an unnecessary config reload and field-mapping re-fetch even when nothing has changed.
2. The `else if (shouldMaybeCreateDestIndex)` branch triggers a `validate()` call that would otherwise be skipped.
Consider resetting the flag in the `else` branch as well, since a non-empty `destIndexMappings` confirms the index exists:
```java
} else {
    context.setShouldRecreateDestinationIndex(false);
    configurationReadyListener.onResponse(null);
}
```
