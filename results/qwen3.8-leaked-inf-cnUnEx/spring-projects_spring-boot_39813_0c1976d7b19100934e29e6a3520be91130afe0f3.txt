#WEMV1: The test registers a filter that excludes classes whose name ends with `"City"`, then asserts `Country` is present and `City` is absent. The logic is correct and covers the new code path. One minor observation: the `EntityManager` obtained via `createEntityManager()` is never closed. In practice the `ApplicationContextRunner` tears down the context (and thus the `EntityManagerFactory`) after the `run` callback, so this is safe in a test, but wrapping it in a try-with-resources would make the intent explicit and guard against future refactors that might decouple the context lifecycle from the assertion:
```java
.run((context) -> {
    EntityManagerFactory emf = context.getBean(EntityManagerFactory.class);
    try (EntityManager em = emf.createEntityManager()) {
        assertThat(getManagedJavaTypes(em)).contains(Country.class).doesNotContain(City.class);
    }
});
```
This is a very minor stylistic point; the current code is functionally correct.
