#5HMC7, #F6MNQ, #Y2B46: The `enableStackOverflowAvoidance` field is declared and initialized but never used in `onConnectionClosed`. The second `if (executor == EsExecutors.DIRECT_EXECUTOR_SERVICE)` check is dead code — it is unreachable because the first `if` already replaces `DIRECT_EXECUTOR_SERVICE` with `threadPool.generic()`. The intended logic appears to be: when the setting is `false` (default) and the handler uses `DIRECT_EXECUTOR_SERVICE`, call `handler.handleException(exception)` directly on the current thread; when the setting is `true`, fall back to `threadPool.generic()`. As written, the setting has no effect and the test in `#4H8Q2` (which expects the DIRECT case to run on the test thread when the setting is absent) will fail.
