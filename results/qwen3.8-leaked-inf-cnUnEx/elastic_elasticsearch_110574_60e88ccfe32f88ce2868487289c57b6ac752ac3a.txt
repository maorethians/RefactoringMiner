#7HFQ2: The `validateGrokPattern` method throws a `ParsingException` whenever a duplicate attribute name is encountered, but the error message states "defined multiple times with **different types**" and the test in `#N0C5B` explicitly expects `"%{WORD:foo} %{WORD:foo}"` (same name, same type) to succeed. As written, if `captureConfig()` returns two entries for `foo` (both `WORD`), this method will throw and the test will fail.
The guard should verify that the types actually differ before rejecting:
```java
if (prev != null && !prev.equals(type)) {
    throw new ParsingException(
        "Invalid GROK pattern [" + pattern + "]: the attribute [" + name + "] is defined multiple times with different types"
    );
}
```
This makes the code consistent with both the error message and the test's expected behavior, and avoids a latent break if the Grok library's `captureConfig()` ever returns same-name/same-type duplicates.
