#AWD58: The comparison `fieldValue.equals(redacted) == false` is slightly harder to read than `!fieldValue.equals(redacted)`. More importantly, if `matchRedact` were ever to return `null` (e.g., an unexpected edge case), `fieldValue.equals(null)` would return `false`, causing `isRedacted` to be `true` and the metadata to be set even though the field was effectively cleared rather than redacted. A defensive `redacted != null && !fieldValue.equals(redacted)` would make the intent more explicit and guard against that edge case.
