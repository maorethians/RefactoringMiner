#96MB5: `markAsUsed` is acquired before the rewrite step but is only released inside `wrapFailureListener`, which is wired into the `onResponse` path of the `delegateFailure` BiConsumer. If `Rewriteable.rewriteAndFetch` (or `shard.ensureShardSearchActive`) fails, the `delegateFailure` listener delegates `onFailure` straight to the original `listener` and `markAsUsed` is never released. This leaks the reader-context keep-alive, potentially preventing the context from being freed.
Consider wrapping the listener passed to `rewriteAndFetchShardRequest` so that `markAsUsed` is released on the failure path as well, e.g. by composing a listener that calls `Releasables.close(markAsUsed)` before delegating to the original listener's `onFailure`, or by restructuring so that `wrapFailureListener` (or an equivalent releasable-closing wrapper) is applied *outside* the `delegateFailure` call.

#03WS8: `createLtrModel()` is invoked in the `@Before` method, so it runs before **every** test method in the class. In an internal-cluster test the trained model persists across test methods within the same cluster, so the second and subsequent calls to `PutTrainedModelAction` with the same model ID (`"ltr-model"`) will likely fail with a "model already exists" error. Consider moving the model creation out of `@Before` into a one-time `@BeforeClass`/`@ClassRule` setup, or guard it with an existence check, so it is only created once per cluster.
