#D67T5: The condition `if (isRoot() || isFragment)` now routes both roots and fragments to `b.startObject()` (anonymous). This is a behavioral change for the `isRoot() && isFragment` combination: previously it would have skipped braces entirely (since `isFragment == false` was the gate), now it writes anonymous braces. While this combination likely never occurs in practice (a root mapper is not a fragment), the logic silently changes behavior for a theoretically possible state. A brief comment or an `assert isRoot() == false || isFragment == false` (or similar) would make the invariant explicit and guard against future regressions if someone introduces a root-fragment mapper.

#TA369, #K7P7D: The single-child path writes `b.field(leafName())` followed by the leaf source loader's output (which is now a full object like `{"foo":"A"}`), producing `"path":{"foo":"A"}`. The multi-child path (in unchanged context) presumably does `b.field(leafName()).startArray()` … `b.endArray()`, producing `"path":[{...},{...}]`. This means a nested field with exactly one value serializes as a bare object while two or more serialize as an array. This is a pre-existing asymmetry (not introduced here), but it's worth confirming that downstream consumers (e.g., `_source` readers, reindexing, or the REST test's comparison logic) handle both shapes correctly. If the REST test in #SWA5V compares synthetic source against standard source, a single-element nested field could produce a shape mismatch (`"path":{...}` vs `"path":[{...}]`).
