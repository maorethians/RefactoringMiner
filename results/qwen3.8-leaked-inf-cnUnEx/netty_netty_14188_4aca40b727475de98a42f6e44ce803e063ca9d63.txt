#MEDV6: The link-local address check is incomplete. The IPv6 link-local prefix is `fe80::/10` (RFC 4291), meaning the first byte must be `0xFE` and the top two bits of the second byte must be `10` (i.e., the second byte ranges from `0x80` to `0xBF`). The current check `ipv6[1] == (byte) 0x80` only matches the single value `0x80`, missing valid link-local addresses such as `fe81::1` or `fe90::1`.
The condition should be:
```java
if (scopeId != 0 || (ipv6[0] == (byte) 0xfe && (ipv6[1] & 0xC0) == (byte) 0x80)) {
```
This aligns with how Java's own `Inet6Address.isLinkLocalAddress()` performs the check.

#KZM22: The tests cover the two primary branches (non-link-local with scopeId=0, and link-local `fe80::` with scopeId=0), which is good. However, consider adding a test for a non-link-local address with a **non-zero** scopeId to verify that the `scopeId != 0` branch correctly includes the scope identifier regardless of the address type. This would guard against a future regression where someone might accidentally couple the scopeId inclusion to the link-local check.
