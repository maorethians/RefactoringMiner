#R6T63: The `case null, default` in the switch is valid Java (since Java 14) and correctly routes a null `inputDataType` to `rawTermQueryList`, which handles the block generically without a type-specific cast. This is consistent with the field now being nullable.

#DNT6F: Adding `@Nullable` to `inputDataType` accurately documents the contract that this field can be null (either from pre-V_8_14_0 transport versions or from an unrecognized type name). This is appropriate.

#8YEET: The deserialization change is wire-compatible. For versions before V_8_14_0, neither the old nor new code reads a string from the stream (the old code used the literal `"unknown"`, the new code simply assigns `null`). For versions on or after V_8_14_0, both read a string and resolve it via `DataType.fromTypeName`. The behavioral outcome is identical (assuming `"unknown"` was not a registered type name, which `fromTypeName` would resolve to `null`), but the new code is more explicit and avoids a pointless map lookup.
