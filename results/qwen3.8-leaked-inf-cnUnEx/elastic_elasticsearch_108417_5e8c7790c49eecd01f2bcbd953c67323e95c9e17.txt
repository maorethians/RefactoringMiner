#54YXB: The `putIfAbsent` deduplication uses `value.name()` (the full dotted path, e.g. `"path.to"`) as the key for ignored values, but `field.fieldName()` (the simple/canonical name, e.g. `"to"`) as the key for field loaders. For any array nested under a non-root object these keys will never match, so the `putIfAbsent` guard is ineffective in that case. The tests pass presumably because the field loader's `hasValue()` is `false` after the source has been consumed by the clone, but if that invariant is ever broken (e.g. a future code path sets `hasValue` on the parent's field loader), the field would be emitted twice. Consider using `value.getFieldName()` as the map key so the deduplication key space is consistent with `field.fieldName()`, or add a comment documenting the invariant that makes the mismatch safe.
