#KXMMK: When `dsTemplateName` is `null` (i.e., `findV2Template` found no matching template for the data stream), the code falls through to `metadata.templatesV2().get(null)`, which returns `null`, making `dsTemplate == null` true. The condition then reduces to `indexTemplate.priorityOrZero() > 0`. For a template with no explicit priority (the common default), `priorityOrZero()` returns `0`, so the expression is `false` and the data stream is excluded from rollover. However, if no existing template matches the data stream, the newly installed template is by definition the first (and only) matching template, so it should trigger rollover regardless of its priority value. Consider treating the `dsTemplate == null` case as an unconditional `true` (or at least decoupling it from the priority comparison).

#89V9Z: The log message still reads `"rolling over data stream [{}] lazily as a followup to the upgrade of the [{}] index template [{}]"`, but the behavior now also covers initial installation (as made explicit by the renamed method and updated Javadoc in #ZRH13). The word "upgrade" is misleading in the installation case; consider "update" or "installation/update" to stay consistent with the new semantics.
