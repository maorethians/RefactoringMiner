#2WY23: In `testSerializationWithConfig()`, the expression is built with a random `config`, but then `assertSerialization(expr)` is called (the no-arg overload), which deserializes using `EsqlTestUtils.TEST_CFG`. Since `EsqlConfigurationFunction.equals()` now compares the `configuration` field, if the configuration is injected via `PlanStreamInput` rather than serialized as part of the expression's wire format, the deserialized expression will carry `TEST_CFG` and the `checkEqualsAndHashCode` assertion will fail. Consider calling `assertSerialization(expr, config)` to ensure the same configuration is used during deserialization, making the round-trip test self-consistent regardless of how the configuration is transported.
