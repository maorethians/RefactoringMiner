#PWMWN: The change simplifies the tail of `fieldNames` by removing the `if/else` branch and unconditionally adding `IndexResolver.INDEX_METADATA_FIELD` (`_index`) to the result set. This is a clean simplification, but it is also a **behavioral change**: previously `_index` was only included as a fallback when both `fieldNames` and `enrichPolicyMatchFields` were empty; now it is always present in the returned set.
If any downstream consumer of `PreAnalysisResult.fieldNames()` uses the *presence* of `_index` to detect the "no explicit fields requested" case (e.g., to skip a field-caps call or to choose a lighter query path), that logic will no longer work as intended. Please confirm that no such consumer exists, or that always having `_index` in the set is safe for all callers.
If the intent is simply to guarantee `_index` is always resolvable, the change is correct and the removed branch was unnecessary. In that case, consider adding a brief comment explaining *why* `_index` is always included (e.g., "always include `_index` so it is available for downstream resolution"), since the old comment that justified the fallback is gone.
