#KCC2A: In the `else if (res == Native.ERRNO_ECANCELED_NEGATIVE)` branch (the path taken when `isReadComplete()` is false, i.e., `readComplete0` returned early due to cancellation), `doBeginReadNow()` is invoked twice:
```java
} else if (res == Native.ERRNO_ECANCELED_NEGATIVE) {
    if (pending) {
        doBeginReadNow();
    }
    doBeginReadNow();  // <-- unconditional second call
}
```
The second call is outside the `if (pending)` guard, so it executes unconditionally. When `pending` is true, `doBeginReadNow()` is called twice (scheduling two reads for one pending request). When `pending` is false, a read is scheduled even though the user never signaled intent to read. This looks like a copy-paste error — the second `doBeginReadNow()` should be removed, leaving only the guarded call.
