#0ZJ70: The call to `RemoteClusterAware.isRemoteIndexName(pattern)` will throw a `StringIndexOutOfBoundsException` at runtime. Here's why:
`pattern` is `"FROM test1"` (produced by `from("test1")`). Inside `isRemoteIndexName`, the method does:
```java
int idx = indexExpression.indexOf(RemoteClusterService.REMOTE_CLUSTER_INDEX_SEPARATOR); // ':' → idx = -1
boolean isSelector = indexExpression.startsWith(SelectorResolver.SELECTOR_SEPARATOR, idx); // startsWith("::", -1) → throws
```
When the string contains no `:`, `idx` is `-1`, and `String.startsWith(prefix, -1)` throws `StringIndexOutOfBoundsException`. The test will crash instead of asserting the expected error message.
Additionally, even if the string did contain a colon (e.g., in a remote-cluster test setup producing `"FROM cluster:test1"`), passing a full SQL clause to a method that expects a bare index expression is a semantic misuse. The method's contract (per its Javadoc) is to evaluate an *index expression component*, not a `FROM` clause.
Suggested fix: extract the actual index name from the pattern before calling the check, or guard against the no-separator case:
```java
String indexName = "test1"; // the index in the FROM clause
boolean isRemote = indexName.contains(":") && RemoteClusterAware.isRemoteIndexName(indexName);
```
Or, if the intent is to check whether the *JOIN* target (`"foo"`) is a remote index, check that instead:
```java
RemoteClusterAware.isRemoteIndexName("foo")
```
