#RCSEF: The method accepts a `null` argument (as done in `#X7YAQ`), but the `else` branch asserts `ignoredFieldWithNoSource != null`. In production builds where assertions are disabled, if `arrayFieldMissingValue` were unexpectedly `null` when a `null` argument is passed, this would result in a `NullPointerException` at `ignoredFieldsMissingValues.add(ignoredFieldWithNoSource)` rather than a clear error. Consider either:
- Adding an explicit `if (ignoredFieldWithNoSource == null)` guard with a meaningful exception, or
- Splitting into two methods: `addIgnoredFieldMissingValue(NameValue)` for the non-array case and `markArrayForSourceRecording()` for the array case, making the null-passing unnecessary.

#BDPYD: 1. If a requested field is not found in the document (e.g., due to a logic error upstream), it is silently dropped from the result. Consider adding a debug-level log or assertion when `fields` is non-empty after the loop completes, to aid diagnosis of missing synthetic source values.
2. The `fields` map is keyed by `field.name()`. If two entries in `ignoredFieldsMissingValues` share the same name (which shouldn't happen in practice but could in edge cases with nested arrays), the last one silently wins. A defensive check or documentation note would help.

#G15RZ: The `RootDocumentParserContext` constructor allocates a new `LuceneDocument` and adds it to its internal `documents` list. Since this context is purely for reading values and is discarded after the method returns, this is harmless but slightly wasteful. If `RootDocumentParserContext` gains side effects in the future (e.g., metrics, listeners), this throwaway instantiation could become problematic. A lighter-weight parser wrapper might be more appropriate, but this is a minor concern.
