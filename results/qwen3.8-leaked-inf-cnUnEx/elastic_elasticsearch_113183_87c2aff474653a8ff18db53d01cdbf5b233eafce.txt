#C54JY: In `checkInvariant`, the heap-mode validation loop always checks `values.get(rootIndex)` instead of `values.get(l)`. This means the loop only re-checks the first element `bucketSize` times rather than verifying that every slot in the bucket is non-null:
```java
for (long l = rootIndex; l < common.endIndex(rootIndex); l++) {
    if (values.get(rootIndex) == null) {  // always checks rootIndex
        throw new AssertionError("values missing in heap mode");
    }
}
```
Should be `values.get(l) == null`.

#C54JY: In `merge`, the invariant check on the `other` sort uses the wrong bucket index. `bucket` is the *target* bucket in `this`, while `otherBucket` is the *source* bucket in `other`:
```java
other.checkInvariant(bucket);   // checks the wrong bucket in 'other'
```
Should be `other.checkInvariant(otherBucket)`. As written, this either validates the wrong bucket's state or (if `bucket` is out of range for `other`) triggers a spurious assertion failure.
