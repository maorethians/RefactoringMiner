#FVXE2: The `newMapperServiceCounter` assertions in this test are vacuous. The test creates a **new** `SyntheticSourceIndexSettingsProvider` whose mapper-service lambda does not increment `newMapperServiceCounter`:
```java
provider = new SyntheticSourceIndexSettingsProvider(
    syntheticSourceLicenseService,
    im -> MapperTestUtils.newMapperService(...),  // no counter increment
    getLogsdbIndexModeSettingsProvider(true)
);
```
As a result, every `assertThat(newMapperServiceCounter.get(), equalTo(0))` in this method passes trivially regardless of whether a `MapperService` is actually created. To make these assertions meaningful, the lambda should also call `newMapperServiceCounter.incrementAndGet()` (as done in `setup()`), or the test should reuse the provider created in `setup()` if the `getLogsdbIndexModeSettingsProvider(true)` variant is not strictly required.
