#99QNZ: The `resolve()` calls use a leading `/` (e.g., `TEST_BASE_DIR.resolve("/config")`). On Unix, a path starting with `/` is absolute, so `Path.resolve()` will discard the base directory and return `/config` — the `TEST_BASE_DIR` prefix is silently ignored. On Windows, `/config` is rooted but not absolute, so it resolves to `C:\config`, still not under the temp dir. If the intent is to place these base dirs under the temp directory (as the use of `TEST_BASE_DIR.resolve(...)` suggests), the leading slashes should be removed:
```java
TEST_BASE_DIR.resolve("config"),
new Path[] { TEST_BASE_DIR.resolve("data1"), TEST_BASE_DIR.resolve("data2") },
TEST_BASE_DIR.resolve("temp")
```

#V6TKD: `TEST_ABSOLUTE_PATH_TO_FILE` is declared `public`, but it is only referenced within `PolicyParserTests` itself. It should be `private` (or at most `protected` if a subclass needs it) to avoid leaking test internals.

#6RXAF, #C6K31, #G2CCW, #D7CTQ: The assertions in `ofPath` / `ofRelativePath` are removed and the corresponding parser-level validation tests (`testEntitlementRelativePathWhenAbsolute`, `testEntitlementAbsolutePathWhenRelative`) are deleted. This means the system no longer enforces anywhere that a `path` entry is absolute or a `relative_path` entry is relative. If this is intentional (e.g., the distinction is now handled downstream or the two forms are being unified), that's fine — but it would be worth a brief note in the commit message or a follow-up issue so the design decision is discoverable, since a caller could now silently pass a relative path to `ofPath` or an absolute path to `ofRelativePath` with no diagnostic at all.
