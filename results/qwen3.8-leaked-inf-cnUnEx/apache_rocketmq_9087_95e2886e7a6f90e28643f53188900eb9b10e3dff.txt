#DTQFH: The null check on `getPopInflightMessageCounter()` is called twice (once for the guard, once for the invocation). In a concurrent scenario the reference could theoretically change between the two calls. Storing it in a local variable would be safer and also avoids the redundant getter call:
```java
PopInflightMessageCounter counter = brokerController.getPopInflightMessageCounter();
if (counter != null) {
    counter.clearInFlightMessageNum(topic, group, entry.getKey());
}
```

#DTQFH: The `commitPullOffset` call passes the hardcoded literal `"ResetOffsetInner"` as the `clientHost` parameter. While this is a reasonable way to tag the origin of the offset commit, it makes the parameter name (`clientHost`) misleading in logs or audit trails. Consider whether a more descriptive constant (e.g., `AdminBrokerProcessor.RESET_OFFSET_SOURCE`) would improve clarity, or whether the `ConsumerOffsetManager` API should accept a dedicated "source" enum/string instead of overloading `clientHost`.
