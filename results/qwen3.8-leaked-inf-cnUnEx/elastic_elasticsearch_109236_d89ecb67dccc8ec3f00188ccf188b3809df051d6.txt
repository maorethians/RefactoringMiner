#DT641: The constant name `ENABLE_STACK_OVERFLOW_AVOIDANCE` and the setting key `transport.enable_stack_protection` use different terminology ("overflow avoidance" vs "stack protection"). Since the key is user-facing and the constant is internal, this is a minor readability concern but acceptable for a deprecated setting.

#MNKT7: In the `enableStackOverflowAvoidance == true` branch, `threadPool.generic().submit(...)` is used, while the adjacent `else` branch uses `executor.execute(...)`. The removed code also used `execute`. `submit` allocates a `FutureTask` wrapper and returns a `Future` that is immediately discarded. For consistency with the sibling branch and to avoid the unnecessary allocation, prefer `threadPool.generic().execute(...)`.

#9ENGC: The test method name contains a typo: `testOnConnetionCloseStackOverflowAvoidance` — "Connetion" should be "Connection".
