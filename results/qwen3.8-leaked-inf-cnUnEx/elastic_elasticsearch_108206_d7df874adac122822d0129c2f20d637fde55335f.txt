#6WX1D, #8GQ4N: The `isAlive` flag is set to `false` in the release lambda but is never reset to `true` when `appendToLoggers` is called again. This means a `MockLogAppender` instance that is captured, released, and then captured again (as the new test `#8GQ4N` does by reusing the same instance 1000 times) will be registered in the `mockAppenders` map but will be silently skipped in `RealMockAppender.append()` because `isAlive.get() == false`. The test passes only because it never asserts that log messages were actually matched.
Fix: add `isAlive.set(true);` at the top of `appendToLoggers`, before the registration loop.

#W16R5, #6WX1D: The new dispatch logic in `RealMockAppender.append()` performs an exact-match lookup: `mockAppenders.getOrDefault(event.getLoggerName(), List.of())`. The previous implementation relied on log4j2's logger hierarchy and additivity — an appender attached to `org.elasticsearch.test` would also receive events emitted by `org.elasticsearch.test.SomeClass`. With the exact-name map lookup, registering a parent logger name (e.g. `capturing("org.elasticsearch.test")` as done in `SettingsFilterTests`) will no longer capture events from child loggers. If all current call sites happen to use the exact logger name this is fine, but it is a silent semantic regression that will break any future (or existing, not shown here) usage that relies on hierarchical capture. Consider walking up the logger name (stripping the last segment) until a match is found, or documenting the exact-match contract explicitly.

#KSWJD: `init()` calls `parent.start()` and `Loggers.addAppender(...)` unconditionally. If it is invoked more than once in the same JVM (e.g. both `ESTestCase` and `SpawnerNoBootstrapTests` static initializers run in a shared test harness), the appender will be added to the root logger config twice, causing every log event to be dispatched to every registered `MockLogAppender` twice. A guard (e.g. an `AtomicBoolean initialized` or a check on `parent.isStarted()`) would make the method idempotent.
