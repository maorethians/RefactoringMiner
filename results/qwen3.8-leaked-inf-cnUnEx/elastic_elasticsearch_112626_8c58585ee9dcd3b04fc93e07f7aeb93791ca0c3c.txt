#1V3YR: The log message says "cannot add resource watcher, resource watcher service is closed" but the code immediately proceeds to add the watcher and return a valid `WatcherHandle`. The message contradicts the actual behavior. If the intent is to warn that the watcher will be registered but never checked (because the executor is shut down), the message should reflect that, e.g., `"adding resource watcher after service close; watcher will not be polled"`. As written, it misleads operators into thinking the add was rejected when it was not.

#Y3GV6: The rejected-execution handler uses `assert false;` immediately before `throw new IllegalStateException(...)`. In debug/test mode (asserts enabled), the `AssertionError` from `assert false` is thrown and the `IllegalStateException` is never reached, changing the exception type that callers see. If the goal is to make the failure loud in tests while still throwing a typed exception in production, consider removing the `assert` and relying solely on the `IllegalStateException`, or use a dedicated test assertion mechanism. As-is, the two lines are redundant in production and contradictory in debug.
