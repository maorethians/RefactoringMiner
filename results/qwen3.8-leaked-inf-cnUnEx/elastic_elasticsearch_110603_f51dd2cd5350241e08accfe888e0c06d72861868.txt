#KZEQP, #9Z9YE: The `useTsdbDefaults` field is declared and initialized to `false`, but it is never read or used anywhere in this chapter. In `#YPDFZ`, the default-mapping merge is gated only on `indexSettings.getMode().getDefaultMapping() != null`, with no reference to `useTsdbDefaults`. If this field is intended to let individual tests opt out of the default-mapping merge (e.g., to test the "no `@timestamp` mapper" path), the gating logic in `build()` is missing. If it is used in a later chapter, that's fine, but as it stands in this chapter it is dead code.

#QFEZC, #S02V5, #0KTA1: There is an inconsistency in which document context is used to access the keyed field. `#QFEZC` writes the key via `context.doc().onlyAddKey(...)`, `#0KTA1` reads it via `context.doc().getByKey(...)`, but `#S02V5` reads it via `context.rootDoc().getByKey(...)`. In the current call paths both resolve to the same root `LuceneDocument`, so the behavior is correct today. However, if a future change ever introduces a nested-document context where `doc() != rootDoc()`, `#S02V5` would silently get `null` while the other two would still work (or vice-versa). Picking one convention (`rootDoc()` for both readers, since the key is always written at the root) would make the contract explicit and prevent a subtle bug.
