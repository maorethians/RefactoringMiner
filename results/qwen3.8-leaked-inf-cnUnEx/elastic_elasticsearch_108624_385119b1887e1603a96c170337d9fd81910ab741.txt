#010Q5, #RD64N, #9SDVE: The dummy rollup index creation logic is duplicated across three test files. In `DatafeedJobsRestIT` it is extracted into a `createDummyRollupIndex()` helper, but in `FullClusterRestartIT` and `RollupIT` the same block is inlined. Consider extracting a shared utility (e.g., a static helper in a common test base class or a small test utility) so the mapping JSON and the "why" comment live in one place. This reduces the risk of the mapping drifting out of sync if the `_meta._rollup` marker format ever changes.

#J8TT4: The manual navigation only inspects the **first** field name at each nesting level (`_doc`, then `_meta`, then `_rollup`). This is correct *only if* the `PARSER_CONFIGURATION` include-filter guarantees that no other fields are emitted at those levels. If the filter semantics are ever changed, or if a mapping contains additional sibling fields that the filter does not strip, the check will silently miss a rollup marker and return `false`. A more defensive approach would be to loop over all field names at each level (using `nextFieldName()` in a loop) rather than relying on positional ordering. Even if the current filter makes the first-field check sufficient, a brief comment explaining *why* only the first field is checked (i.e., "the include-filter guarantees this is the only field present") would prevent a future regression if someone modifies the configuration.
