The old version verified the full physical plan structure (ProjectExec → LimitExec → AggregateExec → ExchangeExec → EsStatsQueryExec) with specific assertions on projections, aggregate names, stats output, and the query builder. The new version only asserts that the plan contains an `EsQueryExec` node. While I understand this is a temporary state given the TODO in `Count.surrogate()` about normalizing `COUNT(*)`, `COUNT()`, `COUNT(1)`, consider adding a comment with a tracking issue reference so it's clear this is intentional and temporary, and so the test isn't accidentally left in this weakened state.

#WNGXM: This change removes the exception for multiple stats that share the same name. Previously, `stats count(*), count(*)` (two stats with the same name) would still be pushed to the source; now any `stats.size() > 1` short-circuits. This is a safe conservative change, but it is a behavioral/performance regression for the (admittedly rare) case of duplicate-named stats. If this is intentional as part of the broader surrogate work, a brief comment explaining why the name-deduplication check is no longer sufficient would help future readers understand the rationale.

vs. the pattern used elsewhere:

assertThat(s.child(), equalTo(testCase.replacementForConstant.apply(...)));
