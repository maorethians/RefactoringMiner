#FT0CW: The `TermsQueryBuilder.doCoordinatorRewrite` has a logic error. A `terms` query has OR semantics — it matches if *any* of the provided values match. However, the current loop returns `MatchNoneQueryBuilder` immediately upon encountering the first value that does not match the tier, without checking the remaining values.
For example, with `terms: { _tier: ["data_frozen", "data_content"] }` and the actual tier being `"data_content"`:
- Iteration 1: `"data_frozen"` → `MatchNoDocsQuery` → returns `match_none` (incorrect!)
- It never reaches `"data_content"` which would have produced `match_all`.
The correct logic should be: if **any** value matches → `match_all`; if **no** values match → `match_none`. Suggested fix:
```java
for (Object value : values) {
    Query tierFieldQuery = tierFieldType.internalTermQueryCaseInsensitive(value, coordinatorRewriteContext);
    if (tierFieldQuery instanceof MatchAllDocsQuery) {
        return new MatchAllQueryBuilder();
    }
}
return new MatchNoneQueryBuilder("The \"" + getName() + "\" query was rewritten to a \"match_none\" query.");
```

#H9T2D: The condition `Regex.isMatchAllPattern(defaultField)` (i.e., `defaultField` is `"*"`) triggers the tier rewrite even when the query string query is intended to search **all** fields, not specifically `_tier`. In that case, a non-matching tier value would incorrectly produce `match_none`, excluding documents that might match the query text in other fields. For example, a `query_string` query with default field `*` and text `"data_frozen"` should search all fields for that text, but the rewrite would short-circuit to `match_none` if the node's tier is not `"data_frozen"`.
Consider restricting the condition to only `defaultField.equals(DataTierFieldMapper.NAME)` unless there is a specific reason to include the `*` case.
