#Z70EK, #V9Y8R: The removal of `physicalPlan(from + expression);` from the test method `testMaxExpressionDepth_mixed` eliminates a specific test case that verifies whether an ESQL statement with a depth just below the maximum limit is accepted without throwing an exception. This change means this particular edge case is no longer tested, which could potentially lead to regressions if the behavior of handling expressions near the maximum depth changes in future implementations. Additionally, the modification from checking a single expected error message to using `anyOf` with two possible messages introduces flexibility in the test by allowing it to pass if either of two specific error messages is returned. This acknowledges that there are multiple mechanisms (lines of defense) within the system for catching overly complex ESQL statements. However, this modification could lead to a false sense of security as it might not catch cases where neither of the expected messages is thrown due to an unexpected error or change in behavior.
