#HN2N1, #MQSFG: The addition of logging and assertion in the `onFailure` method introduces a potential security risk by exposing detailed error information through logs, which can lead to sensitive data leakage if exceptions contain confidential information. Additionally, assertions are not suitable for production environments as they can be disabled, leading to silent failures. This change poses both a security vulnerability and reduced system reliability.

#RRW6H: The introduction of the `onRejection` method ensures tasks are executed on the current thread during node shutdown, which is intended to prevent resource leaks. However, this change can lead to performance issues if a large number of tasks need to be executed synchronously on the current thread, potentially blocking other operations and causing delays. This results in reduced system responsiveness and potential for deadlocks.
