#T3R1H, #RA42C, #0W1GC: The method `isRolloverOnWrite` and the logic within `resolveStoredPipelines` assume that if a data stream is not found, rollover on write should be false. This assumption might be correct based on current requirements, but it's worth adding a comment to clarify this behavior for future maintainers.

#T3R1H: The method `isRolloverOnWrite` could benefit from an early return pattern to improve readability:
```java
if (dataStream == null) {
    return false;
}
return dataStream.getBackingIndices().isRolloverOnWrite();
```
This can be refactored to:
```java
if (dataStream == null || !dataStream.getBackingIndices().isRolloverOnWrite()) {
    return false;
}
return true;
```
Or more succinctly:
```java
return dataStream != null && dataStream.getBackingIndices().isRolloverOnWrite();
```

#RA42C: The method `resolveStoredPipelines` uses `orElse(Pipelines.NO_PIPELINES_DEFINED)` which might not be the most intuitive way to handle the absence of pipelines. Consider using `orElseGet(() -> Pipelines.NO_PIPELINES_DEFINED)` for clarity, although in this case, it doesn't change behavior.

#HJSQV, #TW4MC: Both test methods `testRolloverOnWrite` and `testResolveFromTemplateIfRolloverOnWrite` create similar data streams with different properties. Consider refactoring the creation of these data streams into a helper method to reduce code duplication:
```java
private DataStream createDataStream(String name, boolean rolloverOnWrite) {
    var backingIndex = ".ds-" + name + "-01";
    var indexUUID = randomUUID();
    return DataStream.builder(
        name,
        DataStream.DataStreamIndices.backingIndicesBuilder(List.of(new Index(backingIndex, indexUUID)))
            .setRolloverOnWrite(rolloverOnWrite)
            .build()
    ).build();
}
```
