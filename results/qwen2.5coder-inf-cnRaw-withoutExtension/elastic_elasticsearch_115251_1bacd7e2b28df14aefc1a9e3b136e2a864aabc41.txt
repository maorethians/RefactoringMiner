#82926, #D8GXG: The logic for filtering settings in both `validate` and `filterSettableSettings` methods now includes checking against `ALLOWED_SETTINGS_PREFIXES` and `EXPLICITLY_DENIED_SETTINGS`. However, there is a potential issue with the way `EXPLICITLY_DENIED_SETTINGS` is checked. In `#82926`, it should be `&& EXPLICITLY_DENIED_SETTINGS.contains(setting) == false` instead of `|| EXPLICITLY_DENIED_SETTINGS.contains(setting)` to ensure that explicitly denied settings are not allowed, even if they match a prefix.

#82926: The error message in the `validate` method now includes additional details about allowed prefixes and explicitly denied settings. However, the way it constructs the list of allowed prefixes (`ALLOWED_SETTINGS_PREFIXES.stream().map(s -> s + ".*").collect(Collectors.toSet())`) creates a new set each time this method is called, which could be inefficient if this validation is performed frequently. Consider caching this result or constructing it once during initialization.
