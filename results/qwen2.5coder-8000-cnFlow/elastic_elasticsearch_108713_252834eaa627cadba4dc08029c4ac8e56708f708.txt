#SWDVC, #HWNMV: The new optimizer rule `ReplaceTypeConvertingEvalWithAliasingEval` is introduced to replace type converting eval with aliasing eval when no type change occurs. However, there is a potential issue with the condition check:
```java
if (convert.field() instanceof FieldAttribute fa && fa.dataType() == convert.dataType()) {
```
The comparison `fa.dataType() == convert.dataType()` uses reference equality (`==`) for `DataType` objects. This might not work as expected if `DataType` is a non-primitive type and the instances are not interned or singletons. It's safer to use `.equals()` method for object comparison:
```java
if (convert.field() instanceof FieldAttribute fa && fa.dataType().equals(convert.dataType())) {
```
