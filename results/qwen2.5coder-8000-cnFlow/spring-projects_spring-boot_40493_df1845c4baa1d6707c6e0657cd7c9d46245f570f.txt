#9NA3F, #ZMKR4, #88BH9: The `escapeJson` method is introduced to escape JSON strings, which is a good practice to prevent issues when special characters are present in the input string. However, the current implementation does not handle all possible JSON escape sequences. For example, it does not escape `\f` (form feed) and `\r` (carriage return), which should be included for completeness. The test cases have been updated to include more complex parameters with nested JSON structures. This is good for testing the `escapeJson` method's functionality. However, the expected `authParamString` in both tests should be consistent with the order of parameters as they appear in the map. Since maps do not guarantee order, it might be better to use a sorted map or explicitly define the order in the test case to ensure consistency.

#97B54: The change to use `escapeJson(entry.getValue())` in `getAuthenticationParamsJson` is correct and necessary to ensure that the values are properly escaped before being formatted into JSON. However, it would be beneficial to add a comment explaining why this escaping is necessary to improve code readability.
