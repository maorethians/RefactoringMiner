#4DGGT, #KWHJT, #EMEK2, #75C5X: The change from `SortedSet<Dimension>` to `SortedMap<BytesRef, List<BytesReference>>` introduces a new data structure that requires careful handling of multi-valued fields. The current implementation allows for multiple values per dimension, but the logic assumes single-valued dimensions in some places, which can lead to incorrect behavior or exceptions if a dimension has more than one value.

#KWHJT, #EMEK2: The assertions `assert value.isEmpty() == false : "dimension value is empty";` and `assert values.isEmpty() == false : "dimension values are empty";` do not prevent the code from proceeding with an empty list. This can lead to a `NoSuchElementException` when calling `value.get(0)` or `values.get(0)`. It would be safer to throw an exception or handle the case where the list is empty.

#BG4RX: The change simplifies the hash calculation but removes the duplicate routing dimension check. This could lead to incorrect behavior if there are duplicate names in the `hashes` list, as the exception for duplicates is no longer thrown.
