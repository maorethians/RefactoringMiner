#XRSHN: The logic for handling paths that do not exist in the map is incorrect. The example provided in the Javadoc suggests that if a path like `path1.path2.path3.key2` does not exist, it should be added as `path3.key2` under `path2`. However, the current implementation will add `path3.key2` directly under `path1` because it only considers the last element of the path when adding a new entry. This behavior is inconsistent with the provided example.

#XRSHN: The method `extractSuffixMaps` does not handle cases where the path partially matches but the remaining elements do not exist in the map correctly. The current implementation will add the suffix map at the deepest level it can reach, which might not be the intended behavior if the path is supposed to be inserted as a new sub-map.

#XRSHN: The `insertValue` method should handle cases where the path contains elements that are not maps or lists more gracefully. Currently, it returns an empty list in such cases, but this might lead to unexpected behavior when trying to insert values into non-traversable data types.
