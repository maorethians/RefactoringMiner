#BCR52, #EAW4C: The logic for handling ignored source fields in synthetic mode has been moved from `IgnoredSourceFieldMapper.postParse` to `DocumentParserContext.createCopyToContext`. This change is mostly correct but introduces some redundancy and potential issues:
1. The comment in `createCopyToContext` suggests that this code ensures consistency between stored and synthetic `_source`, which was already handled in `postParse`.
2. The condition `indexSettings().getSkipIgnoredSourceWrite() == false` is checked in both methods, leading to duplicate logic.
3. The handling of `copyToField` scenarios (e.g., null values, disabled objects) is duplicated.
Suggestion: Consider consolidating the logic into a single method to avoid redundancy and ensure consistency. This could be done by moving the logic entirely to `createCopyToContext` if it makes sense for the design, or refactoring it into a helper method that both methods can call.
