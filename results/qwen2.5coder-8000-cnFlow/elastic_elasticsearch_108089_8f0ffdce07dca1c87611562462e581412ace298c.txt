#DBFHJ, #1VVZJ, #AKP20, #63968, #PG42R: The chosen maximum depth values for expressions (`MAX_EXPRESSION_DEPTH`) and queries (`MAX_QUERY_DEPTH`) are both set to 500. While this is a reasonable default, it might be beneficial to make these configurable via settings or system properties to allow flexibility based on different deployment environments and requirements. The `expressionDepth` and `queryDepth` counters are incremented at the beginning of their respective methods and decremented in a `finally` block. This ensures that the depth is correctly adjusted even if an exception occurs. However, it's important to ensure that no other code paths within these methods can bypass the `finally` block without decrementing the counter, which could lead to incorrect state. The test cases added in this diff cover various scenarios for exceeding the maximum expression and query depths. These tests are comprehensive and help verify that the depth checks work as expected. However, consider adding edge case tests where the depth is exactly at the limit to ensure that valid queries do not incorrectly trigger exceptions.
