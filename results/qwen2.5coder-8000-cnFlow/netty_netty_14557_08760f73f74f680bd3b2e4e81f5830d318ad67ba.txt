#WN0H4, #MBSHW, #AGYGZ, #EJWNX, #2XFNV, #3EA2M, #PC2PV: The introduction of `maxTaskProcessingQuantumNs` and its usage seems consistent across the constructors and the `run` method. However, there is a potential issue in how `maxTaskProcessingQuantumMs` is handled when it is zero. The current logic sets `maxTaskProcessingQuantumNs` to `DEFAULT_MAX_TASK_PROCESSING_QUANTUM_NS` if `maxTaskProcessingQuantumMs` is zero, which might not be the intended behavior. If a user explicitly sets `io.netty.eventLoop.maxTaskProcessingQuantumMs` to 0, they likely expect no time limit on task processing, but this change would override that setting.
