#CZ9YB, #5AQ6E: The deduplication of `ShardSearchFailure` objects using `.toString()` as a map key is fragile and inconsistent with the rest of the codebase. It is recommended to use `ExceptionsHelper.groupBy()`, which is the standard utility for this purpose in Elasticsearch (as seen in `#C83CN`).

#MAWDJ: The parser declaration for `SHARD_FAILURES` uses a stub lambda `(p, c) -> ShardSearchFailure.EMPTY_ARRAY` that ignores the input parser and always returns an empty array. This prevents shard failures from being correctly deserialized from XContent, as noted by the accompanying TODO.

#YD3P9: The method handles the `allow_partial_search_results` request parameter but omits the corresponding `allow_partial_sequence_results` parameter. For consistency and completeness, both should be supported if they are available in the `EqlSearchRequest` object.
