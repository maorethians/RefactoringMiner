#NS6T8: The conversion of `ignoredValues` (a `List`) into a `TreeSet` occurs within the `write` method for every document containing ignored values. While this ensures the merge logic in `DocValuesWithIgnoredSortedKeyedValues` works correctly, it introduces allocation and sorting overhead per document. If the number of ignored fields is typically small, this is acceptable; however, for documents with many large fields, this could become a performance bottleneck.

#NS6T8: The `write` method explicitly clears the state by setting `ignoredValues = List.of()`. While `SyntheticFieldLoader` implementations are generally used per-document and typically cleared via `reset()`, performing a side-effect inside `write` means that any subsequent calls to `hasValue()` (diff #4ZQMG) for the same document will return different results before and after the data has been written. This is likely acceptable given the lifecycle of synthetic source generation, but it deviates from a purely read-only `write` operation.
