#0YX4V, #6QJHN, #VJ465: The use of double-casting `(List<Attribute>) (List) in.readNamedWriteableCollectionAsList(NamedExpression.class)` to bypass generic type checks is risky. Since it reads a collection of `NamedExpression` but casts the list to `Attribute`, a `ClassCastException` will occur at runtime if any element in the serialized data is a `NamedExpression` that does not inherit from `Attribute`. It is safer to read the list as `NamedExpression` and explicitly validate or convert each element to an `Attribute`.

#HXZG9: The logic for determining the output of a `LOOKUP` has changed from providing a fallback (`Expressions.asAttributes(matchFields)`) when `localRelation` is null to throwing an `IllegalStateException`. This ensures that the output cannot be queried until the table is resolved, which improves fail-fast behavior but changes the contract of the `output()` method for unresolved nodes.
