#YNRQX: In `patchJar`, the `InputStream` obtained from `jarFile.getInputStream(entry)` is not closed when a class is being patched (inside the `if (classPatcher != null)` block). This leads to a resource leak. It should be wrapped in a try-with-resources block, similar to how it is handled in the `else` block.

#YNRQX: The `transform` method iterates over `patchersToApply` and calls `outputs.file(...)` with the same filename (`inputFile.getName().replace(".jar", "-patched.jar")`) for each matching patcher set. If multiple patcher configurations match a single input file, this will result in redundant I/O operations where subsequent patches overwrite previous ones, and only the last patcher's changes will be preserved. The logic should instead aggregate all applicable patches into a single map and call `patchJar` once per input file.
