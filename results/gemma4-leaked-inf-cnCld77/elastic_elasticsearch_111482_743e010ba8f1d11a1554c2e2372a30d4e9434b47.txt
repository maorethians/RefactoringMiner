#T78XV: The `typeErrorMessage` method constructs an expected error message that does not match the format used in `TypeResolutions.isType`. Specifically, it uses a literal `[]` for the operation name (`"argument of [] must be..."`), whereas the production code populates this field with the actual operation name (e.g., `"argument of [MAX] must be..."`). This will cause type-error test cases to fail as the expected and actual strings will not match.
