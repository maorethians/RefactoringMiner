#9CT4X: The method performs scalar assertions (e.g., `not(equalTo(Double.NaN))`) on the `result` object regardless of whether it is an `Iterable`. When `result` is a collection, these assertions are redundant and logically meaningless as a collection instance will never be equal to a `Double` value. These checks should be moved into an `else` block relative to the `instanceof Iterable<?>` check.

#9CT4X: The use of Java `assert` statements (e.g., `assert testCase.getMatcher().matches(...) == false`) is discouraged in test code because they are typically disabled by default in the JVM unless the `-ea` flag is provided. These should be replaced with framework-provided assertions such as `assertThat` or `assertTrue`.

If the input data is empty (`size == 0`), `expected` remains `null`. In the original implementation, the stream-based approach using `summarizingInt/Long/Double().getAverage()` would have returned `0.0` for empty sets.
