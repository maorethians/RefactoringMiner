#BCR52: Moving the logic for marking copied fields as "void" from `postParse` (which iterated over a set of unique target fields) to `createCopyToContext` introduces potential redundancy. If multiple source fields are configured to copy to the same target field, `createCopyToContext` will be called for each one, resulting in multiple identical entries being added to `ignoredFieldValues`. This subsequently leads to multiple redundant `StoredField` entries being written to the Lucene document for a single target field, increasing storage overhead compared to the previous implementation.
