#QE6V2: In the methods `processDoubles`, `processInts`, and `processLongs`, the optimized path for sorted blocks (`if (valuesBlock.mvSortedAscending())`) incorrectly uses absolute indices instead of relative indices. 
The code accesses values at indices `0`, `valueCount - 1`, `lowerIndex`, and `upperIndex`. However, according to the `Block` API, values for a specific position are located between `getFirstValueIndex(position)` (inclusive) and `getFirstValueIndex(position) + getValueCount(position)` (exclusive).
The indices should be offset by `firstValueIndex`. For example:
- `valuesBlock.getDouble(0)` $\rightarrow$ `valuesBlock.getDouble(firstValueIndex)`
- `valuesBlock.getDouble(valueCount - 1)` $\rightarrow$ `valuesBlock.getDouble(firstValueIndex + valueCount - 1)`
- `valuesBlock.getDouble(lowerIndex)` $\rightarrow$ `valuesBlock.getDouble(firstValueIndex + lowerIndex)`
This will lead to `ArrayIndexOutOfBoundsException` or retrieval of data from the wrong position when the block's first value index for the current row is not zero.
