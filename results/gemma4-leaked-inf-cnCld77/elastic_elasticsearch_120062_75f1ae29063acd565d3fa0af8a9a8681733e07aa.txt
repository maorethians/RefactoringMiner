#NT186: The change replaces the physical shard ID (`shardTarget().getShardId().id()`) with the request-relative ordinal index (`request().shardRequestIndex()`). This is a critical distinction in Elasticsearch when handling aliases or routing, as the coordinator uses the request index to map results back to the original query. Assuming `buildRankFeatureShardResult` is intended to identify the shard's position within the current search request rather than its global cluster identity, this change is correct.
