#PG42R, #5EG5D, #XRJHQ, #03MFV: All changes in this chapter implement safety limits on the nesting depth of ESQL expressions and query plans to prevent potential stack overflow vulnerabilities (DoS). The implementation follows a robust pattern using `try...finally` blocks to ensure that depth counters are correctly decremented regardless of whether parsing succeeds or fails.
The accompanying tests in `#PG42R` comprehensively cover various ways to trigger these limits (casts, mathematical operators, boolean logic, and parentheses), ensuring the boundaries are correctly enforced. Additionally, the updates to `HeapAttackIT` (`#5EG5D`, `#XRJHQ`, `#03MFV`) correctly adjust existing integration tests so they do not inadvertently trigger these new parser limits when testing other mechanisms like circuit breakers.
