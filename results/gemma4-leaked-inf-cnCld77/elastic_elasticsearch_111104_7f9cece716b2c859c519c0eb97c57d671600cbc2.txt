#CKG9M: The addition of async headers (`Async-ID`, `Async-running`) is currently nested within the `if (mediaType instanceof TextFormat format)` block. This results in these headers being omitted for other media types, such as `ArrowFormat`. These headers should be moved outside the format-specific logic to ensure consistent API behavior across all supported formats.

#FVEHM, #N3WAZ: There are several inconsistencies regarding async headers between the implementation and the tests:
1. **Naming Mismatch**: The constants defined in `#N3WAZ` (`Async-ID`, `Async-running`) do not match the hardcoded strings used for verification in `#FVEHM` (`X-Elasticsearch-Async-Id`, `X-Elasticsearch-Async-Is-Running`). Since the implementation only adds headers using the constants, the assertions for the `X-Elasticsearch-` prefixed headers will fail.
2. **Value Mismatch**: In `#FVEHM`, the test parses the running status as a boolean via `Boolean.parseBoolean()` (expecting `"true"`/`"false"`), but subsequently asserts that the header value is either `"?1"` or `"?0"`.
