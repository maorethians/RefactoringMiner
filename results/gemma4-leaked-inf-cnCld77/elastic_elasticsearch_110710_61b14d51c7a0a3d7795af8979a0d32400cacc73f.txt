#FZ7RT: The `readNodesFrom` and `writeNodesTo` methods are implemented using `TransportAction.localOnly()`. This prevents the `NodesFeaturesResponse` from being serialized over the network. Since this action is registered globally in `ActionModule` with a monitor-style name (`cluster:monitor/nodes/features`), it will cause an `UnsupportedOperationException` if called by any client other than the coordinating node (e.g., via a REST request or from another node).

#8YHRC: The retry logic in `NodeFeaturesFixupListener` schedules retries indefinitely upon failure (`scheduleRetry`). There is no mechanism to stop retrying if a node has left the cluster or to implement a maximum retry limit/exponential backoff. This could lead to a resource leak of scheduled tasks for nodes that are permanently gone from the cluster.
