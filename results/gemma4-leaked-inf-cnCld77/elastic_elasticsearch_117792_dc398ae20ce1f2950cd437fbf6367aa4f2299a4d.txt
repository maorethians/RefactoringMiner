#RSAF4: The use of a `ConcurrentMap` keyed by thread ID to manage per-thread `SourceProvider` instances in `getSource` introduces unnecessary overhead. Since `getSource` is called for every document, the cost of `computeIfAbsent` (which involves synchronization and hashing) will be significant. A `ThreadLocal<SourceProvider>` would be more performant and idiomatic for this purpose.

#Z3NE2: When `syntheticSource` is true, `ctx.createSourceProvider()` is called every time `lookup()` is invoked for scripts or runtime fields. If the execution path is not using the `ReinitializingSourceProvider` (e.g., outside of ESQL compute), this will result in the creation of a new `SourceProvider` instance frequently, potentially increasing GC pressure during large searches.
