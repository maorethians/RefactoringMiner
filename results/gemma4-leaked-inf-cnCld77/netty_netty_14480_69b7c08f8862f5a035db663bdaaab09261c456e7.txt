#B9YWS, #TCNQE, #AQN8A: The changes introduce a bug where the underlying stream can be over-consumed by one byte before an `IOException` is thrown when the maximum number of bytes read is exceeded. 
In both `read()` and `read(byte[], int, int)`, the limit check now occurs *after* the read operation has been performed on the underlying stream. Specifically:
1. In `read()`, if `numRead` is exactly equal to `maxBytesRead`, the pre-check passes, a byte is read from the source, and only then is the exception thrown.
2. In `read(byte[], int, int)`, the calculation `Math.min(len, maxBytesRead - numRead + 1)` explicitly allows reading up to one byte beyond the limit before the post-check throws an exception.
This violates the purpose of a bounded stream by modifying the state of the underlying source (consuming a byte) that should not have been read. The previous implementation correctly performed a predictive check to prevent this over-consumption.
