#6GX73: The use of an assertion to verify that `context.sourceToParse().id()` is non-null is problematic. Because assertions are typically disabled in production, a null ID will lead to a `NullPointerException` when calling `Base64.getUrlDecoder().decode()`. This effectively replaces the previous behavior—which threw a descriptive `DocumentParsingException` (as seen in the removed test #QQD59)—with an unhandled runtime exception.

#QQD59: The removal of `testParseWithDynamicMappingNullId` is justified by the new fallback logic in #6GX73, but it creates a testing gap. There should be a corresponding test case added to verify that the routing hash is correctly derived from the document ID when the explicit routing hash is missing.
