#BCR52, #09SM0: Moving the logic to mark `copy_to` target fields as "void" from `postParse` to `createCopyToContext` introduces a potential for redundant data storage. 
In the original implementation (`#09SM0`), this process occurred once per document using a set of unique target fields (`context.getCopyToFields()`). In the new implementation (`#BCR52`), an entry is added to `ignoredFieldValues` every time `createCopyToContext` is invoked. If multiple source fields copy to the same target field, duplicate "void" entries will be added to the list and subsequently written as redundant stored fields in the Lucene document via `postParse`.
