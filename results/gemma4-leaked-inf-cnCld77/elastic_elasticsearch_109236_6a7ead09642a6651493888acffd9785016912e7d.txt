#90ZWA, #F6MNQ, #Y2B46: The `enableStackOverflowAvoidance` field (declared in #F6MNQ and initialized in #Y2B46) is completely ignored in the implementation of `onConnectionClosed`. 
Currently, the logic hardcodes a switch from `EsExecutors.DIRECT_EXECUTOR_SERVICE` to `threadPool.generic()` regardless of the setting's value:
```java
var executor = handler.executor();
if (executor == EsExecutors.DIRECT_EXECUTOR_SERVICE) {
    executor = threadPool.generic();
}
```
Based on the test cases in #RC351, this behavior should be conditional. When `enableStackOverflowAvoidance` is `false`, a handler using a direct executor should be notified on the current thread to avoid unnecessary context switching, whereas when `true`, it should be moved to the generic pool to prevent potential stack overflows.
