#P3DEE, #DJPE3: The implementation of `Locate.process` performs multiple allocations per row during evaluation: it calls `str.utf8ToString()` and `substr.utf8ToString()`, creating two new Java `String` objects for every single record in the page. In a high-throughput compute operator, this will create significant GC pressure. 
If `substr` is a constant literal (which is common), its string representation should be computed once outside the loop rather than per row. Even for non-constants, consider if there are ways to perform the search directly on the `BytesRef` or use a reusable buffer to minimize allocations.
