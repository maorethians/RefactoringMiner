#NGWDH, #F30E6: The logic for identifying original indices has changed. Previously, any index with `IndexMode.LOOKUP` was explicitly excluded via `addOriginalIndexIfNotLookup`. The new implementation in `forEachFromRelation` only excludes indices on the right side of joins. Consequently, if an index with `IndexMode.LOOKUP` is used as a primary source (the left side of a join or the initial `FROM` clause), it will now be included in the original indices list, whereas it was previously filtered out.

#F30E6: The change from `plan.forEachUp(...)` to the recursive `forEachUpWithChildren` (which is a post-order traversal) alters the order in which `EsRelation` nodes are visited. Since `indices` is a `LinkedHashSet`, this will change the order of indices in the resulting array returned by `planOriginalIndices`. If downstream consumers rely on a specific ordering of these indices, this may introduce a regression.
