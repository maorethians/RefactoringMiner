#Y0M91: The implementation of `unsignedLongAsLongExact` is logically inverted. It throws an `ArithmeticException` when the value fits within a signed long (`l >= 0`) and returns a bit-flipped value (via `twosComplement`) when it overflows (`l < 0`). To correctly convert an unsigned long to a signed long, it should return the value if `l >= 0` and throw an exception if `l < 0`.

#ZTT7Y: In `unsignedLongMedianOf`, `Arrays.sort(values, 0, count)` is used on a `long[]` containing unsigned values. In Java, `Arrays.sort(long[])` performs a signed sort; consequently, any unsigned value $\ge 2^{63}$ (where the sign bit is set) will be incorrectly sorted to the beginning of the array rather than the end. An unsigned comparator (e.g., `Long.compareUnsigned`) should be used instead.

#ZTT7Y: The method `unsignedDifference` uses signed comparison operators (`a >= b`) to determine the subtraction order for values intended to be treated as unsigned longs. This will produce incorrect results when one value has the sign bit set (representing a value $\ge 2^{63}$) and the other does not, as the signed comparison will yield the opposite of the unsigned relationship.
