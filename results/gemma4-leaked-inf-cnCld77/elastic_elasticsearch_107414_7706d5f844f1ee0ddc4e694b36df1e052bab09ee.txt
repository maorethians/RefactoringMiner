#WNGXM: The condition for returning early in `PushStatsToSource` has been made significantly more restrictive. Previously, the optimizer only blocked pushing stats to the source if there were multiple **distinct** stat names (`stats.stream().map(Stat::name).collect(Collectors.toSet()).size() > 1`). Now, it blocks the operation whenever there is more than one stat in total (`stats.size() > 1`), regardless of whether they share the same name or are different types of aggregations (e.g., a `SUM` and a `COUNT`).
This appears to be a performance regression as it prevents pushing multiple valid, distinct statistics to the source. If this change was intended to avoid redundant stats (as suggested by the comment in `#NW6B2`), it would be more efficient to implement the deduplication logic first or retain the check for distinct names, rather than disabling the optimization entirely for all multi-stat queries.
