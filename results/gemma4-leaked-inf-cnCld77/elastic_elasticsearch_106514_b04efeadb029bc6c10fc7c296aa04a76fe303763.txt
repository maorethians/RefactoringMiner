#TQEVY, #W8FSE: Logic Issue: Incorrect initialization of `originalIndices`
In diffs `#TQEVY` and `#W8FSE`, the `originalIndices` field is only assigned if it is currently `null`. Since these methods (`indices()` and `index()`) are builder-style setters, this logic prevents `originalIndices` from being updated if a user calls these methods multiple times on the same `AliasActions` instance. 
For example, if a user calls `.index("a")` followed by `.index("b")`, the `indices` field will correctly be `["b"]`, but `originalIndices` will remain `["a"]`. Consequently, `getOriginalIndices()` (diff `#NM3GB`) will return the stale value `["a"]` instead of the actual requested index `["b"]`. The null check should be removed to ensure `originalIndices` always reflects the most recent input.
