#M9JSE: The `Locate.process` method calculates the starting offset using code points (`offsetByCodePoints`), but returns the result of Java's `String.indexOf`, which returns a UTF-16 code unit index. In strings containing characters outside the Basic Multilingual Plane (e.g., emojis), this will return an incorrect position because a single character may consist of multiple code units. To return a 1-based code point position, you must calculate the number of code points existing before the found UTF-16 index.

#MYF4Y: The test cases in `LocateTests` use Java's `String.indexOf` to determine the expected result:
`int expectedValue = 1 + value.indexOf(substrValue);`
Because this mirrors the incorrect UTF-16 indexing logic used in the implementation, the tests will pass even for strings with multi-unit characters, failing to catch the bug described above. The tests should instead verify results against expected code point positions.
