#BFXC4: In the `readComplete` method, within the `finally` block handling the case where `recvBufAllocHandle().isReadComplete()` is false, there is a logic error when `res == Native.ERRNO_ECANCELED_NEGATIVE`. 
The code currently performs:
```java
if (pending) {
    doBeginReadNow();
}
doBeginReadNow();
```
This results in `doBeginReadNow()` being called twice if `pending` is true, and once regardless of the value of `pending`. This contradicts the accompanying comment which states that the read should be scheduled "if the user did signal the desire to read again" (i.e., only when `pending` is true). The unconditional second call should likely be removed.
