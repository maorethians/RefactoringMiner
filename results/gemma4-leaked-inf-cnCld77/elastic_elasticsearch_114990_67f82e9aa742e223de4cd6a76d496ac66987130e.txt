#FT0CW, #ZP11E: The logic in `doCoordinatorRewrite` for `TermsQueryBuilder` is incorrect. A terms query acts as an OR operation across all provided values. However, the current implementation returns a `MatchNoneQueryBuilder` immediately if the first term does not match the constant field value. It should only return `MatchNoneQueryBuilder` if *none* of the terms in the list match.

#H9T2D, #BH8PZ, #AKW8H, #4G4BG: The coordinator rewrite for `QueryStringQueryBuilder` and `SimpleQueryStringBuilder` passes the raw `queryString` (or `queryText`) directly as a single term value to the rewrite helper. This bypasses the parsing logic of these builders. If a user provides a complex query string targeting the `_tier` field (e.g., using boolean operators or wildcards), it will be treated as one literal string, likely resulting in an incorrect `MatchNoneQueryBuilder` instead of being parsed and evaluated correctly.
