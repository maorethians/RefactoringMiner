#T78XV: The `typeErrorMessage` method constructs an expected error message with empty brackets: `"argument of [] must be [...]"`. However, the production code it is testing (`TypeResolutions.isType`) populates these brackets with the `operationName`. This discrepancy will likely cause type-error tests to fail as the actual output will contain the function name while the expectation remains empty.

#KEYHF: The variable `allValuesNull` is determined using `.anyMatch(Block::areAllValuesNull)`. This logic returns `true` if *at least one* block (column) in the page consists entirely of nulls. If the aggregation involves multiple columns, this may be incorrect; it should likely use `.allMatch(...)` to ensure that all input data for the operation is null before treating the entire page as null.
