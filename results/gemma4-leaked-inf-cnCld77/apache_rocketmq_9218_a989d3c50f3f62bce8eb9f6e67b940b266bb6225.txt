#7JRNV: The removal of the fallback logic `if (pullOffset < 0) { pullOffset = brokerOffset; }` is inconsistent with similar logic maintained in `#2B020` and `#1HKDY`. If both `popBufferMergeService.getLatestOffset` and `offsetManager.queryOffset` return negative values, `pullOffset` will remain uninitialized or negative, leading to incorrect calculations for Pop consumers when the KV service is disabled.

#7JRNV: By changing the condition to `if (isPop && !brokerConfig.isPopConsumerKVServiceEnable())`, any Pop consumer using the KV service will now fall into the `else` block and execute `offsetManager.queryPullOffset(group, topic, queueId)`. This incorrectly treats a Pop consumer as a standard Pull consumer for calculating available messages.
