#WVP9V: The `CaseEagerEvaluator` continues to use range-based copies (`builder.copyFrom(lhs, p, p + 1)`) for single positions. The accompanying comment explicitly notes that this is "quite slow" and suggests using single-valued copies—an API that has been introduced in this chapter across all `BlockBuilder` implementations. This should be updated to use the new `copyFrom(block, position)` methods for better performance.

#BXEH1, #0FW1C, #26M5T, #9N9TW, #6RRKB: In the `perPosition` implementation of the lazy evaluators (e.g., `CoalesceBooleanLazyEvaluator`), there is an inconsistency in how values are copied into the result builder. The first block (`lastFullBlock`) is copied using a range-based call (`result.copyFrom(lastFullBlock, p, p + 1)`), while subsequent blocks are copied using the new single-position API (`result.copyFrom(block, 0)`). Since `lastFullBlock` is already known not to be a vector at this stage, the range-based call is less direct and should be replaced with the single-position `copyFrom` for consistency and clarity.
