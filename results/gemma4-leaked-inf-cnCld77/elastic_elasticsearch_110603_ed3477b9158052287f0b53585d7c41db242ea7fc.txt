#0KTA1: The implementation changes the lookup of the timestamp field from `context.rootDoc()` to `context.doc()`. In the previous version, `rootDoc()` was explicitly used to ensure validation occurred against the root document regardless of the current parsing context. If `postParse` is invoked within a nested document context, using `context.doc()` will fail to find the timestamp value (which is stored at the root), potentially leading to incorrect "timestamp field is missing" exceptions for documents containing nested objects. It is recommended to revert to `context.rootDoc()`.
