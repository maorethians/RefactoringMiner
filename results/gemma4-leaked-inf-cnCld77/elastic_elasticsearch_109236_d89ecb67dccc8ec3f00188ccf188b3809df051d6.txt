#DJZE0: The implementation of `onConnectionClosed` has changed the task granularity for notifying response handlers. Previously, a single task was submitted to the generic thread pool to process all pruned handlers sequentially. The new logic submits a separate task (or performs a direct call) for each individual handler. 
While this allows notifications to be distributed across different executors and potentially processed in parallel, it increases overhead on the thread pool's queue during mass disconnection events (e.g., node failure), as $N$ tasks are now queued instead of one.
