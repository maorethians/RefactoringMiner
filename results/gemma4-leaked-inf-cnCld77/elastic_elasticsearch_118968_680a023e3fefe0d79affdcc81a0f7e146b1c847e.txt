#A715J: The setting key `"index.logsdb.use_default_sort_config"` is ambiguous. Given that it specifically controls whether sorting includes `host.name` or only `@timestamp`, a more descriptive name such as `"index.logsdb.sort_on_host_name"` would better express the intent and avoid confusion with general "default" configurations.

#FHANM: The error messages thrown when sort properties (order, mode, missing) are provided without sort fields are slightly misleading. Using `"size mismatch"` is technically correct (0 vs N), but it doesn't clearly communicate to the user that they cannot override properties of a default sort configuration; they must define their own `index.sort.field` list first.
