#2NX5F, #TPWDG, #EJWNX, #2XFNV, #3EA2M, #PC2PV: The introduction of `maxTaskProcessingQuantumNs` and its usage in place of `maxTasksPerRun` seems logical for controlling the time spent processing tasks before yielding to IO. However, there are a few points to consider:
1. The conversion from milliseconds to nanoseconds is done using `TimeUnit.MILLISECONDS.toNanos`, which is correct but could be made more explicit by adding a comment explaining why this conversion is necessary.
2. The default value of 1000 ms (or 1 second) for `maxTaskProcessingQuantumMs` should be well-documented and justified, as it can significantly impact the behavior of the event loop.
3. In `#EJWNX` and `#2XFNV`, the ternary operator used to set `maxTaskProcessingQuantumNs` could be simplified by directly using `ObjectUtil.checkPositiveOrZero(maxTaskProcessingQuantumMs, "maxTaskProcessingQuantumMs")` without the conditional check for zero, as `checkPositiveOrZero` will throw an exception if the value is negative.

#PC2PV: The change in `runAllTasks` from using `maxTasksPerRun` to `maxTaskProcessingQuantumNs` is appropriate given the new parameter. However, ensure that the logic within `runAllTasks` correctly handles the timeout based on nanoseconds, as this might require adjustments if the original implementation was designed around a different unit of measurement.
