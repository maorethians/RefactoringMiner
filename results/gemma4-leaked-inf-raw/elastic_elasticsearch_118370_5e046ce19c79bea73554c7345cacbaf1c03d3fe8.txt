#1JD7R, #VG8DB: Using a `ConcurrentMap` to store `SourceProvider` instances keyed by thread ID can lead to a memory leak if `ReinitializingSourceProvider` is long-lived (e.g., shared across multiple queries), as entries are never removed from the map even after threads terminate. 
A more idiomatic and safer approach for per-thread state in Java is using `ThreadLocal<SourceProvider>`, which ensures that values can be garbage collected along with the thread or explicitly removed.
