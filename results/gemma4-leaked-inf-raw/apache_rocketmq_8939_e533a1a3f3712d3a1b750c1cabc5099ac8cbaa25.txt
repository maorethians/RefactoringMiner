#EX616, #9TXZY: The removal of `RocksDBLmqConsumerOffsetManager` and the corresponding update in tests indicate a change in the behavioral contract of `queryOffset(String group, String topic)`. 
The deleted implementation in `RocksDBLmqConsumerOffsetManager` explicitly guaranteed a non-null return value (returning an empty `HashMap` when no offsets were found for LMQ groups). However, the updated test in `#9TXZY` now expects a `null` return value (`assertNull(actualOffsets)`), which is the default behavior of the base `RocksDBConsumerOffsetManager`.
If there are existing callers of this method that rely on the non-null guarantee to avoid null checks, this change may introduce `NullPointerException` risks. Please verify that all call sites for LMQ offset queries are equipped to handle a `null` return value.
