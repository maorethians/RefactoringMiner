#4KAVQ: In `IngestStats.ByteStats.toXContent`, the condition `if (bytesIngested > 0 && bytesProduced > 0)` prevents either metric from being reported if one of them is zero. For example, if a pipeline ingests data but drops all documents (resulting in `bytesProduced == 0`), neither the ingested nor produced byte counts will be visible in the API response. This logic should likely use a logical OR (`||`) or check each field independently to ensure that any non-zero activity is reported.

#NN5KF: The `peekFirst()` method identifies the "first" pipeline using `defaultPipeline != null ? defaultPipeline : finalPipeline`. If these fields only represent index-level settings, this logic may fail to identify a pipeline explicitly specified in the request as the first pipeline. While it is unclear from this chapter how `defaultPipeline` is populated, typically the resolution order for ingest pipelines is: *Request Pipeline* $\rightarrow$ *Default Pipeline* $\rightarrow$ *Final Pipeline*. If `defaultPipeline` does not encompass the request-specified pipeline, stats will be attributed to the wrong pipeline or missed entirely.
