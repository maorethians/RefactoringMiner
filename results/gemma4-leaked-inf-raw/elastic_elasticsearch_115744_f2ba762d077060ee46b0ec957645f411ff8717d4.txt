#T8AH5: The `min` and `max` methods in `SearchContextStats` are logically broken. Both methods perform calculations to determine the minimum/maximum packed values from Lucene, update an internal cache (`stat.min = min[0]`), but then explicitly return `null` regardless of the result. Additionally, if multiple shards provide a value, they throw an `EsqlIllegalArgumentException` because the logic for comparing values across shards is not yet implemented (as noted in the TODO). These methods should either be fully implemented to return the calculated value or clearly marked as unsupported/returning null without attempting partial calculations that may crash.

#T8AH5: In `SearchContextStats.makeFieldConfig`, the loop initializes `hasIdenticalDelegate = true` and then sets it to `false` if any shard in the context does not have the field mapped or if the field is not a `TextFieldType`. While logically sound for safety, this results in a "pessimistic" view where a single shard missing a mapping disables the identical delegate optimization for the entire request. Given that ES|QL often deals with indices of varying mappings (e.g., across different time-based indices), it should be verified if this strictness is intended or if it will lead to unexpected performance degradation in heterogeneous environments.
