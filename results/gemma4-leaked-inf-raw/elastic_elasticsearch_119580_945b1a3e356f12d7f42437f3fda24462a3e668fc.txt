#7W49T, #NHPJK: The changes remove critical validation logic for Lookup Joins. Previously, the planner ensured that a `LookupJoinExec` targeted exactly one index and verified that this specific index was configured with `IndexMode.LOOKUP`. 
By removing these checks and relying solely on `localSourceExec.indexName()`, the code now allows plans targeting multiple indices (e.g., comma-separated lists) to proceed to the physical execution stage. This is a regression in validation that could lead to runtime failures in the underlying lookup service which expects a single index name.
