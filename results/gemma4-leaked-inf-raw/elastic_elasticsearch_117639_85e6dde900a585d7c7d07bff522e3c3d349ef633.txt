#GMBH8: In `computeOutput`, the arguments passed to `mergeOutputAttributes` appear to be swapped compared to the previous implementation of the `merge` method (which was removed in the same file) and standard join expectations. 
For a `LEFT` join, the code now calls `mergeOutputAttributes(rightOutputWithoutMatchFields, leftOutput)`. If this utility follows the same logic as the deleted `merge(left, right)`—where the first argument provides the base order and the second is appended/merged in—this will result in the right-side columns appearing before the left-side columns. This contradicts the previous behavior in both `Join.merge` and `Analyzer.resolveLookupJoin`, where the left side was prioritized first. The same inversion applies to the `RIGHT` join logic.
