#ZVWV6, #TRG4R, #6Q8NK, #A9DAW, #68XPA, #FHP73: In the `perPosition` method of the lazy evaluators (e.g., `CoalesceBooleanLazyEvaluator`), there is an inconsistency in how values are copied into the result builder. The first value from `lastFullBlock` is copied using the range-based API `copyFrom(lastFullBlock, p, p + 1)`, while subsequent values from other evaluators use the optimized single-position API `copyFrom(block, 0)`. To maintain consistency and performance—especially as noted in the comments in `Case.java` regarding the overhead of range copies—the first copy should also use the single-position `copyFrom` method.

#ZVWV6, #TRG4R, #6Q8NK, #A9DAW, #68XPA, #FHP73: The lazy evaluation path in `perPosition` creates a new `Page` object and filters every block in that page for every single position being evaluated:
```java
int[] positions = new int[] { p };
Page limited = new Page(
    1,
    IntStream.range(0, page.getBlockCount()).mapToObj(b -> page.getBlock(b).filter(positions)).toArray(Block[]::new)
);
```
This results in significant allocation pressure (O(N * M) where N is the number of positions and M is the number of blocks) when many positions require lazy evaluation. Consider if there is a more efficient way to evaluate a single position without reconstructing the `Page` and filtering all its underlying blocks repeatedly.
