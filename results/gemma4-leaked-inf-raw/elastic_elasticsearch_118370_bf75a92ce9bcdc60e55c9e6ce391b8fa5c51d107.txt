#1JD7R, #VG8DB: The use of a `ConcurrentMap` to store `SourceProvider` instances keyed by thread ID may lead to a memory leak if the `ReinitializingSourceProvider` instance is long-lived (e.g., shared across multiple queries). Since entries are never removed from the map, it will grow indefinitely as new threads are utilized. Consider using a `ThreadLocal<SourceProvider>` instead, which better aligns with the "per-thread" requirement and provides more standard lifecycle management.

#VG8DB: The `getSource` method is typically called in a tight loop for every document in a segment. Performing a map lookup via `computeIfAbsent` on every call introduces significant overhead (hashing and volatile reads) compared to using a `ThreadLocal` or a simple field access. Given the high frequency of this operation, switching to `ThreadLocal` would improve performance.
