#N55X8, #389YW, #TRPN9, #SKRDQ, #K1S08, #AYCXF: The changes move the responsibility of starting and ending object boundaries from `NestedObjectMapper` to the underlying `ObjectMapper` (when acting as a fragment). This allows empty nested objects to be correctly represented as `{}` in the synthetic source.

#TRPN9, #SKRDQ, #K1S08: In `NestedObjectMapper.java`, for the case where there is only one child (`children.size() == 1`), `b.startObject(leafName())` has been replaced with `b.field(leafName())`. This relies on the subsequent call to `leafSourceLoader.write()` (which uses an `ObjectMapper` fragment) to call `b.startObject()` and `b.endObject()`.
While this achieves the goal of allowing fragments to manage their own boundaries, it introduces a tight coupling between the parent's use of `b.field()` and the child's state as a fragment. If the loader were to use a non-fragment `ObjectMapper`, the resulting JSON would be invalid (e.g., `"path": "childName": { ... }`).

#AYCXF: The new test case `testSyntheticNestedWithEmptyObject` only verifies the scenario where nested fields are contained within an array (`b.startArray("path")`). It does not cover the single-element case (`children.size() == 1`), which is where the most significant logic change occurred in `NestedObjectMapper.java` (switching from `startObject(name)` to `field(name)`). I recommend adding a test case specifically for a single nested object to ensure that the combination of `b.field()` and the fragment's `b.startObject()` produces the expected `"path": { ... }` output.
