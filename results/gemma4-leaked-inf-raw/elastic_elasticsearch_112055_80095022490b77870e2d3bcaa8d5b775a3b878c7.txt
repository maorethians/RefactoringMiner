#RQ566: The implementation of `unsignedLongAsLongExact(long l)` appears to have its logic inverted. 
In Java, an unsigned long stored in a signed `long` variable $l$ fits into a signed `long` if and only if $l \ge 0$. If $l < 0$, the value is $\ge 2^{63}$ and cannot be represented as a positive signed `long`.
The current code throws an `ArithmeticException` when $l \ge 0$ (the safe case) and attempts to process the value via `twosComplement(l)` when $l < 0$ (the overflow case). It should instead return $l$ if $l \ge 0$ and throw the exception if $l < 0$.
