This renders the `transport.enable_stack_protection` setting ineffective as it does not influence the execution path.

#0Z2R3: The logic in `onConnectionClosed` contains a redundant and unreachable branch. The first `if` block ensures that if the executor is `EsExecutors.DIRECT_EXECUTOR_SERVICE`, it is replaced by `threadPool.generic()`. Consequently, the subsequent check `if (executor == EsExecutors.DIRECT_EXECUTOR_SERVICE)` will always evaluate to `false` (assuming `threadPool.generic()` does not return the direct executor), meaning the code will always enter the `else` block and perform an asynchronous execution via `executor.execute(...)`. This prevents any request from being handled directly on the calling thread, which appears to contradict the intent of the accompanying tests in `TransportServiceLifecycleTests.java`.
