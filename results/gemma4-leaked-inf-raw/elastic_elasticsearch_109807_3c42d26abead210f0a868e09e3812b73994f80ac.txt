#T2ADD: The refactoring of `computeOutput` introduces a regression in functionality for the `Join` class. The previous implementation supported multiple join types (`LEFT`, `RIGHT`, `FULL`, and default), whereas the new implementation throws an `UnsupportedOperationException` for any type other than `LEFT`. While this PR focuses on the `LOOKUP` command (which typically maps to a left join), removing support for other join types in a shared logical plan component may break other parts of the system that rely on these join types.

#27126: The use of a double cast `(List<Attribute>) (List)` to convert the result of `visitQualifiedNamePatterns` is a workaround for Java's generic type erasure and produces compiler warnings (hence the `@SuppressWarnings("unchecked")`). A cleaner, more type-safe approach would be to map the elements of the list:
```java
List<Attribute> matchFields = visitQualifiedNamePatterns(ctx.qualifiedNamePatterns(), ne -> { 
    /* ... existing checks ... */ 
}).stream().map(ne -> (Attribute) ne).toList();
```

#3MWTG: The `output()` method in `Lookup` now throws an `IllegalStateException` if `localRelation` is null. Previously, it provided a fallback using `Expressions.asAttributes(matchFields)`. This changes the behavior of the logical plan when queried before the relation is resolved. Ensure that this strict requirement for resolution is intended and does not break any existing analysis or optimization passes that might call `output()` on an unresolved node.
