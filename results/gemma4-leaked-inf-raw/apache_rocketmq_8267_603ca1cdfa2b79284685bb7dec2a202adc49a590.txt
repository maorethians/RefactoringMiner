#8G51T: The idempotency check inside the validation loop returns from the method immediately (`return response;`) if a topic configuration is found to be identical to the existing one. In a batch request, this means that if any single topic in the list is already up-to-date, all subsequent topics in the list will be ignored and not processed. This should be changed to skip the current iteration or filter out unchanged configurations before processing the list.

#8G51T: In the `finally` block, the metric attribute `LABEL_IS_SYSTEM` is set using `TopicValidator.isSystemTopic(topicNames)`. Since `topicNames` is a semicolon-separated string of all topics in the batch (e.g., `"TopicA;TopicB;"`), this check will not function correctly as `isSystemTopic` expects a single topic name.
