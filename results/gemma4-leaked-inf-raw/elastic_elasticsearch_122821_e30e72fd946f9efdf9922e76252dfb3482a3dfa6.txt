#5YV2J, #WTA4D, #HFHXE, #Z6SFB: The `writeTo` methods for these functions have been updated to serialize the actual source instead of `Source.EMPTY`. However, unlike the changes made to `BinarySpatialFunction`, `Replace`, `ToLower`, and `ToUpper`, these classes are missing corresponding updates to their constructors to read the source from the stream and lack version gating via `TransportVersions.ESQL_SERIALIZE_SOURCE_FUNCTIONS_WARNINGS`. 
This inconsistency will likely lead to `StreamInput` misalignment during deserialization, causing subsequent fields (e.g., `field`, `unit`) to be read incorrectly or triggering an `IOException`. This is particularly critical for rolling upgrades where nodes of different versions coexist in a cluster.
