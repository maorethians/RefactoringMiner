#E5H09, #ZD4YK: The current implementation uses manual string concatenation and a custom `escapeJson` method to generate JSON. This approach is fragile and incomplete:
1. **Missing Key Escaping**: Only the values are escaped; if a key contains a double quote or backslash, the resulting JSON will be malformed.
2. **Partial Control Character Coverage**: The `escapeJson` method only handles a subset of control characters. According to RFC 8259, all characters in the range `U+0000` through `U+001F` must be escaped.
3. **Maintainability**: Since Spring Boot already depends on Jackson, using an `ObjectMapper` or a similar standard JSON library would be more robust, secure, and maintainable than implementing custom escaping logic.
