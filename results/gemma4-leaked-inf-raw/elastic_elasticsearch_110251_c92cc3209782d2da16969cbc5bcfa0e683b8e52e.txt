#PJQT8: The validation logic used to detect if a sort field is part of a nested object is flawed. Using `field.startsWith(nestedObjectMapper.fullPath())` will cause false positives when a non-nested field shares a prefix with a nested field's name (e.g., if there is a nested field named `user` and a keyword field named `username`, sorting on `username` would incorrectly trigger this exception).
The check should ensure that the sort field is either exactly the nested field or starts with the nested field path followed by a dot separator:
`field.equals(path) || field.startsWith(path + ".")`.
