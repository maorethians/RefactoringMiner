#V560T: The loop in `consumerThread()` performs a busy wait when `consumer` is null. Since `consumer` is only set via `addMessageConsumer()`, this thread will consume 100% of a CPU core from the moment the server starts until a consumer is registered. Consider moving the `if (consumer != null)` check inside the `poll()` logic or using a synchronization primitive to wait for the consumer to be initialized.

#V560T: The `server` field is declared as `static`, but it is managed within the lifecycle methods (`before()` and `after()`) of an `ExternalResource` instance. If multiple instances of `ConsumingTestServer` are used across different test classes, they will overwrite the shared static reference, leading to unpredictable behavior during startup and shutdown (e.g., one test's `after()` method stopping another test's server). The `server` field should be an instance variable.

#V560T: In the `handle` method, `received.addAll(read)` is used to add messages to the `ArrayBlockingQueue`. Since `addAll` calls `add()`, it will throw an `IllegalStateException` if the queue reaches its capacity (1000 elements). For a test server, this might be acceptable, but using `offer()` in a loop or `put()` would be more robust.
