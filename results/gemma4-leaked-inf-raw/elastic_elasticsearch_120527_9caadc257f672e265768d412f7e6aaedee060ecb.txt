#Z55GT, #HKNEJ, #1ZVD3, #SWSHG, #HTY49: There is a potential `QlIllegalArgumentException` during the planning phase for certain commands.
In `LogicalPlanBuilder.plan()` (#HKNEJ), any plan node implementing `MetricsAware` is passed to `metrics.command(ma)`. The `PlanningMetrics.command()` method (#Z55GT) explicitly throws an exception if `command.metricName()` returns `null`.
However, `UnresolvedRelation` implements `MetricsAware` (#M1KQG) and its `metricName()` implementation (#1ZVD3) simply returns the internal `commandName` field. In `LogicalPlanBuilder`, both `visitMetricsCommand` (#SWSHG) and `visitJoinCommand` (#HTY49) instantiate `UnresolvedRelation` with a `null` name (specifically to avoid them being counted). 
Because these nodes are still `MetricsAware`, they will be passed to the metrics collector, which will then throw an exception because the name is null. To fix this, either `PlanningMetrics.command()` should handle null names gracefully (e.g., by ignoring them), or `UnresolvedRelation` should not implement `MetricsAware` if it's intended that some instances are "invisible" to metrics.
