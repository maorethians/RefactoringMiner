#CA09F, #YWP71: **Potential NullPointerException in `SandboxStash.listContentsRecursively`**
- In `SymlinkedSandboxedSpawn.filterInputsAndDirsToCreate` (ID `#YWP71`), the code populates an in-memory stash map and puts it into `SandboxStash`. Specifically, it executes:
  `main.dirEntries().put(SandboxStash.getWorkspaceName(), stashContentsMap.get(PathFragment.EMPTY_FRAGMENT));`
  If no inputs or outputs are present, `stashContentsMap.get(...)` returns `null`, resulting in a `null` value being stored for the workspace directory entry.
- Later, in `SandboxStash.listContentsRecursively` (ID `#CA09F`), when iterating through directories:
  ```java
  if (stashContents.dirEntries().containsKey(dirent.getName())) {
      listContentsRecursively(absPath, timestamp, stashContents.dirEntries().get(dirent.getName()));
  }
  ```
  If the value is `null`, the method is called with a `null` `stashContents` argument. This leads to an immediate `NullPointerException` when the code attempts to access `stashContents.filesToPath()` or `stashContents.dirEntries()` inside that recursive call.

#J15QH, #0NJSW, #YWP71: **Inconsistent use of `Optional` and `@Nullable`**
- The method `takeStashedSandboxInternal` is annotated with `@Nullable` and returns an `Optional<StashContents>`, but it frequently returns `null` instead of `Optional.empty()`. 
- Using `Optional` as a return type is intended to eliminate the need for `null` returns. Returning `null` from a method that returns `Optional` forces callers (like in `#YWP71`) to perform double-checks: first checking if the `Optional` itself is null, and then checking if it is present. The method should be updated to return `Optional.empty()` consistently.
