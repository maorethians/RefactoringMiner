#37DXE, #MXFSR: The `ResolveUnionTypes` rule now maintains state via the `unionFieldAttributes` instance variable. If this rule is instantiated as a singleton or shared across multiple plan analyses (which is common for analyzer rules), this will lead to race conditions and incorrect type resolution when multiple queries are analyzed concurrently. State should be passed through method arguments or encapsulated within a per-plan context object.

#7XJAN: The change from returning a list containing an `UnresolvedAttribute` with a descriptive message to throwing an `IllegalStateException` alters the error handling behavior. In ESQL analysis, returning unresolved attributes typically allows the system to collect and report all validation errors to the user in a single response. Throwing an exception will likely terminate the analysis immediately and result in a generic server-side error (e.g., HTTP 500) rather than a user-friendly query validation error.
