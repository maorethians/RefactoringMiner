#SBSRP: In `rewriteTopFieldGroups`, the `newGroupValues` array is initialized using the length of the original group values:
```java
var newGroupValues = new Object[originalTopGroups.groupValues.length];
```
However, it is populated based on the results of the rescoring process (`rescoredTopDocs.scoreDocs`). If the rescorer returns fewer documents than were originally present (e.g., due to a `window_size` limit), `newGroupValues` will contain trailing nulls and its length will mismatch the length of `newFieldDocs`. This likely violates the internal invariants of `TopFieldGroups`, where the score documents and group values arrays must be aligned in size.
The array should be initialized with `rescoredTopDocs.scoreDocs.length`.

#2NQBA: In the `RescorerRetrieverBuilder` constructor, the call to `super(...)` is performed before validating that the `rescorers` list is not empty:
```java
public RescorerRetrieverBuilder(RetrieverBuilder retriever, List<RescorerBuilder<?>> rescorers) {
    super(List.of(new RetrieverSource(retriever, null)), extractMinWindowSize(rescorers));
    if (rescorers.isEmpty()) {
        throw new IllegalArgumentException("Missing rescore definition");
    }
    this.rescorers = rescorers;
}
```
While not a functional bug, it is better practice to perform argument validation before invoking the super-constructor to avoid unnecessary object initialization when an exception is inevitable.
