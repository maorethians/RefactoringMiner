#TRJ5Y, #Y9C93: #### Correctness: Unicode Indexing Inconsistency
The implementation of `LOCATE` contains a logic error regarding Unicode handling. While it correctly uses code points to determine the search starting position (via `UnicodeUtil.codePointCount` and `offsetByCodePoints`), it returns the result based on Java's `String.indexOf()`, which returns a UTF-16 **char index** rather than a **code point index**.
In strings containing characters outside the Basic Multilingual Plane (e.g., emojis), a single code point is represented by two chars (a surrogate pair). Consequently, if such characters appear before the match, the returned position will be higher than the actual code point position. 
For example, in the string `"🐱Meow"`, the character `'M'` is the 2nd code point. However, `indexOf('M')` returns `2` (because the emoji occupies indices 0 and 1), resulting in a return value of `3`. This inconsistency is also reflected in the test case `locateUtf16Emoji` in `#Y9C93`, which expects a result of `3` for a match starting at the second code point.
To fix this, you should calculate the number of code points preceding the index returned by `indexOf()` using `utf8ToString.codePointCount(0, matchIndex)`.

#TRJ5Y, #WWP3T: #### Performance: Excessive String Allocations
The current implementation converts both the source string (`str`) and the substring (`substr`) from UTF-8 `BytesRef` to Java `String` objects on every single row processed in the evaluation loop. 
```java
// Inside Locate.process
String utf8ToString = str.utf8ToString();
return 1 + utf8ToString.indexOf(substr.utf8ToString(), ...);
```
This creates significant memory allocation pressure and GC overhead when processing large datasets. Since `substr` may be a constant literal for the entire block, it should ideally be converted once outside the loop or handled more efficiently. Even if both are dynamic, converting to strings on every row is expensive; consider using Lucene's `BytesRef` utilities or searching within the byte array where possible before falling back to string conversion for code point calculations.
