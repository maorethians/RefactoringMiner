#0236E, #JKPBW, #GBXEA: The new method `union(Set<T> first, Set<T>... others)` in `Sets.java` is introduced to handle multiple sets, but its usage in `BaseRestHandler.java` seems inconsistent and potentially incorrect. In `#JKPBW`, the union of `ALWAYS_SUPPORTED` and `supported` is being recalculated by including `RestResponse.RESPONSE_PARAMS`. This might lead to incorrect behavior if `RestResponse.RESPONSE_PARAMS` should not be part of the supported parameters in this context. The filter condition added in `#GBXEA` checks if a parameter is not in `RestResponse.RESPONSE_PARAMS`, but this check is redundant because it is already ensured that `allSupported` contains all valid parameters including `RestResponse.RESPONSE_PARAMS` and `ALWAYS_SUPPORTED`. The existing logic should suffice without this additional filter.

#ZJNBE: The introduction of `RESPONSE_PARAMS` in `RestResponse.java` is fine, but its usage needs to be consistent across the codebase. Ensure that all places where supported parameters are defined or checked include `RESPONSE_PARAMS` as necessary.
