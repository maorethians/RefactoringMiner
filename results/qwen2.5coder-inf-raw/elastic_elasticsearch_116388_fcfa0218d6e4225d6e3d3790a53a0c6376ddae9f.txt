#4D82D, #3BKJK, #3F62X, #RRYYD, #9M5GE, #BNA78, #PQYD2, #5MA3E, #C1C4H, #W0240, #0T3NF, #KD3JJ, #J3JWR: The changes introduce new fields `allowPartialSearchResults` and `allowPartialSequenceResults` to handle partial results in EQL searches. However, there are a few areas where the handling of these flags could be improved for correctness and maintainability:
- The `EqlSearchResponse` class now includes shard failures, but it does not consistently check if partial results are allowed before including them in the response. For example, in `createResponse`, the method should check if `allowPartialSearchResults` is true before including shard failures.
- In `TumblingWindow`, the `addShardFailures` method uses a `HashMap` to deduplicate shard failures by their string representation, which might not be the most efficient or accurate way to handle this. A more robust approach would be to use a set of unique shard failure objects.
- The `allowPartialSearchResults` and `allowPartialSequenceResults` flags are added to multiple classes but are not consistently used in all places where partial results could occur. For example, in `SampleIterator`, the flag is checked before adding shard failures, but it might be necessary to check this flag in other methods as well.
- The default values for these settings are set in `EqlPlugin` and retrieved using cluster settings. However, there should be a clear explanation of what these settings do and how they affect the behavior of EQL searches.
