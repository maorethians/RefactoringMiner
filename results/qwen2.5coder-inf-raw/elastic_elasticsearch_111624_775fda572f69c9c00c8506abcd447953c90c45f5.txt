#VM664, #HWSM3, #Z6RG9: The method `logWarningHeaderThresholdExceeded` is introduced to handle logging for both size and count threshold exceedances. However, the message pattern construction can be improved for clarity and consistency. Specifically, the use of `{}` in the message pattern should match the number of arguments provided. In the current implementation, when no headers are selected, an empty string is inserted instead of removing the placeholder, which might lead to confusion or incorrect log messages.

#KMVMA: In the test case `testDropWarningsExceedingMaxSettings`, the expected log message for "warnings too long" includes a specific request header content. This test assumes that the headers will be in a particular order and format when logged, which might not always be the case due to the nature of maps (unordered collections). It would be more robust to use a matcher that checks for the presence of key-value pairs rather than expecting an exact string match.
