#XJCGB, #Y3GV6, #T8ATK: The `SafeScheduledThreadPoolExecutor` is being used to manage scheduling tasks, but there are a few concerns:
1. The constructor of `SafeScheduledThreadPoolExecutor` only takes `corePoolSize` and `handler`, which means the maximum pool size and other parameters like keep-alive time are not configurable. This might limit flexibility.
2. In `#Y3GV6`, the executor is created with a core pool size of 1, but there's no indication of whether this is sufficient for all tasks or if it could become a bottleneck.
3. The rejection handler in `#Y3GV6` throws an exception when the executor is not shut down, which might be too aggressive and could lead to unexpected behavior if the executor is temporarily busy.

#1V3YR: The warning message "cannot add resource watcher, resource watcher service is closed" should be conditional on whether the `ResourceWatcherService` is indeed closed. Currently, it logs a warning every time a watcher is added, which might not be accurate or useful.
