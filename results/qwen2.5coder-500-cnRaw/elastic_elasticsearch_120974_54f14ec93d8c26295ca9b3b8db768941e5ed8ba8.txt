#BCR52, #EAW4C: The logic for marking fields as containing copied data has been moved from `IgnoredSourceFieldMapper#postParse` to `DocumentParserContext#createCopyToContext`. This change is mostly correct but introduces some redundancy and potential confusion. The comment in `createCopyToContext` suggests that ignored source values take precedence over the standard synthetic source implementation, which was previously handled in `postParse`. However, the logic for adding `NameValue` entries to `ignoredFieldValues` is now duplicated between these two methods.

#BCR52: The condition `if (mappingLookup.isSourceSynthetic() && indexSettings().getSkipIgnoredSourceWrite() == false)` should be checked before proceeding with the rest of the method. If `indexSettings().getSkipIgnoredSourceWrite()` is true, there's no need to add entries to `ignoredFieldValues`, and the method can return early.

#EAW4C: The removal of the loop that iterates over `context.getCopyToFields()` in `postParse` means that any copy-to fields added after the initial call to `createCopyToContext` will not be processed. This could lead to inconsistent behavior if copy-to fields are dynamically added or modified during parsing.
