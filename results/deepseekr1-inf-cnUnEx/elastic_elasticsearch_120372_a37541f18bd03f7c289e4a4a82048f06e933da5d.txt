The removal of the conditional check that returns `INDEX_METADATA_FIELD` when all field sets are empty could lead to an empty set of field names being returned in some cases. This might cause issues for downstream code that expects at least the index metadata field to be present.
The original code correctly handles the scenario where no fields are explicitly selected by falling back to the index metadata field. The updated code adds `INDEX_METADATA_FIELD` unconditionally, but this might not be necessary in all cases and could lead to redundant fields being requested.

// Original conditional check
if (fieldNames.isEmpty() && enrichPolicyMatchFields.isEmpty()) {
    return result.withFieldNames(IndexResolver.INDEX_METADATA_FIELD);
} else {
    // Add subfields and enrich fields
}
// Current implementation without conditional
