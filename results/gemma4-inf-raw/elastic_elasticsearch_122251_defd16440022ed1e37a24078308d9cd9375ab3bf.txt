#E6SD1, #C66PC: Broadening the exception catch from `ResourceAlreadyExistsException` to `ElasticsearchException` reduces the precision of the test. The test now passes if any `ElasticsearchException` is thrown, which could mask unrelated failures (e.g., internal server errors) and result in a false positive for the "duplicate request" scenario. If the underlying implementation now throws a different specific exception, it should be caught explicitly rather than using a generic parent class.
