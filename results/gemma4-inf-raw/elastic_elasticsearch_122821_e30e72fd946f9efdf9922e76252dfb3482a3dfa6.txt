#5YV2J, #WTA4D, #HFHXE, #Z6SFB: The serialization logic in these classes is updated to write the function source (`source().writeTo(out)`), but unlike other functions in this pull request (e.g., `BinarySpatialFunction` or `Replace`), they lack transport version guards. 
Writing a potentially non-empty `Source` where previously only `Source.EMPTY` was written changes the wire format. Without checking `out.getTransportVersion().onOrAfter(TransportVersions.ESQL_SERIALIZE_SOURCE_FUNCTIONS_WARNINGS)`, this will cause compatibility issues (e.g., `StreamCorruptionException`) when nodes of different versions communicate. Additionally, there are no corresponding updates to the constructors in these classes within this chapter to read the source back from the stream, which will lead to deserialization failures.
