#QJ3B4: The change replaces `context.functionRegistry()` with `context.functionRegistry().snapshotRegistry()`. This restricts implicit casting to only those functions defined in the snapshot registry, effectively disabling implicit casting for all standard functions that were previously supported by the main registry. Furthermore, if the system is not running in a snapshot build, this may result in a `NullPointerException` or trigger the `IllegalStateException` found in the `SnapshotFunctionRegistry` constructor.

#JY8P0, #C99B6, #V3KCB: The transition of `DATA_TYPES_FOR_STRING_LITERAL_CONVERSIONS` from a static map to an instance field (`dataTypesForStringLiteralConversions`) requires that every registry instance be explicitly initialized. While the population logic is now called in `SnapshotFunctionRegistry`, there is no corresponding initialization for the main `EsqlFunctionRegistry`. This will result in an empty conversion map for standard functions, breaking string literal conversions unless the main registry's initialization is handled outside this chapter.
