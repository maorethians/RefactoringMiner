#V4S3M: The `transform` method iterates over `patchersToApply` and calls `patchJar` for each matching configuration. Since `patchJar` always reads from the original `inputFile` and writes to a file with the same name (`...-patched.jar`), if multiple patcher configurations match a single JAR, only the changes from the last configuration in the list will be preserved in the final output. To support additive patching across different configurations, you should aggregate all applicable patches into a single map before calling `patchJar`.

#V4S3M: The use of `System.out.println` for logging "Patching ..." is generally discouraged in Gradle plugins and transform actions. It is better to use a proper logger to allow for better control over log levels and output formatting.
