#KCC2A: In the `finally` block of `readComplete`, there is a logic error when handling `Native.ERRNO_ECANCELED_NEGATIVE`. The code calls `doBeginReadNow()` unconditionally, and potentially twice if `pending` is true:
```java
if (pending) {
    doBeginReadNow();
}
doBeginReadNow();
```
Based on the accompanying comment, the read should only be rescheduled if the user signaled a desire to read again (`pending == true`). The trailing call to `doBeginReadNow()` should be removed.
