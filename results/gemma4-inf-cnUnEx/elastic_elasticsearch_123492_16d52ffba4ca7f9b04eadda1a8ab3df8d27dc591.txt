#QJ3B4, #JY8P0, #1CQEX: The transition from a static map (`DATA_TYPES_FOR_STRING_LITERAL_CONVERSIONS`) to an instance field (`dataTypesForStringLiteralConversions`), combined with the change in `Analyzer.ImplicitCasting#apply` to exclusively use the snapshot registry, appears to introduce a regression for non-snapshot functions. 
Previously, all registries shared the same static conversion data. Now, only the `SnapshotFunctionRegistry` populates this map (in `#1CQEX`), and the analyzer is hardcoded to use that specific instance (`#QJ3B4`). Consequently, any implicit casting logic relying on this map will fail for standard functions, as their registry instances will have empty conversion maps and are no longer passed to the `cast` method.
