#SH180: The logic change looks correct overall. The insertion branch now adds per-character offset corrections for each "extra" output character rather than a single correction at the end, which addresses the negative `startOffset` bug. The deletion branch is equivalent to the old behavior.
One observation: in the insertion branch, the loop `for (int i = 0; i < charDelta; i++)` calls `addOffCorrectMap` with values `lastDiff - i`. If `charDelta` is large (e.g., a single input character normalizes to many output characters), this produces many map entries. This is unlikely to be a practical concern for typical Unicode normalization, but it's worth being aware of if `addOffCorrectMap` has non-trivial cost per call.
