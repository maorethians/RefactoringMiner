#NYY4D: Changelog entry. Standard format, no issues.

#ZMDCC: The core logic change. The validation is now performed on `rankedDocs.size()` before extracting scores, rather than extracting first and then checking `scores.length`. This is a clean improvement: it avoids allocating the `float[]` when the count is wrong, and the error message is more actionable (references `rank_window_size`). The logic is equivalent to the old check since the old `extractScoresFromResponse` created the array with `new float[rankedDocs.size()]`.

#9WHFX: The `extractScoresFromResponse` method is refactored into `extractScoresFromRankedDocs`, which now accepts the already-extracted list. This is a straightforward and appropriate simplification that makes the method more focused and easier to unit-test in isolation.
