#1XBN9: The `dataStreamMigrationFailed` method throws an `ElasticsearchException` from within an `ActionListener` response callback. This causes the exception to be caught by the outer `ActionListener.wrap` and routed to `cancelExistingDataStreamMigrationAndMarkAsFailed`, which will attempt to cancel an already-failed migration before marking the task as failed. This is redundant and confusing. Consider calling `markAsFailed(ex)` directly instead of throwing, which is the pattern used consistently elsewhere in this class (e.g., `markAsFailed(e)` in the `migrateDataStream` failure handler).

#RY6NW, #43SHT: The `origin` parameter is stored without validation. For `Type.EXTERNAL` descriptors, a null origin will cause a `NullPointerException` later when `OriginSettingClient` is constructed during migration. Consider adding a `Objects.requireNonNull` check (at minimum for EXTERNAL type, mirroring the existing validation for `allowedElasticProductOrigins`) to fail fast at construction time.

#1XBN9: The `checkDataStreamMigrationStatus` method reschedules itself every 1 second when the migration is not yet complete, with no maximum retry count or overall timeout. If the underlying reindex task hangs, this will poll indefinitely. Consider adding a deadline (e.g., based on `TimeValue` or a max iteration count) so the task can fail with a clear timeout error rather than hanging forever.

#T11JZ: The method `recordIndexMigrationSuccess` now accepts `SystemResourceMigrationInfo` (covering both index and data stream migrations), but the name still references "Index". Consider renaming to `recordMigrationSuccess` to accurately reflect that it handles both resource types.

#WVHTD: Changing `allowRestrictedIndices` from `false` to `true` for the `kibana_system` user broadens its access to system/restricted indices. This is a security-sensitive change. Please ensure this is the minimal privilege needed for the data stream migration use case, and consider whether a more targeted permission (e.g., scoped to specific data stream actions) would be preferable to a blanket `allowRestrictedIndices(true)`.
