#2ZZ16: In `nextPhase`, the join-key matching loop silently skips any grouping attribute that has no name match on the right-hand side:
```java
for (Attribute lhs : groupingAttributes) {
    for (Attribute rhs : rhsOutput) {
        if (lhs.name().equals(rhs.name())) {
            leftFields.add(lhs);
            rightFields.add(rhs);
            break;
        }
    }
}
```
If a grouping column is missing from the aggregate output (e.g., due to a future rename or a bug), the join will silently use fewer keys than intended, producing a cross-product-like result rather than failing fast. Consider throwing an `IllegalStateException` (or at minimum logging a warning) when a grouping attribute has no corresponding right-hand attribute, so the mismatch is surfaced immediately.
