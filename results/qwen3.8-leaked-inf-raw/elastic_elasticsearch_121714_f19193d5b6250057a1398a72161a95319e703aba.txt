#NCKFP: The `fail()` message at the end of the retry loop reports `attempt`, but at that point `attempt` has already been incremented past `MAX_ATTEMPTS` (it equals 6). The message will read "giving up circuit breaking after 6 attempts" when only 5 were actually made. Consider using `MAX_ATTEMPTS` directly in the message, or restructuring the loop to avoid the off-by-one.

#G6G7H: The base value here is `500`, making the maximum across 5 attempts `2500`. However, the original test used `sortByManyLongs(5000)`, and the comment states "5000 is plenty to break on most nodes." Every other test in this file uses the *original* value as the base (e.g., `attempt * 2000` where the original was 2000, `attempt * 490` where the original was 490). This looks like a typo — the base should likely be `5000` (giving a max of 25000) to be consistent with the pattern and to actually reach the threshold the comment describes.

#5F01S: In `lookupExplosion`, the `finally` block only calls `deleteIndex("sensor_data")` but not `deleteIndex("sensor_lookup")`. The sibling method `lookupExplosionNoFetch` (in the same diff) deletes both indices. Since `lookupExplosionData` creates both `sensor_data` and `sensor_lookup`, the missing cleanup here leaks the `sensor_lookup` index across retry attempts and potentially across tests.
