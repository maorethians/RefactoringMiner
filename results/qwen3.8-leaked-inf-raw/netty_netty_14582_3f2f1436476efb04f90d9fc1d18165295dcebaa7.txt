#CFAMF: The Javadoc comment directly above this field states the maximum memory is `5 * NettyRuntime.availableProcessors() * MAX_CHUNK_SIZE` bytes, but with the new `Math.min(2, ...)` cap the actual maximum is `5 * 2 * MAX_CHUNK_SIZE` regardless of processor count. The comment is now misleading and should be updated to reflect the effective cap.
Additionally, `CENTRAL_QUEUE_CAPACITY` is a user-facing system property (`io.netty.allocator.centralQueueCapacity`). Silently clamping any user-supplied value above 2 to 2 without a warning log or documentation of the cap can be surprising for operators who explicitly configure this for high-core machines. Consider either:
- Logging a warning when the configured value exceeds the cap, or
- Documenting the hard cap in the Javadoc so users know the property is bounded.
