#58M8R: The `surrogate()` method in `Count` has a subtle logic path worth noting. When `field.foldable()` is true but `field` is neither a non-null scalar `Literal` nor a `List` literal (e.g., a foldable arithmetic expression like `1+1`), it falls through to the `Mul(Coalesce(MvCount(field), 0), Count(*))` path. This is correct, but the first `if` block only guards against *Literal* instances. A foldable non-Literal expression that evaluates to a non-null scalar (e.g., `COUNT(1+1)`) will produce `MvCount(1+1) * Count(*)` rather than simply `Count(*)`. This works correctly at runtime (since `MvCount(2)` = 1), but it's a slightly less optimal form than the TODO envisions. No action needed now, but the TODO comment could mention this case explicitly to avoid confusion for future readers.

#4HMVP: In `Median.surrogate()`, when `field` is foldable, the surrogate is `MvMedian(ToDouble(field))`. If `field` is a multi-value literal like `[-1, 0, 1, 3]`, this relies on `ToDouble` correctly mapping over the list elements. If `field` is a non-numeric foldable expression that somehow passes type resolution (unlikely given `Median`'s type constraints), `ToDouble` would fail at evaluation time. This is acceptable since the type system should prevent it, but it's worth confirming that `Median`'s `resolveType()` strictly enforces numeric input before this surrogate is ever reached.

#425RW: The simplification from checking distinct stat names to simply bailing on `stats.size() > 1` is correct. Since ES|QL requires unique stat aliases, the old special case (multiple stats with the same name) was unreachable for valid queries. The removed `Collectors` import in #Z0T5R is consistent with this change.

#F8KF2: Two minor observations in the test helper methods:
1. `assertAggOfConstExprs` mixes JUnit's `assertEquals` with Hamcrest's `assertThat`/`assertThat(..., instanceOf(...))`. While functionally fine, picking one assertion style per method improves readability and makes failure messages more consistent.
2. The method `oneLeaveIsNull` checks whether *any* leaf is null, not specifically "one." A name like `hasNullLeaf` or `anyLeafIsNull` would more accurately describe the predicate and avoid implying exactly one.

assertThat(plan.anyMatch(EsQueryExec.class::isInstance), is(true));
