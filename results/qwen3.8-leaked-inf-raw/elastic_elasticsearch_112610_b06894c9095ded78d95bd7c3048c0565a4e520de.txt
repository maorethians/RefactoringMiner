#R922Q: The indentation inside the `dependencies` block was changed from 4 spaces to 2 spaces, which is inconsistent with the surrounding file structure (the `apply` directives and the `dependencies {` keyword itself use no/standard indentation). This is a minor style inconsistency that will likely be flagged by the project's Gradle formatting checks or look out of place to reviewers.

#XKHF6: The old code used `indexOf(':')` to split on the *first* colon only. The new code uses `split(":")` which splits on *every* colon. While current ES type names don't contain colons, this is a subtle behavioral change. If a future type or header format ever includes a colon in the type portion, `header[1]` would only capture the segment before the second colon, silently truncating the type. Using `split(":", 2)` would preserve the original "split on first colon" semantics while still allowing the new logic.

#GVPP7, #Q0M7Y: In both `readMappingFile` (data loader) and `loadIndexResolution` (test), when a key from `typeMapping` is not found in the mapping/properties, it is silently ignored. For a test utility, this makes it difficult to diagnose why a type override isn't taking effect (e.g., a typo in the field name would produce a confusing "type not widened" test failure rather than a clear "field X not found in mapping" error). Consider logging a warning or throwing an `IllegalArgumentException` when a `typeMapping` key is absent from the mapping, to fail fast with a clear message.
