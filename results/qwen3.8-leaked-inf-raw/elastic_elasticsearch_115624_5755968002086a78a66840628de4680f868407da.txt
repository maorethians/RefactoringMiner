#GZWR9: In the new `MvExpand` branch of `PushDownAndCombineLimits`, the limit value is obtained via `(int) limitSource.fold()`. If `fold()` ever returns a value exceeding `Integer.MAX_VALUE` (e.g., a very large literal), this cast silently overflows to a negative number. The subsequent guard `mvxLimit < 0` would then treat it as "no limit" and overwrite it, but the `Limit` node pushed below would still carry the original (potentially huge) value, creating an inconsistency. In practice ES|QL limits are bounded well below `Integer.MAX_VALUE`, so this is unlikely to manifest, but a defensive check (e.g., `Math.toIntExact` or an explicit range check) would make the intent clearer and avoid a silent misbehavior if the bound is ever raised.
