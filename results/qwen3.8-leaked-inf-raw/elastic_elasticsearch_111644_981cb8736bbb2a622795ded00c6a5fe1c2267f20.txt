#QAHBJ, #MZV8P, #Y18N3, #W1XFX, #SJD7S: The change to `useAlternatingSort` from `true` to `false` is a public field default change. Since `MergingDigest` is in a `libs` module, other modules or downstream consumers may rely on the previous default. Consider whether this should be a deprecation cycle rather than a silent default flip, or at minimum document the behavioral change in the changelog entry (the current summary only mentions "Force using the last centroid during merging" and doesn't mention the alternating-sort default change).

#Y18N3: The new guard `if (lastUsedCell == mean.length - 1)` unconditionally sets `addThis = true`, overriding the immediately preceding `addThis = false` set by the `i == 1 || i == incomingCount - 1` check. This is presumably intentional (the last centroid must always be preserved), but the interaction is subtle: for the **first** centroid (`i == 1`), if `lastUsedCell` happens to equal `mean.length - 1` (e.g., a single-centroid digest), the "never merge" intent for the first centroid is silently overridden. A brief comment explaining why the last-centroid rule takes precedence over the first/last "never merge" rule would help future readers.

#W1XFX: The test uses `between(0, 3_600_000)` which produces random values on each run, making the test non-deterministic. While the assertions are loose enough to be unlikely to fail, a seeded or fixed dataset (or at least a fixed random seed) would make the test reproducible and easier to debug if it ever does fail in CI.
