#FNSYY, #1AC98: The field `private Runnable isCancelled` and the setter parameter `Runnable isCancelled` are misleadingly named. The name `isCancelled` reads as a boolean state (e.g., `boolean isCancelled`), but the type is a `Runnable` representing an action to perform. A name like `cancellationChecker` or `cancellationCheck` would better convey that this is a callable check, not a state flag. This matters for maintainability since `checkCancellation()` calls `isCancelled.run()`, which is confusing when the field name suggests a predicate rather than an action.

#E6ME6, #P1F55: The constant `MAX_CALLS_BEFORE_QUERY_TIMEOUT_CHECK = 10` is duplicated in both `QueryRescorer` (server module) and `LearningToRankRescorer` (x-pack module). I understand this may be intentional to avoid cross-module dependencies, but it's worth noting that if the check frequency needs to be tuned, both locations must be updated in lockstep. A brief comment referencing the other location (or a shared constant in a common module if one exists) would reduce the risk of them drifting apart.

#2RF6E: In the test's `TimedQuery`, the `Scorer.explain()` method returns `null`. If any code path in the rescore flow (e.g., a debug/explain request, or an assertion in a test framework) attempts to use the returned `Explanation`, this will cause a `NullPointerException`. Consider returning `Explanation.noMatch("timed query")` or a similar non-null value to be safe, even in a test utility class.

#RJK2P: The `ctx.setCancellationChecker(null)` call after `rescore()` will not execute if `rescore()` throws an exception (including the `TimeExceededException` that is the primary new path). While this is likely harmless since the `RescoreContext` is not reused after an exception, wrapping the rescore call in a try/finally would make the cleanup deterministic and guard against any future code that might inspect the context after a failed rescore:
```java
try {
    topDocs = ctx.rescorer().rescore(topDocs, context.searcher(), ctx);
} finally {
    ctx.setCancellationChecker(null);
}
```
