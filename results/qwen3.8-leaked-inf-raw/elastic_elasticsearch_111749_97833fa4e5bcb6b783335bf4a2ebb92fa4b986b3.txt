#V9347: There is a critical index bug in the sorted-ascending fast path of all three `process*` methods. When `valuesBlock.mvSortedAscending()` is true, the code reads values using indices relative to the start of the block rather than relative to the current position's first value:
```java
if (valuesBlock.mvSortedAscending()) {
    if (percentile == 0) {
        builder.appendDouble(valuesBlock.getDouble(0));  // should be firstValueIndex
    } else if (percentile == 100) {
        builder.appendDouble(valuesBlock.getDouble(valueCount - 1));  // should be firstValueIndex + valueCount - 1
    } else {
        var result = calculateDoublePercentile(fraction,
            valuesBlock.getDouble(lowerIndex),   // should be firstValueIndex + lowerIndex
            valuesBlock.getDouble(upperIndex));  // should be firstValueIndex + upperIndex
        builder.appendDouble(result);
    }
}
```
Compare with the non-sorted path which correctly uses `firstValueIndex + i`. The same bug exists in `processInts` (using `valuesBlock.getInt(0)`, `valuesBlock.getInt(lowerIndex)`, etc.) and `processLongs` (using `valuesBlock.getLong(0)`, `valuesBlock.getLong(lowerIndex)`, etc.).
This will produce incorrect results whenever the page has more than one row and the current position `p > 0`, because it will read values belonging to a different row. The fix is to add `firstValueIndex` to every index used in the sorted path, e.g.:
```java
builder.appendDouble(valuesBlock.getDouble(firstValueIndex));
builder.appendDouble(valuesBlock.getDouble(firstValueIndex + valueCount - 1));
calculateDoublePercentile(fraction,
    valuesBlock.getDouble(firstValueIndex + lowerIndex),
    valuesBlock.getDouble(firstValueIndex + upperIndex));
```

#V9347: The `foldable()` method only checks the `field` child:
```java
@Override
public boolean foldable() {
    return field.foldable();
}
```
It should also check `percentile.foldable()`. If the percentile argument is a non-foldable expression (e.g., a column reference), the entire expression cannot be constant-folded at plan time. The correct implementation is:
```java
return field.foldable() && percentile.foldable();
```
