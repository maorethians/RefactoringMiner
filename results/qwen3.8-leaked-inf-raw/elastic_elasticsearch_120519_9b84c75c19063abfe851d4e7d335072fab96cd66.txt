#PEBE5: The `makeDirectoryWith` helper unconditionally calls `writer.forceMerge(1)`. The original `testQueries` did not call `forceMerge` (only `testRandomMatchQueries` did). While this shouldn't change correctness (doc IDs remain 0–4 in a single segment), it is a subtle behavioral difference in the test setup. If a future test relies on multi-segment behavior (e.g., testing cross-segment search), this helper would not support it. Consider whether `forceMerge` should be a parameter or whether a separate helper without it is needed.

#9FM44, #6NGR7: The `mvJoinKeyFromRow` test now requires both `join_lookup_v11` and `join_lookup_skip_mv`, and its expected output changed from 4 matching rows to a single null row. This means the previous multi-value-matching behavior for this scenario is no longer covered by any test case in the spec. Since `JOIN_LOOKUP_SKIP_MV` is defined as dependent on `JOIN_LOOKUP_V11`, they will always be enabled together in practice, so this is likely fine. However, if there is ever a deployment where `join_lookup_v11` is on but `join_lookup_skip_mv` is off (e.g., a partial upgrade), the old behavior would be untested. Worth confirming this scenario is intentionally unsupported.
