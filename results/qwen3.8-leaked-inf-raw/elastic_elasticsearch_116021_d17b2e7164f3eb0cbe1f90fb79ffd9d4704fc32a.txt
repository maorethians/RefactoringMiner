#YRM8J: `testNoIndices()` and `testNoIndicesIgnoreUnavailable()` are functionally identical in effect. Both call `prepareFieldCaps()` without naming any specific index, so the closed `old_index` is excluded by `expandWildcardsClosed = false` during wildcard resolution. The `ignoreUnavailable` flag only takes effect when a closed index is *explicitly named* in the request (as in `testOneClosedIndex` / `testTwoIndicesOneClosed`). Since the closed index never enters the resolved set in these two tests, toggling `ignoreUnavailable` changes nothing, and both tests exercise the same code path. Consider either removing one of them or renaming them to make the intent clearer (e.g., `testWildcardExcludesClosedIndex`), so a reader doesn't assume the `ignoreUnavailable` flag is being meaningfully exercised here.

#CFZKV, #YRM8J: All the new integration tests explicitly set `IndicesOptions` via the new `setIndicesOptions(...)` builder method, so none of them actually exercise the changed **default** (`strictExpandOpenAndForbidClosed()`). A test that closes an index, calls `prepareFieldCaps("old_index").setFields("*")` *without* calling `setIndicesOptions`, and asserts an `IndexClosedException` would directly verify the new default and guard against a future regression of the constant.
