#3QRNQ, #E5V36, #S4NN6, #8CK5X: The `concreteIndices()` method in `EsRelation` returns `indexNameWithModes.keySet()`, which is a live view backed by the underlying map. While all current call sites only read from it (`.isEmpty()`, `.addAll()`, assignment to a `Holder`), returning a mutable view from a getter is a subtle footgun. If a future caller mutates the returned set, it would corrupt the internal state. Consider returning `Set.copyOf(indexNameWithModes.keySet())` or documenting that the returned set must not be modified. This is low-risk given the current usage but worth a defensive note.

#C4SJ6: In `EsSourceExec.writeTo()`, the backward-compatible path constructs `new EsIndex(indexName, Map.of(), indexNameWithModes)` on every serialization to an older peer. This allocates a throwaway object per write. While not a hot path in practice, if this class is serialized frequently in mixed-version clusters, it could add minor GC pressure. This is acceptable for a compatibility shim, but worth being aware of.
