#XA1GX: `testReadEmpty` only exercises the non-empty path (where `readBoolean()` returns `true` and three ints are consumed). The early-return branch (`readBoolean() == false` → return `EMPTY` immediately) is never hit. Adding a case that writes `Source.EMPTY` and then a sentinel int, and asserts both `readEmpty` returns `EMPTY` and the sentinel is still readable, would close that gap and guard against a future regression where someone accidentally adds a read in the empty branch.
