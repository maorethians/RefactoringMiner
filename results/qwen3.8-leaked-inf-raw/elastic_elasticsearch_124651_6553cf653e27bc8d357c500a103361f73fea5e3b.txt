#SE3A6, #D66H0: Potential `NullPointerException`: `dataStreams.stream().map(project.dataStreams()::get).collect(Collectors.toSet())` will produce a `Set<DataStream>` containing `null` for any name not present in the project. Downstream in `MetadataDataStreamsService.deleteDataStream`, the call `dataStreams.stream().map(DataStream::getName)` will NPE on the null element. The original code at least had `assert dataStream != null;` as a guard, but that assert is placed *after* the stream operation that would already NPE, so it is ineffective. Consider filtering out nulls (`.filter(Objects::nonNull)`) or throwing a meaningful `IndexNotFoundException` for missing data streams before passing the set to the service method.

#CHYVZ: `testSystemDataStreamAliasesAreAlwaysRestored` is annotated with a commented-out `@AwaitsFix` and a TODO noting it is failing. As written, this test will execute and fail in CI, breaking the build. Either uncomment the `@AwaitsFix` annotation (or use `@AwaitsFix` with the appropriate bug URL) so the test is properly skipped, or remove the test until the underlying issue is resolved.

#D66H0: The method naming is misleading: `deleteDataStream` (singular) accepts a `Set<DataStream>` and handles multiple data streams, while `deleteDataStreams` (plural) also accepts a `Set<DataStream>`. The singular/plural distinction does not convey the actual difference (project-level vs. cluster-level operation). Consider renaming to something like `deleteDataStreamsFromProject` / `deleteDataStreamsFromCluster`, or making both plural and differentiating by parameter type in the name.

#D0J22: `resolveSystemDataStreamsToDelete` performs two separate map lookups per data stream name (`containsKey` followed by `get`). This can be simplified to a single `get` with a null-check filter:
```java
.map(dataStreamName -> currentState.metadata().getProject().dataStreams().get(dataStreamName))
.filter(Objects::nonNull)
```
This avoids the redundant lookup and is also more robust if the map implementation has any edge-case behavior with `containsKey` vs `get`.
