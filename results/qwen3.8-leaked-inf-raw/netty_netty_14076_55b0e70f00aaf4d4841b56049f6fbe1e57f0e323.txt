#B0YHF, #DQ2PK, #RRJR7: The new `ReadOnlySlicedByteBuf` and `ReadOnlyDuplicatedByteBuf` inner classes (in `ReadOnlyByteBufferBuf`) extend the standard writable `SlicedByteBuf` / `DuplicatedByteBuf` and only override `isWritable()` / `isWritable(int)` to return `false`. However, they do **not** override the actual write methods (`setByte`, `writeByte`, `setInt`, `writeLong`, etc.) to throw `UnsupportedOperationException`. In Netty's `AbstractByteBuf` hierarchy, write methods do not internally check `isWritable()` before mutating — they perform the write directly. This means a caller that invokes a write method without first checking `isWritable()` will silently succeed in mutating a buffer that is contractually "read-only."
The previous implementation (`new ReadOnlyByteBufferBuf(allocator, buffer)`) presumably inherited write-guarding from `ReadOnlyByteBufferBuf` itself. The new approach provides a weaker guarantee. Consider either:
- Extending a common read-only base that throws on all write operations, or
- Overriding the write methods in both inner classes to throw `UnsupportedOperationException`.
