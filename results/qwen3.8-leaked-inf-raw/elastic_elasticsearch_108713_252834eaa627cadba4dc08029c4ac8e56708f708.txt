#PKZS8: Rule scope is `Eval`-only: The rule extends `OptimizerRule<Eval>`, so it only fires when the convert function sits inside an `Eval` node. In the `stats centroid = st_centroid_agg(to_geopoint(location))` case this works because the planner materialises the conversion as a separate `Eval` below the `Aggregate` (visible in the old nested test's pre-optimisation plan). If a future planner change inlines the conversion directly into the aggregate expression (bypassing an `Eval`), this rule would silently stop applying. A brief comment on the rule noting this dependency on the planner emitting an `Eval` for the conversion would help future maintainers.
