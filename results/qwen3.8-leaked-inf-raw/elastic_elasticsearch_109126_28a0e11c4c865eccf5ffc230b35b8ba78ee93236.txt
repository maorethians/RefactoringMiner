#0C4MT: The `ingest_time` column previously emitted a `TimeValue` (e.g. `"1.5s"`), but now emits a raw `long` millisecond value. This is a user-visible change in the `_cat` API output format. While it's understandable that `TimeValue` objects can't be trivially summed across deployments, the change should be called out explicitly (e.g. in the changelog or a release note) since downstream consumers parsing the `_cat` response may break. If the intent is to keep the human-readable format, consider formatting the accumulated millis back into a `TimeValue` before adding the cell.

#CC1YB: The test method is named `testAddTrainedModelStatsHandlesMultipleDeployments`, but it only creates a single `TrainedModelStats` entry for model `"id1"`. This does not exercise the duplicate-key merge path (`(stats1, stats2) -> stats1`) that the PR is fixing. To actually validate the fix, the test should include two `TrainedModelStats` entries sharing the same model ID `"id1"` in the `statsResponse`, and assert that the result is still correct (i.e., no `IllegalStateException` is thrown and the expected memory value is reported).
