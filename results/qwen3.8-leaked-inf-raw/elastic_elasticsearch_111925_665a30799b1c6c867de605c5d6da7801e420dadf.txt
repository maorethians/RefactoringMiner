#JBRVD: **Bug: In-place reassignment of `floatArraySupplier` makes the ternary a no-op after the first iteration.**
`floatArraySupplier` is a method parameter. On the first loop iteration (`sim == COSINE`), it is reassigned to `FLOAT_ARRAY_RANDOM_FUNC`. On every subsequent iteration (`DOT_PRODUCT`, `EUCLIDEAN`, `MAXIMUM_INNER_PRODUCT`), the "else" branch of the ternary reads `floatArraySupplier` — which is now already `FLOAT_ARRAY_RANDOM_FUNC`. So all four similarities end up using the same supplier, defeating the intent of the conditional.
Fix: introduce a local variable so the original parameter is preserved:
```java
final Function<Integer, float[]> supplier = sim == COSINE ? FLOAT_ARRAY_RANDOM_FUNC : floatArraySupplier;
```
…and use `supplier` in the rest of the loop body instead of `floatArraySupplier`.
