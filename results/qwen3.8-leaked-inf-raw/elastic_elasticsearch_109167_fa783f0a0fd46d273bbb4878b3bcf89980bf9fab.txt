#SZWAJ, #Q2S87, #1H1QJ: The `ConstructingObjectParser` is declared to expect an object with a `"role_mappings"` array field (via `declareObjectArray(constructorArg(), ..., new ParseField(TYPE))`). However, when `RoleMappingMetadata` is parsed through the `NamedXContentRegistry` during `Metadata` deserialization, the parser is typically positioned at the *value* of the `"role_mappings"` field (i.e., at `START_ARRAY`), not at a wrapping object. The `ConstructingObjectParser.apply()` method expects `START_OBJECT` as the first token.
The `AbstractXContentSerializingTestCase` in #M68C1 performs a direct `toXContent` → `fromXContent` round-trip, which may produce/consume the full `{"role_mappings": [...]}` object and thus pass. But the actual `Metadata` parsing path (where the registry dispatches to `fromXContent` with the parser already advanced past the field name to the array value) may not be exercised by that unit test.
Please verify that the integration test (#9329Z) actually exercises the `Metadata` XContent deserialization path (not just the transport/stream serialization path). If the `FileSettingsService` recovery path uses stream-based deserialization (`StreamInput`) rather than XContent parsing, the `ConstructingObjectParser` may never be invoked in the registry context, and the bug would remain latent. If it *is* invoked, the parser position mismatch would cause a `XContentParseException`.

#M68C1: The `assertEqualInstances` method compares all fields except `name`, which is correct given the documented limitation. However, the comparison uses a nested loop with `found |=` which is O(n²). For the test sizes involved (0–3 elements) this is fine, but a `Set`-based or stream-based approach would be more idiomatic and scale better if the random set size is ever increased.

#9329Z: The test is thorough, but the repeated blocks that construct expected `ExpressionRoleMapping` objects (appearing 4 times with slight variations) could be extracted into a small helper to reduce duplication and the risk of a copy-paste error in the expected values. For example, a helper like `expectedMapping(String name, List<String> roles, Map<String,String> metadata, boolean enabled)` would make the assertions more readable and easier to keep in sync with the JSON fixture.
