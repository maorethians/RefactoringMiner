#GHPXF, #YR5ST, #MA4CR, #DVQCG, #0H63S, #694Y8, #D12YV, #182NG, #XP7RZ: Looking at this PR, it introduces two dynamic index settings (`skip_ignored_source_write` and `skip_ignored_source_read`) as a safety net to disable the ignored source field mechanism. The changes thread `IndexSettings` through several mapper classes that previously didn't need it.
**1. NPE risk in `SourceLoader.Synthetic` constructor when `indexSettings` is null**
The constructor unconditionally calls `indexSettings.getSkipIgnoredSourceRead()`:
```java
if (indexSettings.getSkipIgnoredSourceRead() == false) {
    this.requiredStoredFields.add(IgnoredSourceFieldMapper.NAME);
}
```
However, several test call sites pass `null` as the `indexSettings` to `NestedObjectMapper.Builder`, which flows into `syntheticFieldLoader()` → `new SourceLoader.Synthetic(..., indexSettings, NOOP)`. While the specific tests that pass `null` (e.g., `NestedLookupTests`, `FieldAliasMapperValidationTests`, `AbstractSortTestCase`, `NestedAggregatorTests`) don't appear to invoke the synthetic source path, this is a latent NPE that would surface if any code path on those mappers ever calls `syntheticFieldLoader()`.
Consider adding a null guard in the `SourceLoader.Synthetic` constructor (e.g., `if (indexSettings == null || indexSettings.getSkipIgnoredSourceRead() == false)`) or asserting non-null at the `NestedObjectMapper.syntheticFieldLoader()` call site to fail fast with a clear message rather than a bare NPE.

#7HM2C, #41YGQ: **2. `IgnoredSourceFieldMapper` stores `indexSettings` but it appears unused in the shown code**
The field `private final IndexSettings indexSettings` is added and set in the constructor, but none of the visible methods (`valueFetcher`, `parse`, etc.) reference it. The actual skip logic lives in `DocumentParserContext` and `SourceLoader.Synthetic`, which obtain settings from their own references. If this field is not used by any method outside the shown hunks, it is dead state that adds confusion about where the setting is actually consulted.
If the field is genuinely unused, consider removing it to avoid the impression that `IgnoredSourceFieldMapper` itself enforces the skip behavior. If it is used in a method not shown in this diff, no action is needed.

#JATED, #RQ539, #GHPXF: **3. Minor: `== false` on a boolean getter**
Throughout the diff, the pattern `indexSettings().getSkipIgnoredSourceWrite() == false` is used. Since the getter returns a primitive `boolean`, the idiomatic form is `!indexSettings().getSkipIgnoredSourceWrite()`. This is a style nit and the existing codebase may prefer the explicit comparison, so this is optional.
