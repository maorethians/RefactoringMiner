#PPE9V, #YVBF2: Both `EndsWith.asQuery()` and `StartsWith.asQuery()` use `FoldContext.small()` as a placeholder with a TODO comment. While `translatable()` already guarantees the expression is foldable (i.e., a literal), relying on a "small" fold context is fragile. If the folding logic ever needs context (e.g., for type resolution or field-aware folding), this will silently produce incorrect results. Consider either:
- Passing the real `FoldContext` through the `TranslatorHandler` (which likely already has access to it), or
- Asserting that the expression is a `Literal` and reading its value directly, bypassing `fold()` entirely.
This avoids the dependency on fold-context semantics for what is effectively a constant extraction.

#RBNXP, #KS4H9: The test method names `testLuceneQuery_NonFoldableSuffix_Translatable` (EndsWith) and `testLuceneQuery_NonFoldablePrefix_Translatable` (StartsWith) are misleading. Both tests construct a `Literal` as the suffix/prefix, which **is** foldable — the test is verifying the *positive* (translatable) path. The "NonFoldable" in the name contradicts what the test actually exercises. Suggested renames:
- `testLuceneQuery_FoldableSuffix_Translatable`
- `testLuceneQuery_FoldablePrefix_Translatable`
This prevents confusion when reading the test suite, since the sibling test `testLuceneQuery_NonFoldableSuffix_NonTranslatable` correctly uses a `FieldAttribute` (non-foldable) and asserts non-translatability.
