#9V489: The guard clause is a good addition — it prevents a less informative `NullPointerException` or connection failure downstream when `brokerAddr` resolves to null/blank.
One minor concern: the error message is slightly misleading in the branch where `brokerName` is `null`. In that path, `brokerAddr` is derived from `msg.getStoreHost()` via `RemotingHelper.parseSocketAddressAddr(...)`, so the failure is about an unparseable or missing store host, not about a "master node does not exist." The message would read `"Broker[null] master node does not exist"`, which could confuse operators debugging the issue.
Consider differentiating the message based on which path produced the blank address, e.g.:
```java
if (UtilAll.isBlank(brokerAddr)) {
    String reason = (brokerName != null)
        ? "Broker[" + brokerName + "] master node does not exist"
        : "Store host [" + msg.getStoreHost() + "] is not a valid address";
    throw new MQClientException(reason, null);
}
```
This is a minor readability/clarity point; the functional guard itself is correct and well-placed.
