#CRWXD, #HSG91, #8DFE5: The changes are a clean refactoring that extracts a hardcoded scheduling period into a configurable field. The default value (`1000 * 120` = 120 s) matches the previously hardcoded `1000 * 60 * 2`, so behavior is preserved. Naming, Javadoc, and getter/setter all follow the existing `BrokerConfig` conventions (e.g., `registerNameServerPeriod`).
One minor observation: the setter performs no validation. If an operator sets a value ≤ 0, `ScheduledExecutorService.scheduleAtFixedRate` will throw `IllegalArgumentException` at startup, which is a hard-to-diagnose failure. That said, this is consistent with how other period fields in `BrokerConfig` (e.g., `registerNameServerPeriod`) are handled, so it is not a regression. If the project ever adds a centralized validation pass for `BrokerConfig`, this field should be included.
No other correctness, thread-safety, or performance concerns are apparent for this chapter.
