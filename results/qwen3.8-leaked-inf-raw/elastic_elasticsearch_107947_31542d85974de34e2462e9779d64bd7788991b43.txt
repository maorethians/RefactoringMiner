#82V9B: In `testSerializationWithConfig()`, the expression is built with a random `config`, but then `assertSerialization(expr)` is called without passing that configuration. Looking at `SerializationTestUtils`, the no-arg overload delegates to `assertSerialization(expr, EsqlTestUtils.TEST_CFG)`. If the `EsqlConfiguration` is not serialized as part of the expression's byte stream but is instead supplied externally during deserialization (as suggested by the `CsvTests` change passing `configuration` explicitly), then the deserialized expression will carry `TEST_CFG` while the original carries the random `config`. The subsequent `checkEqualsAndHashCode` call would then compare two expressions with different configurations and fail, since `EsqlConfigurationFunction.equals` now compares `configuration`.
Consider changing:
```java
assertSerialization(expr);
```
to:
```java
assertSerialization(expr, config);
```
so that the deserialization context matches the configuration used to build the expression.
