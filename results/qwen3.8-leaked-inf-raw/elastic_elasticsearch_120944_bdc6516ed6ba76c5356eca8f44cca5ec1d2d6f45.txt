#7BJ2B: In `testTerms`, the success path asserts `assertMap("not expected to finish", response, matchesMap())` — i.e., it expects an *empty* response body. A successful search with `size: 0` and a terms aggregation will return a non-empty body (with `_shards`, `hits`, `aggregations`, etc.), so this assertion will always fail if the request completes. The intent is clearly "the request should not complete within the timeout," but the assertion message and the empty-map matcher are misleading. A clearer approach would be to simply `fail("Expected SocketTimeoutException but request completed")` in the try block, making the test's expectation explicit.
