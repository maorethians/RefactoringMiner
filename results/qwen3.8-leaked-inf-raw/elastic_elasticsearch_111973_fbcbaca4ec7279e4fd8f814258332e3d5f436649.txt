#8CTG3: The two branches handle ordering inconsistently: when the set has ≤ 3 elements, the natural iteration order of the `Set` is used (insertion order for `LinkedHashSet`, undefined for `HashSet`); when it has > 3 elements, the output is sorted. This means the same three indices could appear in different orders depending on whether a fourth index is present or not. For deterministic output in both branches, consider sorting in the ≤ 3 case as well:
```java
if (e.getValue().size() <= 3) {
    errorMessage.append(e.getValue().stream().sorted().collect(Collectors.toList()));
} else {
    ...
}
```
This is a minor UX/consistency point rather than a correctness bug, but it avoids surprising users who see the same indices listed in different orders across slightly different queries.
