#V5WWT: The `userEventTriggered` override silently swallows all user events that are not `SslCloseCompletionEvent`. The default implementation in `ChannelHandlerAdapter` (which this class almost certainly inherits from, given it's a `ChannelDuplexHandler`/`ChannelInboundHandlerAdapter`) forwards the event via `ctx.fireUserEventTriggered(evt)`. By overriding without calling `super` or forwarding, any other user events (e.g., `ChannelInputShutdownEvent`, custom events) will be dropped before reaching downstream handlers in the pipeline.
Suggested fix:
```java
@Override
public void userEventTriggered(ChannelHandlerContext ctx, Object evt) throws Exception {
    if (evt instanceof SslCloseCompletionEvent closeEvent) {
        if (closeEvent.isSuccess() && ctx.channel().isActive()) {
            logger.trace("received TLS close_notify, closing connection {}", ctx.channel());
            ctx.close();
        }
    } else {
        super.userEventTriggered(ctx, evt);
    }
}
```
