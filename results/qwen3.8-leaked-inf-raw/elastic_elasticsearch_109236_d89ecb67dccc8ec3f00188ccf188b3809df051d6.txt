#57K0W: In the non-DIRECT executor branch, if `handler.handleException(exception)` throws inside `doRun()`, the exception is handled by whatever `ForkingResponseHandlerRunnable`/`AbstractRunnable` provides by default (typically rethrown into the executor's task wrapper). The old code had an explicit `onFailure` that logged a warning with the connection context. Consider adding an `onFailure` override in the anonymous subclass to preserve that diagnostic logging, especially since the connection object is in scope and useful for debugging:
```java
executor.execute(new ForkingResponseHandlerRunnable(handler, exception) {
    @Override
    protected void doRun() {
        handler.handleException(exception);
    }
    @Override
    public void onFailure(Exception e) {
        logger.warn(() -> "failed to notify response handler on connection close [" + connection + "]", e);
    }
});
```
This matches the error-handling pattern already used in the DIRECT + avoidance branch just above it.
