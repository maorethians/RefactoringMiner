#BAS90: The old `Sync.result()` had a `default` branch that threw `IllegalStateException` unconditionally (after the `assert false`). The new code relies solely on `assert isDone()` and then calls `getValue()`. When assertions are disabled (production), an invalid synchronizer state will fall through to `getValue()` rather than throwing a clear `IllegalStateException`. If `getValue()` doesn't itself guard against invalid states, this could lead to a less obvious failure (e.g., `NullPointerException` on a null `value` field) in production. Consider whether a non-assert guard is warranted here, or confirm that `getValue()` handles all non-terminal states safely.

#EDPQS: The private `actionResult()` here effectively re-introduces the unwrap pattern that was removed from `PlainActionFuture`. This is acceptable as a private helper, but note that it unwraps *any* `Exception` cause from `ExecutionException`, whereas the old `PlainActionFuture.actionResult()` only unwrapped `ElasticsearchException`. This broader unwrap is arguably more correct, but it means that if a listener in `executeListener` previously would have seen an `UncategorizedExecutionException` for a non-`ElasticsearchException` failure, it now sees the raw exception. Verify that all callers of `executeListener` (i.e., the `ActionListener<Long>` implementations) handle arbitrary exception types gracefully in their `onFailure` paths.

#AVWXT: The `assertDoesNotThrow` helper is `protected static` on `ESTestCase`. This is fine for subclasses, but note that it is not available to test classes that don't extend `ESTestCase` (e.g., standalone utility tests). If this pattern is expected to be reused broadly, a public utility location (e.g., a test-utility class) might be more discoverable. This is a minor placement suggestion, not a bug.
