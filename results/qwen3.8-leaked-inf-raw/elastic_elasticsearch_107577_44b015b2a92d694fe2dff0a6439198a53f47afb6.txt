#0V6JX: In `testManySingleDocPages`, the `Checks` record is constructed with `DEDUPLICATED_AND_SORTED_ASCENDING` for both the boolean/numerical and bytesRef orderings. However, the operator code (e.g., `ValuesSourceReaderOperator`) now unconditionally reports `SORTED_ASCENDING` for boolean/numerical doc values. The test data uses `between(1, numDocs)` values per document, so positions can contain duplicates (e.g., `[1, 2, 2, 1]` → doc values return `[1, 1, 2, 2]`), which is sorted but **not** deduplicated. The assertion `assertThat(longs.mvOrdering(), equalTo(DEDUPLICATED_AND_SORTED_ASCENDING))` would fail against the new `SORTED_ASCENDING` label. This test likely needs to expect `SORTED_ASCENDING` for the boolean/numerical parameter (while the bytesRef parameter can remain `DEDUPLICATED_AND_SORTED_ASCENDING` if keyword doc values are genuinely deduplicated by Lucene).
