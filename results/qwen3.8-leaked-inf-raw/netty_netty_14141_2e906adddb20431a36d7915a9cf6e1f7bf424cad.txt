#NXG3K: The new bracket-detection logic is sound for the intended use case. However, there is a minor null-safety regression: if `hostString` is `null` (e.g., `addr.getHostString()` returns `null` for an unresolved address), the old code would have produced the string `"[null]"` via concatenation, whereas the new code will throw a `NullPointerException` at `hostString.charAt(0)`. Consider adding a null guard:
```java
if (hostString != null && hostString.charAt(0) == '[' && hostString.charAt(hostString.length() - 1) == ']') {
    return hostString;
}
return '[' + hostString + ']';
```
This also lets you drop the `else` branch, simplifying the structure slightly.

A name like `testIpv6UnresolvedWithBrackets` or `testIpv6UnresolvedAlreadyBracketed` would more clearly convey that the input string already contains brackets, which is the specific scenario being exercised.
