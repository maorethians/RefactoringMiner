#R24M5: Two concerns in `wrapSingleValueQuery`:
1. **Silent exception swallowing.** The `catch (IOException e)` block discards the exception with only a `TODO` comment. If `rewrite()` fails, the code falls through and uses the *un-rewritten* `SingleValueMatchQuery` as a `FILTER` clause in the `BooleanQuery`. An un-rewritten `Query` that has not been resolved against a `LeafReaderContext` will likely throw at execution time or produce incorrect results. At minimum, log the exception; ideally, decide on a safe fallback (e.g., return the original `query` unfiltered, or propagate the error).
2. **Redundant per-position work.** `getQuery` is called once per row position. For every call where `onlySingleValues` is true, a new `SingleValueMatchQuery` is constructed and `rewrite(searcher())` is invoked, yet the parameters (`field`, `searchExecutionContext`) are identical across all positions. The rewritten result is position-independent, so it should be computed once (e.g., lazily cached in the `QueryList` instance) rather than repeated for every row.
