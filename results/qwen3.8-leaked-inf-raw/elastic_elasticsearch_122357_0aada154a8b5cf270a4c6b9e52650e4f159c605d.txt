#KZ9M1: The profiler code (`searchContext.queryResult().profileResults(...)`) is now inside the `try` block. In the previous code, if `RescorePhase.execute` timed out with partial results allowed, the exception was caught *inside* `RescorePhase`, execution continued to `SuggestPhase` and the profiler, and profiler results were still recorded. Now, any timeout during rescore or suggest skips the profiler entirely. This is a subtle behavioral change: a client requesting both `profile=true` and a search that times out will no longer receive partial profiler output. If this is intentional (arguably reasonable since the operation didn't complete), it's fine, but it's worth confirming it doesn't break any existing expectations around profiler output on timeout.

#J9S0A: In `TimeoutRescorerBuilder.innerBuildContext`, the `RescoreContext` is constructed with a hardcoded window size of `10` rather than the `windowSize` parameter passed to the method. Since the rescorer immediately throws, this is functionally irrelevant, but using the parameter (`new RescoreContext(windowSize, ...)`) would be more consistent and avoid confusion if the test is ever extended.
