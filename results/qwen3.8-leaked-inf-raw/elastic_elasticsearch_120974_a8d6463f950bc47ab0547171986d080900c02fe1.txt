#370GF: If multiple source fields target the same `copy_to` destination (as the new test does with both `k` and `k2` → `my_values.copy`), `createCopyToContext` will append a duplicate `NameValue` void entry to `ignoredFieldValues` for each source field. The previous implementation iterated `context.getCopyToFields()`, which may have been a `Set` and thus deduplicated. The duplicate is functionally harmless (identical stored-field value, last-write-wins), but it is a small behavioral difference. Consider whether a guard (e.g., checking if a void entry for this `copyToField` already exists) is warranted, or at minimum confirm that `getCopyToFields()` was indeed a `Set` so this is not a regression.
