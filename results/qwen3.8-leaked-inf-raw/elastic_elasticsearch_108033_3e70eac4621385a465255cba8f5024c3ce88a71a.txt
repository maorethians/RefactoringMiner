#CBC6B: The `rarely()` guard is a randomized-testing idiom used to occasionally exercise a **non-default** configuration path. Changing `store` from `true` to `false` makes the block set the value to what is already the implicit default for binary fields, so the `rarely()` branch now effectively tests nothing new — the same code path is already exercised every time `store` is omitted.
If the intent is to keep covering the non-default branch, the value should remain `true`. If the intent is to explicitly assert that `store: false` is accepted (e.g., guarding against a regression where the parser rejects the default), that is a different (and weaker) goal, and it would be clearer to drop the `rarely()` wrapper and set it unconditionally, or add a comment explaining why the default is being tested explicitly.
