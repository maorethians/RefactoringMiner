#H4QAH, #10KH2: The `equals()` and `hashCode()` implementations include `tokenToParam` and `parsingErrors`, both of which are mutable after construction (via `addTokenParam` and `addParsingError`). This means an object's `hashCode` can change over its lifetime, which violates the general `hashCode` contract ("if used as a key in a hash table, equal objects must have equal hash codes" — and by extension, a mutated object may become unfindable in a `HashMap`/`HashSet`). While `QueryParams` is unlikely to be used as a collection key in practice, this is a latent footgun. Consider either (a) excluding the mutable fields from `equals`/`hashCode` and comparing only the immutable `params`/`nameToParam`/`paramsCount`, or (b) documenting that `QueryParams` must not be used in hash-based collections after mutation.

#H4QAH: There is an inconsistency in defensive immutability: `nameToParam` is wrapped with `Collections.unmodifiableMap(...)`, but `params` is left as a raw `ArrayList`. Since the `positionalParams()` accessor that previously exposed the list has been removed, the list is only read internally via `get(int)`. For consistency and to prevent accidental mutation if a reference ever leaks, consider wrapping it: `this.params = List.copyOf(tempList)` or `Collections.unmodifiableList(new ArrayList<>(params))`.
