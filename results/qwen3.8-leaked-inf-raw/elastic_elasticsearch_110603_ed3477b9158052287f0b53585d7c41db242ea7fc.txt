#AYC41: The `else if` branch checks `getByKey(TIMESTAMP_MULTIPLE_VALUES_FLAG) == null` before calling `onlyAddKey`. If `onlyAddKey` already guarantees "add only if absent," the null-check is redundant. If it does *not* guarantee that (i.e., it overwrites), then the null-check is necessary to avoid redundant writes on the 3rd+ call. Either way the logic is correct, but a brief comment clarifying the intent of the guard (e.g., "set the flag exactly once") would help future readers understand why the check exists, since the method name `onlyAddKey` is ambiguous about whether it is idempotent.
