#KTNVN: The `calculateLastStartTime` method wraps `job` in `Optional.ofNullable(job)` at the start of both chains, but `job` is a required method parameter that is never null at either call site (it comes directly from a non-null collection element in `start` and from the `add` method's parameter). The `ofNullable(job)` adds a layer of indirection without protecting against a real case. A simpler formulation would improve readability:
```java
private long calculateLastStartTime(Watch job) {
    WatchStatus status = job.status();
    if (status != null) {
        if (status.lastChecked() != null) {
            return status.lastChecked().toInstant().toEpochMilli();
        }
        if (status.state() != null && status.state().getTimestamp() != null) {
            return status.state().getTimestamp().toInstant().toEpochMilli();
        }
    }
    return clock.millis();
}
```
This is a minor style/readability point rather than a correctness issue, but the nested `Optional` chains with the redundant `ofNullable(job)` make the fallback logic harder to scan at a glance.
