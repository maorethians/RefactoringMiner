#CPC0P: The `tagsSchema` method in the parent class `AbstractHighlighterBuilder` references constants defined in the child class `HighlightBuilder` (`HighlightBuilder.DEFAULT_PRE_TAGS`, `HighlightBuilder.DEFAULT_POST_TAGS`, `HighlightBuilder.DEFAULT_STYLED_PRE_TAG`, `HighlightBuilder.DEFAULT_STYLED_POST_TAGS`). This creates an upward dependency (parent → child) which is a design smell and will break if `HighlightBuilder` is ever refactored or if another subclass is introduced. Consider moving these tag constants into `AbstractHighlighterBuilder` (or a shared constants holder) so the parent is self-contained.

1. The assertion message for the `styled_string` field's `preTags` check reads `"setting tags_schema 'default' at the field level should alter pre_tags..."` but it should say `'styled'` since it's asserting against `DEFAULT_STYLED_PRE_TAG`.
2. Both styled-field assertion messages contain the typo `"that that field"` (doubled word).

#D1GAN, #82E56, #7QKTM, #67D0P: The serialization position of `encoder` has shifted. Previously it was written/read in `HighlightBuilder.doWriteTo`/constructor (after all parent fields). Now it is written/read in `AbstractHighlighterBuilder.writeTo`/constructor (between `numOfFragments` and `highlighterType`). This changes the wire format for both `HighlightBuilder` and any other subclass (e.g., `Field`). If this PR is intended to ship in a rolling-upgrade-compatible release, verify that the transport layer's version negotiation handles this reordering, or that a `Version` guard is in place. Otherwise, mixed-version clusters could misread the stream.
