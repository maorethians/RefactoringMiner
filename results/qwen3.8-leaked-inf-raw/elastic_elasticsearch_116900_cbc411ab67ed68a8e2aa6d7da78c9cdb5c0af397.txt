#ST95X, #0FQW1, #TSG74, #V8YG8: The change from `getAge()` to `getAge(Supplier<Long> now)` is a **breaking API change**. Any existing caller of the no-arg `getAge()` will fail to compile. If this class is part of a public API surface (it implements `ToXContentObject` and `Writeable`, and lives in `x-pack/plugin/core`), this needs careful consideration. A safer approach would be to keep the no-arg `getAge()` (delegating to the instance `nowSupplier`) and add the parameterized overload for testing, or simply have `getAge()` read from the field and let tests set the field.

#0FQW1: The `nowSupplier` field is package-private and mutable, with no encapsulation. This works for the test in the same package, but it exposes an internal implementation detail and allows any code in the same package to mutate it at any time. Consider making it `private` with a package-private setter (e.g., `void setNowSupplier(Supplier<Long> supplier)`), or better yet, inject it via the constructor/builder so the object is immutable after construction. This also avoids a potential visibility issue if the object is shared across threads in a server context (the field is neither `volatile` nor `final`).

#PB3ZN: The test directly assigns `indexLifecycleExplainResponse.nowSupplier = () -> now;`, which relies on the package-private mutable field. If the field is made `private` (as suggested above), this will need to go through a setter. Additionally, capturing `System.currentTimeMillis()` once and freezing it for the entire test is a reasonable approach for deterministic assertions, but be aware that if the test runs long enough (e.g., under heavy CI load), the "frozen" time could drift far from real time, making the test less representative. This is a minor concern but worth noting.
