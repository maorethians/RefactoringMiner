#PJQT8: The validation logic has a subtle but important bug:
```java
if (field.startsWith(nestedObjectMapper.fullPath())) {
```
This uses a plain `startsWith` without a dot boundary. Consider a nested object at path `nested_field` and a top-level sort field `nested_field2`. The check `"nested_field2".startsWith("nested_field")` evaluates to `true`, so the system would incorrectly reject a perfectly valid sort on a non-nested field. The same applies to any field whose name merely begins with the nested object's path (e.g., nested object `foo` vs. top-level field `foobar`).
The fix should anchor on a path segment boundary:
```java
if (field.equals(nestedObjectMapper.fullPath())
    || field.startsWith(nestedObjectMapper.fullPath() + ".")) {
```
This ensures only fields that are actually *inside* the nested object (or the nested object itself) are rejected.
