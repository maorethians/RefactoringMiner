#DBFV1: 1. `System.out.println("Patching " + inputFile.getName());` is a debug statement left in production code. In a Gradle transform this will pollute build output on every invocation. Consider removing it or using a proper logging mechanism.
2. The `Parameters` interface declares `getMatchingArtifacts()` as `@Optional`, meaning it can be `null`. However, in `transform()`, the code calls `matchingArtifacts.contains(jp.artifactTag())` without a null guard. If the parameter is ever omitted (which `@Optional` permits), this will throw a `NullPointerException`. Either remove `@Optional` (since all call sites in this PR always set it) or add a null check.
3. The `hadoop-client-api` pattern `Pattern.compile("hadoop-client-api.*")` is very broad and would also match a hypothetical `hadoop-client-api-*-tests.jar`. The `hadoop-common` pattern explicitly excludes tests via a negative lookahead, but this one does not. If test jars of `hadoop-client-api` could ever appear on the classpath, they would be incorrectly patched.

#SPCKS, #XZGG7, #0PTF6: The `patched` attribute is defined independently in each build script (`def patched = Attribute.of('patched', Boolean)`). This works because Gradle's `Attribute.of` is a factory that returns a canonical instance for the same name+type, so the references are consistent. No issue here, but it's worth noting that if the attribute name or type ever changes, all three sites must be updated in lockstep.
