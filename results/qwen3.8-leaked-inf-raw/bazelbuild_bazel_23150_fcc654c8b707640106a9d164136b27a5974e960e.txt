#E0EPX, #PXKB3, #HH0BY, #WP3Z5, #44HZ4, #F8FAV, #112GN: The `isFatalError` check in `SharedConnection.call()` only inspects `status.getCause()` (the immediate cause). If gRPC or Netty wraps the `NativeIoException` inside another exception (e.g., a `StatusRuntimeException` or a generic `IOException`), the `instanceof` check will miss it. Consider walking the full cause chain:
```java
private static boolean isFatalError(@Nullable Throwable t) {
  for (Throwable cur = t; cur != null; cur = cur.getCause()) {
    if (cur instanceof Errors.NativeIoException) {
      return true;
    }
  }
  return false;
}
```
This makes the detection robust against additional wrapping layers that may be introduced by future gRPC/Netty versions.

#H0VC9: The constructor accepts `Action onClose` (RxJava) and `Runnable onFatalError` (JDK) for what are semantically identical no-arg callbacks. This inconsistency makes the API harder to read. Prefer using `Runnable` for both (or `Action` for both) to keep the interface uniform.

#89QNQ: Two issues in the new test:
1. **Redundant `onClose` call.** The mock `brokenConnection`'s `doAnswer` on `start()` already invokes `listener.onClose(...)` on the *wrapped* listener, which triggers the fatal-error path and then delegates to the original listener. The subsequent explicit `listener.onClose(Status.fromThrowable(...), new Metadata())` after `call.start(...)` is a second, direct invocation on the original listener that bypasses the wrapper entirely. It is harmless here (the listener is a no-op) but it obscures what the test is actually verifying and could mask a regression if the forwarding logic changes. Remove it.
2. **Unnecessary exception mock.** `Errors.NativeIoException` has a simple constructor (`new Errors.NativeIoException("msg", errno)`). Using `mock(Errors.NativeIoException.class)` adds a Mockito dependency for no benefit and is slightly fragile (relies on Mockito's subclass-based mocking to satisfy `instanceof`). Prefer a real instance.
