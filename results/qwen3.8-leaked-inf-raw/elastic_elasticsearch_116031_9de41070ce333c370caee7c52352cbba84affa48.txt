If auto-creation is the intended behavior, a brief comment noting that would help future readers. Otherwise, a `indices.create_data_stream` for `data-stream-3` is missing from the setup.

#GP9DW: The `resolvedPipelineCache` is keyed solely on `indexRequest.index()`. In the non-rollover path, `resolveStoredPipelines` also receives `originalRequest` (the `DocWriteRequest`), which is forwarded to `resolvePipelinesFromMetadata`. If that method ever uses `originalRequest` in a way that could yield a different result for two distinct bulk items targeting the same index (e.g., different request-level metadata), the cache would return a stale entry for the second item. In practice this is unlikely because request-level pipeline is handled separately in `setPipelineOnRequest`, but it would be safer to either (a) assert/document that resolution is a pure function of `(index, metadata, epochMillis)`, or (b) include a discriminator in the cache key if `originalRequest` can influence the outcome.
