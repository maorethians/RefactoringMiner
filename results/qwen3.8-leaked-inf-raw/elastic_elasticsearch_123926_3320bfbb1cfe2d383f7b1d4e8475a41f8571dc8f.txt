#NB3T3: In `checkDataStreamMigrationStatus`, the exception message uses the `migrationInfo` object directly in string concatenation:
```java
"error occurred while reindexing data stream [" + migrationInfo + "]"
```
This will call `toString()` on the `SystemDataStreamMigrationInfo` object, which is unlikely to produce a useful identifier. It should use `dataStreamName` (which is already a local variable in scope) to produce a clear, actionable error message, consistent with the other log statements in the same method.

#HZ3VK: The Javadoc for `IndexMatcher` has a typo: `@link Metadata}` is missing the opening brace. It should be `{@link Metadata}`.

#WTP1Y: The Javadoc for `fromFeature` states it returns "A {@link Stream} of {@link SystemIndexMigrationInfo}s that represent all the indices the given feature currently owns." However, the method actually returns `Stream<SystemResourceMigrationInfo>` and includes both index and data stream migration infos. The Javadoc should be updated to reflect the broader return type.

#PYSZQ, #T100Q: The `origin` field in `SystemDataStreamDescriptor` is assigned without a null check, unlike other constructor parameters (e.g., `dataStreamName` uses `Objects.requireNonNull`). Since `origin` is later passed to `OriginSettingClient` via `SystemResourceMigrationInfo.createClient()`, a null value could cause a `NullPointerException` at runtime. Consider adding `Objects.requireNonNull(origin, "origin must be specified")` in the constructor, or documenting that null is acceptable and handling it in `createClient`.

#YV4NR: A test system data stream descriptor (`"sds-1"`, described as "Test System Data Stream") is added to `SERVER_SYSTEM_FEATURE_DESCRIPTORS`, which is production code. This will be registered as a real system feature on every node. If this is intended solely for integration testing, it may be better to register it via a test plugin or test-specific configuration rather than hardcoding it in the server's static feature map, to avoid shipping test artifacts in production builds.

#S0G4S: In `finishResourceAndLoop`, the assertion `migrationQueue.isEmpty() == false` is evaluated outside the `synchronized(migrationQueue)` block. While the persistent task executor is single-threaded in practice, the pattern is inconsistent with the rest of the class where all queue accesses are inside synchronized blocks. Moving the assertion inside the synchronized block would be more defensive and consistent.
