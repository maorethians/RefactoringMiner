#ZHETZ, #J68A3, #PE8SZ: The nested `assertBusy` calls in `assertNoSearchesRunning()` are almost certainly a mistake. The outer `assertBusy` (1-minute timeout) wraps an inner `assertBusy` (default timeout, ~10s). This means the outer loop will repeatedly invoke the inner `assertBusy`, each of which itself retries for its full default duration before throwing. The result is a confusing, redundant retry structure where the effective wall-clock time and number of HTTP requests are much higher than intended, and the semantics are hard to reason about.
The intent appears to be a single `assertBusy` with a 1-minute timeout that performs the check and logs hot threads on failure. The inner `assertBusy` should be removed, leaving:
```java
private void assertNoSearchesRunning() throws Exception {
    assertBusy(() -> {
        Request tasks = new Request("GET", "/_tasks");
        tasks.addParameter("actions", "*search");
        tasks.addParameter("detailed", "");
        Map<?, ?> response = responseAsMap(client().performRequest(tasks));
        if (response.isEmpty() == false) {
            logger.warn("search still running, hot threads:\n{}", hotThreads());
        }
        assertMap(response, matchesMap().entry("nodes", matchesMap()));
    }, 1, TimeUnit.MINUTES);
}
```

#PE8SZ: In the `hotThreads()` helper, the local variable is named `tasks` but the request is to `/_nodes/hot_threads`. This is misleading for anyone reading the method. A name like `request` or `hotThreadsRequest` would be clearer.
