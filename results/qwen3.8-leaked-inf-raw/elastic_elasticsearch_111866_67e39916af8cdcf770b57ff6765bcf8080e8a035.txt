#DD5BY: The test `test20MemoryLockingEnabled` only verifies that the process starts successfully, but does not assert that memory locking actually took effect. The TODO acknowledges this, but since this test is specifically added to validate the Windows memory locking fix (per the changelog), a minimal verification would strengthen it considerably. For example, on Linux you could check `/proc/<pid>/status` for `VmLck` > 0, or on Windows you could inspect the process's working set via `GetProcessMemoryInfo`. Even a log-level check (e.g., asserting the bootstrap log contains the expected "memory lock" confirmation message) would make the test meaningful rather than a smoke test.

#DR543: The fix is correct. The original `FunctionDescriptor.of(ADDRESS, JAVA_LONG, JAVA_LONG)` was missing the `HANDLE hProcess` parameter and incorrectly declared the return type as `ADDRESS` instead of `BOOL`. The corrected descriptor `FunctionDescriptor.of(JAVA_BOOLEAN, ADDRESS, JAVA_LONG, JAVA_LONG)` now matches the Windows API signature `BOOL SetProcessWorkingSetSize(HANDLE, SIZE_T, SIZE_T)`.
