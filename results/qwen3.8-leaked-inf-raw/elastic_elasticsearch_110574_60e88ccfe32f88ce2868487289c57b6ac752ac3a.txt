#54KX8, #K7ZGD, #EZE6J, #09NV6: The `validateGrokPattern` method throws a `ParsingException` whenever a duplicate attribute name is encountered, but the error message states "defined multiple times **with different types**". The code does not actually compare the types (`prev` vs `type`)—it unconditionally throws on any name collision. This correctness relies on the implicit assumption that the underlying Grok library's `captureConfig()` already deduplicates same-name/same-type captures. If that behavior ever changes, the error message would be misleading (reporting a "different types" conflict for what is actually a same-type duplicate). A more defensive and self-documenting check would be:
```java
if (prev != null && !prev.equals(type)) {
    throw new ParsingException(...);
}
```
This makes the intent explicit and decouples the validation from the library's deduplication behavior.

#K7ZGD: The new `ParsingException` is constructed with only a message string, without a source location. The existing GROK validation error (from `Grok.pattern(...)`) presumably carries source information that helps users locate the offending pattern in their query. Consider passing the source (available as `source(ctx)` in the calling method) to the `ParsingException` constructor for consistency and better diagnostics.
