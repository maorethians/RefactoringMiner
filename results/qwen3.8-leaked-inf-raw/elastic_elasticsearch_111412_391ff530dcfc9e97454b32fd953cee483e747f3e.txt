#MG3E3: The new 3-argument `parseLong` method calls itself, creating infinite recursion:
```java
public static long parseLong(String s, long minValue, String key) {
    return parseLong(s, minValue, key);  // ← calls itself (same 3-arg signature)
}
```
This should delegate to the 4-argument overload, e.g. `return parseLong(s, minValue, key, false);`. As written, any call to the 3-arg variant will result in a `StackOverflowError`.

#VRP9Q: In the `EnrichCache(long maxSize, LongSupplier)` constructor, `createCache(maxSize, null)` passes a `null` weigher to `CacheBuilder.weigher(...)`. If `CacheBuilder` does not explicitly handle a `null` weigher (falling back to a default weight of 1 per entry), this will throw a `NullPointerException` at construction time. Consider either:
- Guarding inside `createCache`: `if (weigher == null) { /* skip .weigher(...) */ }`, or
- Passing an explicit default weigher like `(k, v) -> 1L`.
This matters because the `long maxSize` constructor is still the fallback path used when the JVM max heap size cannot be determined (see `EnrichPlugin`), so it must remain functional.
