#ME6ZC, #PM6T2, #VA532, #JEEHX, #VAV6N, #KERW5: The old guard `remaining.size() > 1` ensured the pruned `EsRelation` always retained at least one non-key field. The new guard `remaining != null` permits `remaining` to be an empty list (size 0). In practice the join key should always be present in `used` (since the `Join` operator references it), so `remaining` should always contain at least the key. However, if a future refactoring or a bug ever causes the key to be absent from `used`, an `EsRelation` with zero output fields would be constructed, which could surface as a confusing downstream failure in the execution engine. A defensive `remaining != null && !remaining.isEmpty()` would be a low-cost safeguard. This is not a blocker given the current invariants, just a note for robustness.
