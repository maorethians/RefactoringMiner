#V8338: There is a potential resource leak with `markAsUsed`. It is created before `rewriteAndFetchShardRequest` is called, but it is only released inside `wrapFailureListener(l, readerContext, markAsUsed)` which lives in the success-path callback. If the rewrite step itself fails, `listener.delegateFailure(...)` will forward the exception to the original `listener`, but `markAsUsed` is never closed. This means the reader context stays marked as "used" (with its keep-alive) indefinitely, preventing it from being cleaned up.
Consider handling the failure path explicitly so that `markAsUsed` is released in both outcomes, e.g.:
```java
rewriteAndFetchShardRequest(readerContext.indexShard(), shardSearchRequest, new ActionListener<ShardSearchRequest>() {
    @Override
    public void onResponse(ShardSearchRequest rewritten) {
        runAsync(getExecutor(readerContext.indexShard()), () -> { /* ... */ },
                 wrapFailureListener(listener, readerContext, markAsUsed));
    }
    @Override
    public void onFailure(Exception e) {
        markAsUsed.close();
        listener.onFailure(e);
    }
});
```
Or, if `delegateFailure` is the intended API, ensure the failure path also releases `markAsUsed` (e.g., via a `finally`-style wrapper or by passing `markAsUsed` into the failure delegation).

#82GX1: All four test methods call `runLtrExplainTest`, which in turn calls `createLtrIndex` using the same constant `LTR_SEARCH_INDEX`. In an `internalCluster()`-based integration test the cluster persists across test methods within the same class, so the second (and subsequent) test will fail when `prepareCreate(LTR_SEARCH_INDEX)` is invoked because the index already exists (and with different shard/replica settings at that).
Suggested fixes (pick one):
- Delete the index at the start of `createLtrIndex` (or in an `@After` method) before creating it.
- Use a unique index name per test (e.g., include the shard/replica counts in the name).
- Add an `@After` method that deletes the index so each test starts from a clean state.
