#WEE4R, #HEJ1K: The `pooledChunkAllocations` counter is only incremented inside `allocateNormal`. In Netty's pool architecture, both small and normal allocations can trigger the creation of a new `PoolChunk` when the existing chunks in the corresponding `PoolChunkList` are exhausted. If `allocateSmall` also has a code path that creates a new chunk (which is the standard pattern in `PoolArena`), those chunk allocations will not be counted, causing `numChunkAllocations()` and `numActiveChunks()` to undercount. Please verify whether `allocateSmall` (or a shared helper it calls) also needs the `++pooledChunkAllocations` increment.

#6P6CR: The test only exercises the normal-allocation path and asserts the initial (non-deallocated) state. Consider adding a follow-up that frees the buffer (triggering `freeChunk` → `destroyChunk`) and then asserts `numChunkDeallocations() == 1` and `numActiveChunks() == 0`. This would cover the deallocation branch added in #088Y1 and the subtraction logic in #ZP0MS.
