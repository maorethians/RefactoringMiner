#T8ZKR: The boolean passed to the `Cap(boolean enabled)` constructor is inverted. `Runtime.version().feature() < 20` evaluates to `true` on JDK < 20, which **enables** the capability exactly where it should be **disabled**. The Javadoc on the same line says "This is not supported on JDK versions less than 20," and the test in #973MZ gates the grapheme-cluster reversal test on this capability. The condition should be `Runtime.version().feature() >= 20` so the capability is enabled only when the JDK actually supports correct grapheme cluster reversal.

#1TVYQ: The `Cap(FeatureFlag featureFlag)` constructor now calls `featureFlag.isEnabled()` once at enum-initialization time and stores the result. In the previous code, `featureFlag.isEnabled()` was called on every invocation of `isEnabled()`. If any feature flag in use can be toggled at runtime (e.g., via a REST API or system property change after startup), the new code will not reflect that change. If all feature flags used here are immutable after node startup, this is fine, but it is a subtle behavioral change worth confirming.
