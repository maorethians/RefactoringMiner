#E6MZH: **Bug: duplicate `Locale("fr")` entry — the second one should be `Locale("ga")`.**
There are two consecutive `LOCALE_DATA.put(new Locale("fr"), ...)` calls. The second block uses the local variable name `gaData` and contains Irish (Gaelic) locale data (`"RC"`, `"AD"` for eras; `"a.m."`, `"p.m."` for AM/PM). Because `HashMap.put` overwrites on duplicate keys, the first `fr` entry (with `"BC"`, `"ap. J.-C."`) is silently discarded, and the `ga` locale is never registered.
The fix is to change the second key to `new Locale("ga")`:
```java
LOCALE_DATA.put(new Locale("ga"), memoized(() -> {
    Map<Integer, Map<Integer, List<String>>> gaData = new HashMap<>();
    // ...
}));
```

#E6MZH: **Minor: `getDisplayName` does not guard against a negative `value`.**
```java
if (value < values.size()) {
    return values.get(value);
}
```
If `value` is negative (e.g. `-1`), the condition `-1 < values.size()` is `true`, and `values.get(-1)` will throw `IndexOutOfBoundsException`. While the `Calendar` API contract guarantees non-negative values, a defensive `value >= 0 && value < values.size()` check would make the method robust against misuse or future callers:
```java
if (value >= 0 && value < values.size()) {
    return values.get(value);
}
```
