#MTMYN: The test always uses `statusInterval` (1–10 ns) far smaller than `tickTime` (10 000–100 000 ns), so the periodic status update fires on every single iteration and `unreportedIterations` is always 1 at report time. This means the code path where multiple iterations accumulate in `unreportedIterations` before a periodic update fires (i.e., `statusInterval > tickTime`) is not exercised. Consider adding a case (or a second test) where `statusInterval` is larger than `tickTime` so that the periodic update fires less frequently than per-iteration, verifying that the accumulated delta is reported correctly in both the periodic and the terminal (WAITING/DONE) status updates.
