If the response contains no data nodes, this could return `null` and cause an NPE. While this is unlikely in practice (a snapshot response should always have data nodes), a defensive null-check or an early return with a clear error message would make the failure mode more diagnosable.

#KQM63, #0HA4P, #M8VBB, #95B8B: **Exception thrown inside `listener.map` lambda**: The `SnapshotException` is thrown within the mapping function passed to `listener.map(...)`. Confirm that `ThreadedActionListener` (or the underlying `ActionListener` contract) reliably forwards exceptions thrown inside the `map` function to the downstream listener as a failure. This is a conservative (safe) choice, but worth noting in a code comment or the exception message so operators understand why a seemingly compatible snapshot is rejected.
