#SKYNC: The single-argument `indexDocs(String indexName)` now delegates to `indexDocs(indexName, false)` which already performs the `IndicesStatsResponse` assertion at the end of the two-arg method. The single-arg version then performs the same stats check a second time. This results in a redundant API call and assertion. Consider removing the duplicate stats check from the single-arg overload since the two-arg version already validates the doc count.

#TF1DC: Two issues in the new data stream migration code:
1. `dataStreamMigrationFailed` constructs the exception message using `migrationInfo` (the object's `toString()`) rather than `migrationInfo.getDataStreamName()`, which is inconsistent with the log statement immediately above it that correctly uses `getDataStreamName()`.
2. The method `throws` the `ElasticsearchException` rather than calling `markAsFailed(ex)`. This relies on `ActionListener.wrap` catching the exception from the response handler and routing it to the failure handler. However, the sibling method `cancelExistingDataStreamMigrationAndMarkAsFailed` uses the explicit `markAsFailed` pattern. For consistency and to avoid depending on the `ActionListener.wrap` exception-catching behavior, consider calling `markAsFailed(ex)` directly instead of throwing.

#WTP1Y: The javadoc for `fromFeature` says "A {@link Stream} of {@link SystemIndexMigrationInfo}s that represent all the indices the given feature currently owns." This is now inaccurate since the method returns `Stream<SystemResourceMigrationInfo>` which includes both `SystemIndexMigrationInfo` and `SystemDataStreamMigrationInfo` instances.

#8HNRF: The `getThreadPoolNames()` javadoc says "for operations on this system index" but the interface is now shared with data streams. Minor documentation inaccuracy.

#1663R: Changes `allowRestrictedIndices(false)` to `allowRestrictedIndices(true)` for the `kibana_user` role. This is a security-relevant change that grants Kibana access to restricted (system) indices. This appears intentional to support system data stream access from Kibana, but it broadens the attack surface. Worth confirming this is the minimal necessary change.

#FD2R5, #PTDSD: Renames `getFailedIndexName()` to `getFailedResourceName()`. The field is still named `failedIndexName` internally (visible in #PTDSD where the getter body returns `failedIndexName`). This is a minor naming inconsistency but acceptable for a rename that preserves serialization compatibility.
