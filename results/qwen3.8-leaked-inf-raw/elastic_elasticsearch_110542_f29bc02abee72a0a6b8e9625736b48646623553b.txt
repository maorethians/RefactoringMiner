#T4RPH: The `onFailure` handler `e -> {}` silently swallows any exception thrown by `loadQueuedModels`. If the service calls `onFailure`, the test will fail with the generic message "Test failed to call the onResponse handler" without revealing the actual exception. Consider capturing the exception (e.g., into an `AtomicReference<Exception>`) and including it in the assertion message, or calling `fail(e)` so the root cause is visible in the test output. This makes debugging significantly harder if the test ever fails for an unexpected reason.
