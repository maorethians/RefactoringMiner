#VBDR2: The `TermsQueryBuilder.doCoordinatorRewrite` logic is incorrect. A terms query matches if **any** of its values match. The current loop returns `MatchNoneQueryBuilder` as soon as it encounters a single value that produces `MatchNoDocsQuery`, even if a subsequent value would produce `MatchAllDocsQuery`.
For example, with tier = `"data_frozen"` and values `["data_hot", "data_frozen"]`:
- `"data_hot"` → `MatchNoDocsQuery` → immediately returns `MatchNoneQueryBuilder` (wrong!)
- `"data_frozen"` → `MatchAllDocsQuery` (never reached)
The correct semantics: return `MatchAllQueryBuilder` if **any** value matches; return `MatchNoneQueryBuilder` only if **all** values fail to match. Suggested fix:
```java
boolean anyMatch = false;
for (Object value : values) {
    Query tierFieldQuery = tierFieldType.internalTermQueryCaseInsensitive(value, coordinatorRewriteContext);
    if (tierFieldQuery instanceof MatchAllDocsQuery) {
        anyMatch = true;
        break;
    } else if (tierFieldQuery instanceof MatchNoDocsQuery) {
        // continue checking other values
    } else {
        assert false : "Constant fields must produce match-all or match-none queries, got " + tierFieldQuery;
    }
}
if (anyMatch) {
    return new MatchAllQueryBuilder();
}
return new MatchNoneQueryBuilder("The \"" + getName() + "\" query was rewritten to a \"match_none\" query.");
```

#6WPGN, #PRERM: The coordinator rewrite in `QueryStringQueryBuilder` and `SimpleQueryStringBuilder` triggers when `_tier` is **one of** the fields in `fieldsAndWeights`, not necessarily the **only** field. For example, a query like `{"query_string": {"query": "data_frozen", "fields": ["_tier", "name"]}}` would be rewritten to a tier-only match, but the original intent was to search both `_tier` and `name`. This could produce incorrect results (missing documents that match on `name` but not `_tier`).
Consider restricting the rewrite to the case where `_tier` is the sole field being queried (e.g., `fieldsAndWeights.size() == 1 && fieldsAndWeights.containsKey(DataTierFieldMapper.NAME)`), or at minimum document this as a known limitation.
