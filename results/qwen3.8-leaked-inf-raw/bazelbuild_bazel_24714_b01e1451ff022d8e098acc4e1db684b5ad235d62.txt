#KRBNJ, #7PAJR, #1CJ28, #WGRH3: The changes look correct overall. The regex fix from `.*\s` to `\S+\s` properly addresses a real bug: with a trailing newline (e.g., `"-1 100000\n"`), the old greedy `.*\s` pattern would consume the entire line including the period value, causing `nextInt()` to fail. The new pattern `\S+\s` matches only the first token and its trailing whitespace, leaving the period intact for `nextInt()`.
The `hasNextLong()` guard in `getCpus` correctly handles the cgroups v2 `max` sentinel value, and the added test cases cover both the trailing-newline scenario and the `max` (unlimited) path.
One minor observation on `#7PAJR`: the `getCpus` method performs integer division (`quota / period`), so a configured value like 1.5 CPUs (quota=150000, period=100000) would report back as `1`. This is pre-existing behavior and not introduced here, but it's worth being aware of if callers rely on `getCpus()` to round-trip the value set by `setCpus()`.
