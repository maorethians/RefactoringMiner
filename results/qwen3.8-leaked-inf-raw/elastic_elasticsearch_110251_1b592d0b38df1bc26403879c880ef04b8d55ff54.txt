#1X3EF, #ESTZ8: The `startsWith` check has a false-positive bug. Consider a nested object at path `foo` and a top-level sort field named `foobar`:
```java
if (field.startsWith(nestedObjectMapper.fullPath())) {
```
`"foobar".startsWith("foo")` evaluates to `true`, so the validation would incorrectly reject a perfectly valid sort field. The check should ensure a dot-separator boundary:
```java
if (field.equals(nestedObjectMapper.fullPath()) || field.startsWith(nestedObjectMapper.fullPath() + ".")) {
```
This also correctly handles the case where the sort field *is* the nested object path itself (e.g., sorting on `nested_field` directly), which the current `startsWith` would catch but the `equals` clause makes the intent explicit.
