This text is copied verbatim into every generated type (Boolean, Double, Float, Int, Long), where `BytesRef` is irrelevant and the `@link` reference is misleading. #ZVWV6, #TRG4R, #6Q8NK, #A9DAW, #68XPA, #FHP73: In the lazy evaluator's `perPosition`, the copy from `lastFullBlock` uses the range-based overload:
```java
result.copyFrom(lastFullBlock, p, p + 1);
```
while the copy from the freshly-evaluated block uses the new single-position overload:
```java
result.copyFrom(block, 0);
```
Both are copying exactly one position. For consistency (and to avoid the redundant range-bound check), the `lastFullBlock` copy should also use the single-position form: `result.copyFrom(lastFullBlock, p)` (or `result.copyFrom(lastFullBlock, p, scratch)` for BytesRef). This also makes the generated code uniform with the eager evaluator, which already uses the single-position form throughout.
