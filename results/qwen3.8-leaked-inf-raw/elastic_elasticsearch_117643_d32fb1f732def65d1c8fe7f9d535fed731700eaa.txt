#FW32Q, #CF0G5, #YGS91, #9QW0C, #DFNPW: **Separator bug in `TextFormatter` when the first column is dropped**
In `TextFormatter.formatHeader` (#FW32Q), the separator line (#CF0G5), and the data rows (#YGS91), the separator is prepended using `if (i > 0)`. This is based on the *original* column index, not on whether the current column is the first *visible* one. If `dropColumns[0]` is `true`, the loop skips index 0, and when it reaches index 1 the condition `i > 0` is still true, so a `|` is written before what is actually the first visible column — producing a leading separator in the output.
The `row` helper in `TextFormat` (#9QW0C) handles this correctly with a `firstColumn` flag. The three `TextFormatter` loops should use the same pattern:
```java
boolean firstColumn = true;
for (int i = 0; i < width.length; i++) {
    if (dropColumns[i]) {
        continue;
    }
    if (firstColumn) {
        firstColumn = false;
    } else {
        writer.append('|');
    }
    // ...
}
```
The existing test `testFormatWithDropNullColumns` (#DFNPW) places the null column at index 3, so it does not exercise the case where column 0 is dropped. A test with the null column at position 0 would catch this.

#5G7X6, #Q1DGT: **`columns()` null-safety regression in `TextFormat.format`**
In #5G7X6 the guard was changed from `esqlResponse.columns() != null` to `esqlResponse.columns().isEmpty() == false`. If `columns()` can ever return `null` (the original null-check suggests it was considered possible), the new expression will throw a `NullPointerException`. The same change appears in #Q1DGT (`response.columns().size() > 0` → `response.columns().isEmpty() == false`). If `columns()` is guaranteed non-null by contract, the original null-check was dead code and the change is fine; otherwise this is a regression. Worth confirming the invariant.

#5G7X6, #WAHAS: **`dropColumns` array allocation when `dropNullColumns` is false**
In both #5G7X6 and #WAHAS, when `dropNullColumns` is `false` the code allocates `new boolean[esqlResponse.columns().size()]` (all `false`). This is an unnecessary allocation on the common path. A shared `static final boolean[] NO_DROP = {}` sentinel or a `null` check in the `row`/format loops would avoid the allocation. Minor, but it runs on every request.
