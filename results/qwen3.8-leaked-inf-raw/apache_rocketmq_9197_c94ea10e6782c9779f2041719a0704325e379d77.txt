#8DX0M, #0TT71, #QT0BX: The changes are well-structured and maintain backward compatibility. One minor observation: in `MQClientAPIExt.notification()`, the backward-compatible path now allocates a `NotifyResult` object solely to extract `isHasMsg()` via `thenApply(NotifyResult::isHasMsg)`. This is functionally correct but introduces a small unnecessary allocation on every call through the legacy API. If this method is on a hot path, you could alternatively keep the original inline logic in `notification()` and only use `notificationWithPollingStats()` for the new path. That said, the overhead is negligible in practice, so this is purely a style/performance nit.

#0HGSH: The `NotifyResult` class is a straightforward DTO. One small note: it does not implement `equals()`/`hashCode()`. If this object is ever used in assertions, collections, or compared in tests, the default identity-based equality could be surprising. Adding them (or at least documenting the intent) would be a low-cost improvement, though for a simple per-request result object it is not strictly required.
