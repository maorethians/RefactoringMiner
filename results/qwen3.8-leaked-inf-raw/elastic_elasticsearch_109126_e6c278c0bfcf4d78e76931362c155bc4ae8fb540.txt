#0C4MT: The `ingest_time` column changes from a `TimeValue` (e.g. rendered as `"1.5s"`) to a raw `long` millisecond value (e.g. `"1500"`). This is a user-visible output-format change for the `_cat` trained models API. While it makes sense that raw numeric values are needed to accumulate across multiple deployments, this is a breaking change for any consumer that parses the `_cat` output expecting a human-readable time string. If this is intentional, it should be called out in the changelog or release notes; if not, consider formatting the accumulated millis back into a `TimeValue` before adding the cell.

It never exercises the duplicate-key merge path (`(stats1, stats2) -> stats1`) that this PR is fixing. To actually validate the fix, the test should include two `TrainedModelStats` entries sharing the same model ID `"id1"` in the `statsResponse`, which would previously have thrown `IllegalStateException` in `Collectors.toMap`. As written, this test would pass even without the merge-function fix.
