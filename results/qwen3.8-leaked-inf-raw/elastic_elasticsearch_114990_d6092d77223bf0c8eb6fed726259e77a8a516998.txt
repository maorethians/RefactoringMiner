#VBDR2: The `doCoordinatorRewrite` logic for `TermsQueryBuilder` is incorrect. A `terms` query is a disjunction (OR) — a document matches if **any** of the provided values match. However, this code returns `MatchNoneQueryBuilder` as soon as it encounters the **first** value that produces a `MatchNoDocsQuery`, without checking the remaining values.
Example: tier is `"data_hot"`, values are `["data_frozen", "data_hot"]`. The loop hits `"data_frozen"` → `MatchNoDocsQuery` → returns `MatchNone`, incorrectly skipping the shard even though `"data_hot"` would match.
The correct logic should be:
1. If **any** value produces `MatchAllDocsQuery` → return `MatchAllQueryBuilder`.
2. Only if **all** values produce `MatchNoDocsQuery` → return `MatchNoneQueryBuilder`.
Suggested fix:
```java
boolean anyMatch = false;
for (Object value : values) {
    Query tierFieldQuery = tierFieldType.internalTermQueryCaseInsensitive(value, coordinatorRewriteContext);
    if (tierFieldQuery instanceof MatchAllDocsQuery) {
        anyMatch = true;
        break;
    }
}
if (anyMatch) {
    return new MatchAllQueryBuilder();
} else {
    return new MatchNoneQueryBuilder("The \"" + getName() + "\" query was rewritten to a \"match_none\" query.");
}
```

#6WPGN, #PRERM: The coordinator rewrite in `QueryStringQueryBuilder` and `SimpleQueryStringBuilder` triggers whenever `_tier` is **one of** the fields in `fieldsAndWeights`, even when other fields are also present. However, a multi-field query is a disjunction across all listed fields — a document can match via any of them. The rewrite treats the query as if it were exclusively against `_tier`, so it can return `MatchNone` and skip a shard that would actually have matching documents in the other fields.
Example: `query_string: { query: "data_frozen", fields: ["_tier", "message"] }` on a shard whose tier is `"data_hot"`. The coordinator rewrite sees `_tier` doesn't match and returns `MatchNone`, but a document in that shard could still match via the `message` field.
The rewrite should only apply when `_tier` is the **sole** field being queried (e.g., `fieldsAndWeights.size() == 1 && fieldsAndWeights.containsKey(DataTierFieldMapper.NAME)`), or the logic should be extended to account for the other fields.
