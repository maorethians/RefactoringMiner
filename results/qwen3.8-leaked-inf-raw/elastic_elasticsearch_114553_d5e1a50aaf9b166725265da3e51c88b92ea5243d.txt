#KZRWF: The `/_tasks/_cancel` call without any filter parameters cancels **all** pending tasks cluster-wide, not just the ML-related persistent tasks mentioned in the comment. In a shared or parallel test environment, this could inadvertently cancel tasks belonging to other concurrently running tests or the test framework itself. Consider scoping the cancellation, e.g. by specifying a `tasks` parameter with a wildcard for ML task names (like `*anomaly*` or `*_close*`), or at minimum by node, to limit the blast radius.

#E1S3X, #2RZR8: Two observations:
1. The identical try-catch block is duplicated for `extraIndex1` and `extraIndex2`. Extracting a small private helper (e.g. `performRequestIgnoringWarnings(Request)`) would reduce duplication and make the intent clearer if more index-creation calls are added later.
2. The exception type is referenced by its fully-qualified name (`org.elasticsearch.client.WarningFailureException`) rather than via an import. This is inconsistent with the rest of the file's style and hurts readability. A standard import at the top of the class would be preferable.
