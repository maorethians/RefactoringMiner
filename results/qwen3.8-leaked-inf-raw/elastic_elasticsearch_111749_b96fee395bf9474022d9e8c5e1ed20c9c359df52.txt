#V9347: **Critical: Missing `return` after the sorted-ascending fast path**
In all three process methods (`processDoubles`, `processInts`, `processLongs`), the `if (valuesBlock.mvSortedAscending())` block appends a result to the builder but does **not** return. Execution falls through to the unsorted path below, which copies the values, sorts them, and appends a **second** value for the same position. This corrupts the output block (two values written where one is expected).
```java
if (valuesBlock.mvSortedAscending()) {
    // ... appends result ...
}
// <-- missing return here; falls through to:
var values = new double[valueCount];
// ... appends a second result ...
```
A `return;` is needed at the end of the `if (valuesBlock.mvSortedAscending())` block (or the unsorted path should be in an `else`).

#V9347: **Critical: Wrong indices in the sorted-ascending path**
In the sorted path, block values are accessed without the `firstValueIndex` offset. For a multi-row page, position `p > 0` has its values starting at `firstValueIndex > 0`, so:
- `valuesBlock.getDouble(0)` should be `valuesBlock.getDouble(firstValueIndex)`
- `valuesBlock.getDouble(valueCount - 1)` should be `valuesBlock.getDouble(firstValueIndex + valueCount - 1)`
- `valuesBlock.getDouble(lowerIndex)` should be `valuesBlock.getDouble(firstValueIndex + lowerIndex)`
- `valuesBlock.getDouble(upperIndex)` should be `valuesBlock.getDouble(firstValueIndex + upperIndex)`
The same issue exists in `processInts` (`getInt`) and `processLongs` (`getLong`). Without the offset, the sorted path reads values from the wrong positions in the block's value array.

#V9347: **Potential overflow in `processInts`**
```java
var difference = (long) upperValue - lowerValue;
var percentileValue = lowerValue + (int) (fraction * difference);
```
When the value range spans the full int range (e.g., `[Integer.MIN_VALUE, Integer.MAX_VALUE]`), `difference` can be up to `2^32 - 1`. For `fraction > 0.5`, `fraction * difference` exceeds `Integer.MAX_VALUE`, and the `(int)` cast silently overflows, producing a wrong result.
The fix is to compute the full result as a double before casting:
```java
var percentileValue = (int) (lowerValue + fraction * ((long) upperValue - lowerValue));
```
This is safe because the result of a convex combination of two ints is always within `[Integer.MIN_VALUE, Integer.MAX_VALUE]`.
