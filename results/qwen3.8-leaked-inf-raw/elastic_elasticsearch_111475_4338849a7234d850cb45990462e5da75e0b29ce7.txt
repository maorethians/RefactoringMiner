#A7C3H: The Javadoc on `NamedExpression.toAttributeUnchecked()` (in #35SNB) states "Do not return an `UnresolvedAttribute` if this is unresolved," but `UnresolvedNamedExpression.toAttributeUnchecked()` throws `UnresolvedException`. While technically this satisfies the contract (throwing ≠ returning), the distinction between "throws" and "returns UnresolvedAttribute" is subtle and could mislead future readers into thinking this method is safe to call without a try/catch in all cases. Consider adding a `@throws` note to the Javadoc on the abstract method in `NamedExpression` to make the throwing behavior explicit for the `UnresolvedNamedExpression` case.

#RJ1R8: The `types` string is built via `imf.getTypesToIndices().keySet().stream().collect(Collectors.joining(","))`. This produces an unordered, comma-separated list (since `keySet()` on a `HashMap` has no guaranteed order). If this string appears in user-facing error messages or is compared in tests, the non-deterministic ordering could cause flaky test assertions. Consider sorting the types before joining, e.g., `.sorted().collect(Collectors.joining(","))`.
