#MSYSP: The change from `queueId` to `entry.getKey()` in the `clearCache` call is a correct bug fix — the original code used the method-level parameter `queueId` inside a loop over multiple queue entries, which would have cleared the wrong cache entry for all queues except the one matching the parameter.
However, there is an inconsistency in null-safety: `getPopInflightMessageCounter()` is now guarded by a null check, but the newly added `getConsumerOffsetManager()` call is not. If `getPopInflightMessageCounter()` can be null in certain deployment or initialization states, `getConsumerOffsetManager()` could plausibly be in the same situation, and the new line would throw a `NullPointerException`. Consider either adding a similar null guard or documenting why `getConsumerOffsetManager()` is guaranteed non-null at this point.
Additionally, the `commitPullOffset` call is placed inside the `isPopConsumerKVServiceEnable()` branch. If the intent is to persist the reset offset for *all* consumers (not only those using the KV service), this call should be moved outside that `if` block. If it is intentionally scoped to the KV-service path, a brief comment explaining the coupling would help future readers.
