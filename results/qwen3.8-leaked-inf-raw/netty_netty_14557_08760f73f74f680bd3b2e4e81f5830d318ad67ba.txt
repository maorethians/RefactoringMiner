#9YJES, #9X7BY, #49XQP, #BEGFT, #S5DJ4, #DCQ00: **Critical bug: missing unit conversion in constructor assignments.**
In the two constructors that accept `maxTaskProcessingQuantumMs` (diff #BEGFT), the user-supplied value is in **milliseconds** but is assigned directly to the field `maxTaskProcessingQuantumNs` which is in **nanoseconds**:
```java
this.maxTaskProcessingQuantumNs =
        ObjectUtil.checkPositiveOrZero(maxTaskProcessingQuantumMs, "maxTaskProcessingQuantumMs") == 0 ?
                DEFAULT_MAX_TASK_PROCESSING_QUANTUM_NS : maxTaskProcessingQuantumMs;
```
If a caller passes `500` (intending 500 ms), the field will be set to `500` nanoseconds instead of `500_000_000` nanoseconds. The event loop would then attempt to run IO after a single task (or even between tasks), severely degrading throughput.
The default constant is correctly converted (`TimeUnit.MILLISECONDS.toNanos(...)`), but the user-provided path is not. The fix should be:
```java
this.maxTaskProcessingQuantumNs =
        ObjectUtil.checkPositiveOrZero(maxTaskProcessingQuantumMs, "maxTaskProcessingQuantumMs") == 0 ?
                DEFAULT_MAX_TASK_PROCESSING_QUANTUM_NS
                : TimeUnit.MILLISECONDS.toNanos(maxTaskProcessingQuantumMs);
```

#9X7BY: **Breaking API change: field visibility reduced from `protected` to `private`.**
The field was previously `protected static final int DEFAULT_MAX_TASKS_PER_RUN` and `private final int maxTasksPerRun`. Now it is `private static final long DEFAULT_MAX_TASK_PROCESSING_QUANTUM_NS` and `private final long maxTaskProcessingQuantumNs`. Any subclass that previously accessed `maxTasksPerRun` (or the constant) will no longer compile. If this class is intended to be extended (it is `public` and not `final`), consider keeping the field `protected` or providing a getter.

#BEGFT: **Breaking API change: constructor signatures changed without deprecation.**
Both public constructors that previously accepted `(parent, threadFactory/executor, ioHandler, maxPendingTasks, rejectedExecutionHandler)` now require an additional `long maxTaskProcessingQuantumMs` parameter. Existing callers will fail to compile. If backward compatibility matters, consider keeping the old signatures as deprecated overloads that delegate with the default quantum.
