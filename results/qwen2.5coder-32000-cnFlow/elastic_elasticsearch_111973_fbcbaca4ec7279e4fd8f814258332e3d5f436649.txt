#9929M, #T9VA8: The logic for handling indices when there are more than three is correct, but it can be optimized for performance and readability. The current implementation sorts the entire set of indices and then limits the result to three elements. This approach has a time complexity of O(n log n) due to sorting. Instead, you could use a `PriorityQueue` or `Stream.limit()` directly on an unsorted stream with a custom comparator to find the first three elements without sorting the entire list. Additionally, the string concatenation for the error message can be improved by using `StringBuilder` to avoid creating multiple intermediate strings.
