#8HP28: The method `parseLong` is now public but does not handle null input for the string `s`. This could lead to a `NullPointerException`.

#PPNG5, #X1F2K: In `EnrichCache`, the constructor that takes `long maxSize` and `LongSupplier relativeNanoTimeProvider` has been replaced with one that uses `ByteSizeValue maxByteSize`. However, the method `createCache` is now called with a weigher function `(key, value) -> value.sizeInBytes`, which might not be appropriate if `value` does not have a `sizeInBytes` field directly. The `CacheValue` record has `sizeInBytes` as a field, but it's unclear if this is the intended usage without further context.

#6W5BT: The new parser for `CACHE_SIZE` in `EnrichPlugin` handles null input by returning null, which might not be appropriate since `Setting<Long>` expects a `Long`. This could lead to issues when trying to use the setting value later on.

#YVAYZ: In the constructor of `EnrichPlugin`, there is a fallback mechanism that calculates `maxByteSize` as 1% of the configured max heap size. However, this calculation does not consider if the calculated size is too small or too large for practical use. Additionally, the fallback to 1000 entries when both `maxSize` and `maxHeapSize` are null might not be suitable in all environments.
