#MTJ29, #3VA9W: The change replaces a custom `SyntheticFieldLoader` implementation with `SyntheticSourceSupport.Fallback`. However, the original loader had specific behavior for writing to `XContentBuilder`, which is not preserved by `Fallback`. The comment suggests that `_source` should only contain the value if it was in the original document, but `Fallback` does not implement this logic. This could lead to inconsistent behavior between stored source and synthetic source. The test case `testNoValueInDocumentSyntheticSource` checks that the synthetic source is empty when there is no value in the document. However, it does not verify that the behavior matches the expected fallback logic described in the comment for `#MTJ29`. The test should be updated to ensure that the synthetic source behaves as intended.
