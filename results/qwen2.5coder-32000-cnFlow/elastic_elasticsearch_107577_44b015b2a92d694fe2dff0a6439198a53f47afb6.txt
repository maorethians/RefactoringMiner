#P7711: The change from checking `block.mayHaveMultivaluedFields()` to `block.mvDeduplicated()` might not be semantically equivalent. The original condition checks if the block can have multivalued fields, while the new condition checks if multivalued fields are deduplicated. This could lead to different behavior if a block may have multivalued fields but they are not deduplicated.

#VK4WJ, #8JTTT, #AV64A, #9TRHW: The changes from `Block.MvOrdering.DEDUPLICATED_AND_SORTED_ASCENDING` to `Block.MvOrdering.SORTED_ASCENDING` imply that the data is no longer guaranteed to be deduplicated. This change should be reflected in any logic that assumes deduplication, and tests should verify that this assumption holds or is not necessary.

#DXWMG: The method `infoAndChecksForEachType` now takes two parameters for different types of doc values ordering. Ensure that all calls to this method correctly pass the appropriate orderings, especially since some methods were updated to pass `Block.MvOrdering.UNORDERED` twice, which might not be correct if there are differences between boolean/numerical and bytesRef orderings.

#SKTKD: The addition of a case for `SORTED_ASCENDING` in `putInOrder` is correct. However, ensure that all parts of the codebase that use this method are aware of the new ordering and handle it appropriately.
