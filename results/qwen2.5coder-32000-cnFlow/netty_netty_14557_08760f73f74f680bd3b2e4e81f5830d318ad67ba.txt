#VCACG, #PC2PV: The removal of `DEFAULT_MAX_TASKS_PER_RUN` and its usage in favor of `maxTaskProcessingQuantumNs` seems logical, but there is a mismatch in units. `DEFAULT_MAX_TASKS_PER_RUN` was an integer representing the number of tasks, whereas `maxTaskProcessingQuantumNs` represents time in nanoseconds. This change could lead to incorrect behavior if the logic in `runAllTasks` expects a task count rather than a time duration.

#EJWNX, #2XFNV: In both diffs, there is a ternary operator that checks if `maxTaskProcessingQuantumMs` is zero and assigns `DEFAULT_MAX_TASK_PROCESSING_QUANTUM_NS` if true. However, this logic might not be necessary since `SystemPropertyUtil.getInt` already provides a default value of 1000 milliseconds, which converts to a non-zero nanoseconds value. This ternary operation can likely be simplified or removed.
