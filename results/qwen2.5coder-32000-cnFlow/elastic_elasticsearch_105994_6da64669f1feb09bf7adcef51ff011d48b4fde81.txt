#1NKF1: The logic for adjusting the filter query when it might match nested documents seems correct, but there are a few points to consider:
1. The `NestedHelper` instance is created every time `doToQuery` is called. If this method is invoked frequently, creating a new `NestedHelper` each time could lead to performance issues due to object creation overhead.
2. The comment "We treat the provided filter as a filter over PARENT documents" suggests that the logic assumes the filter query is intended for parent documents. However, there's no explicit check or transformation of the filter query to ensure it only targets parent documents before applying the `nestedTypeFilter`. This could lead to unexpected behavior if the filter query inadvertently matches nested documents.
3. The use of `Queries.filtered` and `Queries.not` to adjust the filter query is clear, but it would be beneficial to add a test case that specifically verifies this adjustment logic with various types of queries.
