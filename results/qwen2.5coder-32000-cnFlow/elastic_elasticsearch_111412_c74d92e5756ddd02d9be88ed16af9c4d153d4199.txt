#87A0K, #971VZ: The `createCache` method initializes the cache with a removal listener that adjusts `sizeInBytes`. However, when using the weigher function `(key, value) -> value.sizeInBytes`, it does not account for changes in weight due to updates or evictions. This could lead to inconsistencies between the actual size of items in the cache and the tracked `sizeInBytes`.

#H4NMV: The new setting parser for `CACHE_SIZE` allows both flat numbers and byte size values. However, it uses a default value that is 1% of the configured max heap size. This might be misleading if users expect the default to be in bytes or another unit. It would be clearer to specify the unit in the documentation or use a more explicit default value.

#38JP0: The logic for initializing `enrichCache` based on the parsed `FlatNumberOrByteSizeValue` is correct, but it could benefit from additional validation. For example, if both `byteSizeValue` and `flatNumber` are null, or if they are both non-null, the behavior might not be as expected. Adding checks for these cases would improve robustness.

#894QC: The test cases cover various scenarios, including parsing percentages, byte sizes, and flat numbers. However, it does not include tests for invalid inputs that do not throw exceptions but could lead to unexpected behavior (e.g., negative values or unsupported units). Adding such test cases would improve coverage.
