#ES472, #JQCFZ: The logic introduced in `#ES472` checks if the snapshot was created with a version higher than the current node's version by comparing index versions and build versions. However, this check is only performed when the current node's index version matches the maximum data node compatible index version from the response. This might not cover all scenarios where a restore should be rejected due to version incompatibility.
In `#JQCFZ`, the test case expects an exception message that includes either "index version" or "version" or "Elasticsearch version". While this covers the new logic introduced, it would be more robust if the test could specifically assert against the exact message format used in the new code. This ensures that the test is not passing due to a different error message.
