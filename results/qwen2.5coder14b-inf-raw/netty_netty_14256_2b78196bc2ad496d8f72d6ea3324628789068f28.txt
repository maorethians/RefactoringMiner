#WEE4R, #HEJ1K, #088Y1, #7SDG8, #V5TZD, #ZP0MS: The addition of `pooledChunkAllocations` and `pooledChunkDeallocations` counters in the `SizeClass` enum seems misplaced. These fields should be part of the `PoolArena` class instead of the `SizeClass` enum.
The method `numActiveChunks()` calculates the active chunks by subtracting `pooledChunkDeallocations` from `pooledChunkAllocations`. This logic assumes that every chunk allocation is eventually deallocated, which might not always be true if there are memory leaks or other issues. Consider adding checks to ensure that the number of active chunks does not exceed a certain threshold.
The test case in `PoolArenaTest.java` only tests the scenario where one chunk is allocated but none is deallocated. It would be beneficial to add more test cases to cover scenarios with multiple allocations and deallocations, as well as edge cases like zero allocations or deallocations.
