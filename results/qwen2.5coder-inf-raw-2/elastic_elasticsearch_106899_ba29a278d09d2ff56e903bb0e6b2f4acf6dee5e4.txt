#AR7JF, #3HJ87, #RX5WS, #K6Q58, #J1SYY, #Y9C93: The `locate` function is described as returning an integer that indicates the position of a substring within another string. However, in the implementation and test cases, it returns 0 if the substring is not found. This behavior should be clearly documented to avoid confusion. Additionally, the description in `#AR7JF` mentions "keyword substring," which might imply only keyword types are supported, but the implementation supports both keyword and text types.

#TRJ5Y: In the `process` method of `Locate.java`, the conversion from `BytesRef` to `String` using `utf8ToString()` can be inefficient for large strings. Consider optimizing this if performance becomes an issue.

#QJ49F: The test cases in `LocateTests.java` do not cover all boundary conditions, such as:
  - When the start index is negative and larger than the string length.
  - When the substring is longer than the string.
  - When the start index is exactly at the end of the string.
